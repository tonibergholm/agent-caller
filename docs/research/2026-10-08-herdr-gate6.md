## 1. AgentInfo.revision
- a. PER-PANE. Same server, simultaneous: p1=3, p2=10 (pane.list, agent.list). Activity in p1 (`echo hi`, title change, cd) moved only p1: p1 1->3->5->7->8->9 while p2 stayed 10 (agent.get 10 before/after).
- b. Monotonic (never saw a decrease). It counts pane METADATA changes (terminal title, cwd/foreground_cwd, agent detection/session attach), NOT screen output and NOT agent status.
  - Plain shell p2 running `while true; do date; sleep 0.5; done`: pane.list revs `p2: 1 -> 2 (first poll) -> 2 -> 2 -> 2`, then ctrl+c -> 3. p1 stayed 1 throughout. 300 lines of `seq` output: p1 3 -> 3.
  - Title OSC (`printf '\033]0;mytitle\007'`): p1 3 -> 5. `cd /tmp`: 5 -> 7. Starting `codex`: -> 8, then 9 (agent_session / title).
  - Claude: detection 8 -> 9 (session attached), working (title spinner changed) 9 -> 10. Status transitions alone did not bump: idle(seq 4) rev 9; working->blocked (seq 5->6) rev 10 -> 10; blocked->idle (seq 7) rev 10. Over 12 polls at unknown->blocked (seq 0->1) rev stayed 4.
  - So revision != state_change_seq. state_change_seq is the server-wide counter (claude 0,1,2... then codex 9 etc.); revision is not a status-change signal.
- c. NO. `pane.read.read.revision` was 0 for every pane at every moment (plain shells, idle claude, blocked claude, codex) while AgentInfo/PaneInfo revision was 1..10. pane.read revision is a different (apparently unused/screen) counter: it never moved even with 300 lines of output. AgentInfo.revision == PaneInfo.revision (pane.list) at the same time, and equals `data.pane.revision` in pane_updated/pane_created events.
- d. NO. A plain shell is absent from agent.list (`agents: []`), and `agent.get` on it returns error `agent_not_found` ("agent target w1:p1 not found"). Plain shells appear only in pane.list (agent_status "unknown", no `agent` key). A pane appears in agent.list as soon as an agent is detected (agent_status "unknown" briefly). After agent exit it disappears again (released event). Note: even claude/codex trust dialogs report `blocked`.

## 2. Param shapes (schemas.request)
- `agent.list`: `{}` (EmptyParams)
- `agent.get`: `{"target": string}` (NOT pane_id; passing pane_id -> invalid_request "missing field `target`"). target accepted: pane id like "w1:p2".
- `agent.read`: `{"target": string, "source": "visible"|"recent"|"recent_unwrapped"|"detection", "lines"?: uint32|null, "format"?: "text"|"ansi" (default text), "strip_ansi"?: bool (default true)}` required: target, source. Result `{"type":"pane_read"? ...}` shape: `result.read.{pane_id,workspace_id,tab_id,source,format,text,revision,truncated}`.
- `pane.read`: `{"pane_id": string, "source": same enum, "lines"?, "format"?, "strip_ansi"?}` required pane_id, source.
- `agent.prompt`: `{"target": string, "text": string, "wait"?: {"timeout_ms"?: uint64|null, "until"?: ["idle"|"working"|"blocked"|"done"|"unknown"]} | null}`
- `agent.send_keys`: `{"target": string, "keys": [string]}`; `pane.send_keys`: `{"pane_id": string, "keys": [string]}`
- `ping`: `{}`
- `events.subscribe`: `{"subscriptions": [ {"type":"pane.created"}, {"type":"pane.closed"}, {"type":"pane.agent_detected"}, {"type":"pane.agent_status_changed","pane_id":"w1:p2","agent_status"?:...} , ...]}`. pane.agent_status_changed requires pane_id. Also `pane.updated`, `pane.exited`, `pane.output_matched` (pane_id, source, match required), etc.
- Key names (schema has only `keys: [string]`, no enum; probed on a live pane): accepted: "1", "x", "esc", "Esc", "escape", "Escape", "enter", "Enter", "tab", "space", "up", "Up", "backspace", "Backspace", "shift+tab", "ctrl+c", "C-c". REJECTED (`invalid_key`, "unsupported key X"): "BSpace", "S-Tab", "btab". CLI help: `esc` canonical, `escape` also accepted.
- Methods that exist (from the unknown-method error): includes agent.explain, agent.wait, agent.start, pane.send_text, pane.send_input, pane.wait_for_output, events.wait, pane.close, pane.split.

## 4. Events (frames recorded)
- Subscribe reply: `{"id":"sub","result":{"type":"subscription_started"}}`.
- Frame: `{"data":{...,"type":...},"event":"<name>"}`. Surprise: `event` names are inconsistent: underscore for most (`pane_created`, `pane_closed`, `pane_agent_detected`, `pane_updated`) but DOTTED for `pane.agent_status_changed`; and `data.type` is present for the underscore events, absent for pane.agent_status_changed.
  - pane_created: `{"data":{"pane":{PaneInfo incl. revision:0},"type":"pane_created"},"event":"pane_created"}`
  - pane_closed: `{"data":{"pane_id":"w1:p3","type":"pane_closed","workspace_id":"w1"},"event":"pane_closed"}`
  - pane_agent_detected: `{"data":{"agent":"claude","pane_id":"w1:p2","type":"pane_agent_detected","workspace_id":"w1"},...}`. On agent exit the SAME event name is sent with `"final_status":"idle","released":true`, followed by pane.agent_status_changed with agent_status "unknown" (no `agent`).
  - pane.agent_status_changed: `{"data":{"agent":"claude","agent_status":"blocked","pane_id":"w1:p2","workspace_id":"w1"},"event":"pane.agent_status_changed"}`. Seen: idle, working, blocked, idle, unknown(after release). Note the unknown->(blocked) trust dialog transition was before the subscription.
  - pane_updated carries full PaneInfo (with revision).
- Blocked-agent flow worked: claude in manual mode, `agent.prompt` "run exactly this bash command ... touch /tmp/acp2/proj/x.txt" -> working -> blocked (permission dialog "1. Yes ... 4.
