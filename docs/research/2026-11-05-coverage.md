# Coverage-driven security tests, 2026-11-05

## Method

- `cargo llvm-cov 0.9.1` (stable toolchain, `llvm-tools-preview`):
  `cargo llvm-cov --workspace --locked --no-fail-fast --json`, then
  `cargo llvm-cov report --json` (the run exits non-zero in this sandbox, see
  below, so the report is built from the collected profiles).
- Per crate, counted over `crates/<crate>/src/**` only. Line, function and
  region coverage. **Branch coverage was not measured**: `--branch` needs a
  nightly compiler. Region coverage (which counts each branch arm and
  short-circuit operand) is the stand-in.
- Function coverage was merged over monomorphised instances (an instance
  that no test uses does not count against a function another instance
  covers). Candidates were ranked by uncovered regions and then read by hand
  for security relevance (auth, answer routing, limits, pairing, owner
  checks, error paths, log privacy).
- Before = `origin/main` at 75cc913. After = this branch.

Function counts barely moved (acd-core 270 to 272, acd-inbox 332 to 334): the
targeted code was mostly branches inside functions that already ran.

The gains are small because the security code was already well covered. The
`acd` numbers are **understated**: four test binaries (`cli`, `external_cli`,
`harness`, `hooks_cli`) fail in this sandbox (the daemon cannot bind
`[::1]`, no IPv6), so `daemon.rs`, `status.rs` and parts of `service.rs` run
no tests here. Compare failing names against clean `origin/main`; they are the
same set.

## Still uncovered, and why

- `acd`: `daemon::run` and its closures, `status::*`, `pair::print`,
  `service` retry paths: need a running daemon; the daemon tests fail here
  (no IPv6). Not a gap on CI.
- `acd-inbox`: `linux/keyring.rs` (`read_in`, `write_in`, `delete_in`,
  `unlock_in`), `linux/dbus.rs`, `serve::linux_run`, `install::*`: need a
  session D-Bus and Secret Service or a desktop; Linux integration checks.
- `acd-securefs`: `diagnose_denied` and the permission-denied branches of
  `open_path`: need a non-root user; this session runs as uid 0 (the existing
  test spawns an unprivileged child but that path is not reached under root).
  `windows.rs`, `winacl.rs` are Windows only.
- `acd-client`: `conn::run`/`serve`/`open`, `fake.rs` servers, `tls.rs`
  verifier signature methods: exercised only through instantiations the
  profile attributes elsewhere, or by network fakes; remaining regions are
  `map_err` closures for I/O failures that cannot be provoked deterministically.
- `acd-adapters`: `hooks/state.rs` codex and question paths, `t3/reconciler.rs`
  discovery and policy, `herdr/keys.rs` deliver/confirm closures, `t3/fake.rs`,
  `herdr/fake.rs`: large state machines whose remaining regions are timing
  paths; a meaningful test needs the fake servers with controlled time, not a
  small test. Suggested follow-up.
- `acd-core`: `server::session` and `on_frame` closures, `TlsListener::new`
  closures, `registry::migrate`: reached by e2e tests only in part.
- Branch coverage: not measured (nightly only).
