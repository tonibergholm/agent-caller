# Voice backend B: Linux and Windows

Research date: **2026-10-12**. Recommendations for backend B delivery planning; product code was read only. Based on [voice design](../superpowers/specs/2026-10-11-voice-design.md) §§4, 6 and 11 and [CLAUDE.md](../../CLAUDE.md); Step 1 remains the safety/execution foundation. Links below are primary sources; versions are observed releases/manifests, not promises of compatibility. No target-machine benchmarks or installed `voxtype` version were verified.

## Decision

Build a small **Rust client-side voice host**, sharing the existing router, safety core and `acd-client`; keep `acd` and acd/1 unchanged. On Omarchy, this host belongs in the proposed **`acd-inbox` systemd user service**, with Quickshell presenting the inbox and voice HUD. This is the user's proposed architecture, not an existing implemented service.

| Component | Linux: Hyprland first | Windows |
| --- | --- | --- |
| Trigger | Compositor press/release bindings → private `acd-inbox` control IPC; separate toggle binding. Add GlobalShortcuts portal adapter for broader Wayland coverage. | `RegisterHotKey` for toggle; dedicated `WH_KEYBOARD_LL` hook for hold/release, especially modifier-only keys. |
| Capture | CPAL **0.18.2 native PipeWire**; PulseAudio fallback, including Flatpak. | CPAL/WASAPI in an interactive per-user process. |
| VAD | Silero ONNX on CPU, pinned model and modern `ort`; WebRTC VAD if avoiding ONNX. | Same. |
| Transcription | First spike: **Parakeet TDT 0.6B v3 int8 via `transcribe-rs`**, competing against Whisper multilingual base/small via `whisper-rs`. Ship the measured winner, retain Whisper as broad-language fallback. | Same portable engines; optional Vulkan Whisper GPU build. |
| Intent | Deterministic fast path first; optional user-installed Ollama, initially Qwen3 1.7B/4B quantized, schema constrained, thinking disabled. | Same; Windows AI APIs are optional future adapters. |
| Speaker | Speech Dispatcher with an explicitly local module; eSpeak NG fallback. Optional warm Piper worker for natural speech. | Installed OneCore voices via WinRT `SpeechSynthesizer`; SAPI fallback. |

**Reuse voxtype's engines, models and compositor integration knowledge, not its default shared dictation daemon.** Agent commands must become a validated proposal in the HUD, never text injected into the active editor or shell. The installed dictation app should keep its own shortcut; avoid competing capture on the same gesture.

## 1. Triggers and permissions

**Hyprland:** compositor bindings are rootless and naturally provide press/release. Invoke tiny `start`, `stop`, `toggle`, `cancel` IPC commands; don't launch a recognizer per key event. Hyprland's event socket is a compositor event stream, not a global keyboard stream. Current **0.56.2 (2026-08-05)** uses the newer Lua configuration path; older hyprlang examples need version gating rather than blind installation. Use the current [binding documentation](https://wiki.hypr.land/Configuring/Basics/Binds/) and [IPC documentation](https://wiki.hypr.land/IPC/). Test release order, repeated keys, submaps, reloaded bindings and lock/suspend.

**Wayland portable path:** the [GlobalShortcuts portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) supplies `Activated`/`Deactivated` events and user-controlled shortcut registration without raw input-device grants. Backend support and configuration UX vary. In **xdg-desktop-portal-hyprland 1.4.1 (2026-07-29)**, the [implementation](https://github.com/hyprwm/xdg-desktop-portal-hyprland/blob/v1.4.1/src/portals/GlobalShortcuts.cpp) maps pressed/released to those signals, but ignores `preferred_trigger` and does not provide a general shortcut picker. Register an application/shortcut id, then configure Hyprland's `global` dispatcher; inspect `hyprctl globalshortcuts`. Probe the actual interface version: portal v2 features such as `ConfigureShortcuts` cannot be assumed. Compositor IPC bindings remain the fallback.

| Candidate | What actually works | Decision |
| --- | --- | --- |
| [handy-keys 0.3.4](https://github.com/handy-computer/handy-keys) (2026-08-07, MIT) | Linux reads evdev devices; needs device ACLs/`input` membership. Blocking adds grabs/uinput. No implemented GlobalShortcuts portal in its README. | Useful Windows hook abstraction to spike; not rootless Wayland default. |
| [rdev 0.5.3](https://github.com/Narsil/rdev) (2023-06-26, MIT) | Normal Linux listener is X11; experimental grab path reads evdev, requiring access. | Avoid treating “cross-platform” as Wayland support. |
| [global-hotkey 0.8.0](https://github.com/tauri-apps/global-hotkey) (2026-05-01, MIT/Apache-2.0) | Windows/macOS/X11. Windows release detection polls `GetAsyncKeyState` every 50 ms; Linux is X11. | Good toggle/X11 implementation; Windows hold needs measured polling latency or hook. |
| [evdev 0.13.2](https://docs.rs/evdev/0.13.2/evdev/) (2025-09-15, MIT/Apache-2.0) | Reliable Linux key up/down independent of display server, if `/dev/input/event*` is readable. | Opt-in fallback only. “No root at runtime” after an admin grant is not permission-free. |

Granting `input` access permits reading other applications' keystrokes; do not require it for installation. Rootless Wayland options are compositor bindings, supported portals and in-panel focused keys. XWayland/X11 listeners cannot observe all native Wayland applications.

**X11:** use X11 shortcut grabs (`global-hotkey`) for chords and release events; select a non-conflicting key and handle grab failure. A modifier-only hold may need an X11 listener. No root is needed in the user's X session, but X11 does not offer Wayland's isolation.

**Windows:** [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) posts activation (`WM_HOTKEY`), not key-up; use `MOD_NOREPEAT` and report collisions. A [low-level keyboard hook](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) receives down/up globally on the interactive desktop without admin rights. Keep its callback minimal, enqueue events, keep a message loop and ignore unwanted injected/repeat events. Hooks can disappear silently on timeout: the independent recording cutoff is essential. With `global-hotkey` polling, test releasing modifiers before the main key; its synthesized release is not a native key-up notification. Secure desktop, session switch and lock are stop conditions, not opportunities to elevate.

## 2. Capture and VAD

[CPAL 0.18.2](https://github.com/RustAudio/cpal/releases/tag/v0.18.2) (2026-08-16, Apache-2.0) is the common API. **0.18 adds native PipeWire/PulseAudio**; older advice that CPAL Linux is ALSA-only is stale. Start with its PipeWire host, not a second bespoke native implementation. Direct [PipeWire streams](https://docs.pipewire.org/page_tutorial4.html) remain an alternative if CPAL cannot express device routing, negotiated latency or portal-provided connections. Windows uses WASAPI shared mode; exclusive mode adds little value to short commands.

Negotiate actual microphone format, downmix and resample off the callback to **16 kHz mono f32**, then adapt the chosen engine's input. Use bounded queues; never block audio on inference, IPC or UI. Measure 10–20 ms callback buffers as a starting target, not an end-to-end latency claim. Open/start capture only for the trigger, stop on release, ignore silent or <0.3 s utterances and enforce 60 s independently of key-up. VAD filters silence and trims boundaries; it must not add a long silence timeout after hold release. Keep padding within the authorized recording interval to preserve initial/final consonants.

[Silero VAD 6.2.3](https://github.com/snakers4/silero-vad/releases/tag/v6.2.3) (2026-09-23, MIT) reports <1 ms CPU processing for a 30+ ms chunk; this excludes capture/endpointing/ASR. Its model is small, multilingual and suitable for noise rejection. [vad-rs 0.1.5](https://github.com/thewh1teagle/vad-rs) (2024-12-16, MIT) is convenient but pins `ort` 2.0.0-rc.9 and uses an older h/c tensor interface: **do not feed it the newest Silero model without testing compatibility**, or introduce conflicting ONNX versions beside `transcribe-rs`. Prefer one modern ONNX runtime plus a tested adapter. [WebRTC VAD Rust bindings](https://github.com/kaegi/webrtc-vad) provide tiny CPU-only 10/20/30 ms frame classification with no model download; expect more threshold tuning and weaker noise discrimination.

**Permissions:** native Linux PipeWire/PulseAudio access normally follows the logged-in audio session; Wayland input permissions do not grant microphone access. Flatpak's [PulseAudio socket permission](https://docs.flatpak.org/en/latest/sandbox-permissions.html) covers microphone as well as playback. Do not assume ScreenCast/Camera portals authorize ordinary mic capture; test the distribution's audio mediation. Flatpak is therefore a later package, with portal shortcuts and an explicit audio grant, not evdev passthrough. Windows capture must respect [microphone privacy controls](https://support.microsoft.com/en-us/windows/privacy/windows-camera-microphone-and-privacy), including “Let desktop apps access your microphone”; link `ms-settings:privacy-microphone`. Packaged capture APIs may additionally require manifest capabilities. Device loss/denial closes the session and produces a classified HUD error.

## 3. On-device transcription

Published WER and throughput benchmarks are **not short-command safety benchmarks**. One “deny”→“approve” error matters more than an average dictation WER. English/Finnish availability also does not prove Finnish command routing: the existing fast phrase table is English first and needs deliberate locale entries.

### Voxtype reuse on Omarchy

The installed fact comes from the user; **v1.1.0 (2026-09-24)** was inspected, not the machine's package. Its [release README](https://github.com/peteonrails/voxtype/blob/v1.1.0/README.md) shows compositor start/stop commands, optional evdev, warm model management and multiple engines. Its [manifest](https://github.com/peteonrails/voxtype/blob/v1.1.0/Cargo.toml) uses `whisper-rs` 0.16.0 and optional ONNX/Parakeet. Borrow those proven integration patterns; reuse a compatible existing local model path read-only after checking exact format/hash/license, rather than downloading duplicates.

**Default shared-daemon integration fails the privacy/ownership contract:** it types/pastes or copies output, supports transcript files/notifications, remote engines and arbitrary post-processing. Its [daemon source](https://github.com/peteonrails/voxtype/blob/v1.1.0/src/daemon.rs#L2613) logs the full transcript at INFO, and [eager transcription](https://github.com/peteonrails/voxtype/blob/v1.1.0/src/daemon.rs#L2476) also logs combined text. Journald can persist this. `record start --output-file` is not the required in-memory generation-tagged transcript API.

This does not rule out every configuration: `--quiet` may suppress those messages, and a controlled private child/IPC adapter or upstream nonpersisting transcript endpoint could be useful. It needs a specific spike proving no files/clipboard/injection, no content in stderr/errors/dependency logs, local-only engines, cancellation, bounded messages and session correlation. Avoid transcript-file watching, even temporary files, under §6.3. Embedding tested engine libraries is presently simpler than taking control of an independently configured dictation daemon.

## 4. Free-form intent

Use [Ollama structured output](https://docs.ollama.com/capabilities/structured-outputs), with the **actual JSON schema** in `format`, not merely `"json"`. Ollama **0.40.3 (2026-10-11)** is the observed release. Start with [Qwen3 1.7B](https://huggingface.co/Qwen/Qwen3-1.7B) (Apache-2.0), test 4B if target resolution is inadequate; disable thinking, keep output bounded and retain the model in RAM. Rough Q4 weight payloads are order **1–3 GB**, plus runtime/KV cache; measure actual files and RAM. CPU load/prompt evaluation can dominate even with a short JSON answer; no source establishes a subsecond intent guarantee on this user's x86 machine. Set a budget/timeout and keep fast commands available when the model is absent or slow.

Ollama is quickest when already installed. [llama.cpp grammars/JSON schema](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md) (MIT; observed **0.6.0**, 2026-10-05) gives an embedded library or controlled local worker later, with tighter deployment/privacy control. Its schema conversion supports a subset: validate the exact plan union, bounded candidates and text constraints. Grammar-valid output can still choose the wrong agent; Rust provenance, frozen ids and confirmation remain mandatory.

Local does not mean nonpersisting: audit server access/debug logs, retained chat sessions and crash diagnostics; send one stateless request over loopback/private transport, clear per-session data on lock/off/quit. Loopback alone does not prove local inference: require a downloaded local model and disable Ollama cloud features. Its cloud service currently does not support structured outputs either.

**Windows Copilot Runtime/Foundry APIs:** [Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica) is hardware-gated (NPU or supported experimental GPU, no CPU baseline), Limited Access Feature, and transitioning to Aion Instruct. Microsoft's overview and detailed page currently disagree on rollout dates; don't base packaging on that schedule. No verified arbitrary JSON-schema grammar contract was found. [Windows ML](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/supported-execution-providers) manages ONNX execution providers, not a ready-made intent parser; model/tokenizer/decoding/schema integration remains ours. Keep both optional Windows-specific spikes.

**Anthropic:** off by default, text/context only, never audio; retain §6.3 field disclosure and separate request-details opt-in. Use [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), a fixed schema with no private identifiers baked into cached definitions, and the existing 5 s timeout/classified errors. Store credentials in Secret Service on Linux and Credential Manager/DPAPI on Windows; fail availability rather than store plaintext when the secret store is missing. Provider [retention terms](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention) are separate from our no-local-persistence promise and must be reviewed for the chosen account/features. Models have no tools and no execution authority.

## 5. Speech output and reference projects

Linux default: [Speech Dispatcher 0.12.1](https://github.com/brailcom/speechd/releases/tag/0.12.1) (2025-05-06) provides queues/cancellation and user-selected voices. Explicitly choose a local module: supported modules include cloud services too. Its daemon is GPL and client libraries LGPL; speaking quality comes from the engine. [eSpeak NG 1.52.0](https://github.com/espeak-ng/espeak-ng/releases/tag/1.52.0) (2024-12-12, GPLv3) is compact, fast, supports Finnish/English, but robotic. Prefer system packages/SSIP or stdin-based worker over linking GPL code into a permissive client.

[Piper 1.8.0](https://github.com/OHF-Voice/piper1-gpl/releases/tag/v1.8.0) (2026-09-04) is natural local neural speech; keep a model warm and stream PCM without WAV files. The maintained engine is **GPLv3**, unlike the archived original MIT project; individual voices need their own model-card checks. Finnish [Harri medium](https://huggingface.co/rhasspy/piper-voices/blob/main/fi/fi_FI/harri/medium/MODEL_CARD) is available (~63 MB model, CC0 source dataset). Check the full voice provenance before redistribution. An optional separately packaged worker avoids making Piper an obligatory dependency; that is a packaging choice, not a blanket licensing exemption.

Windows default: [WinRT SpeechSynthesizer](https://learn.microsoft.com/en-us/uwp/api/windows.media.speechsynthesis.speechsynthesizer) uses installed Microsoft-signed voices, enumerated by locale. Rust `windows` bindings can consume the generated stream; `stop` must cancel playback and late results. SAPI COM is a mature alternative with asynchronous speech and [purge flags](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms720892(v=vs.85)); SAPI and OneCore voice inventories differ. Verify installed Finnish/English rather than assume downloadable natural Narrator voices are exposed to every API. No extra neural model is needed for this baseline. Measure first-audio/cancellation latency; Piper can be optional on Windows too.

## 6. Host, seams and packaging

The spec's trigger/capture/transcriber/speaker interfaces are **planned seams**; current code defines [IntentModel](../../crates/acd-voice/src/router/model.rs), `InboxPort` and `HudSink`, not a complete audio API. Do not implement adapters by submitting to [Controller::text_input](../../crates/acd-voice-client/src/controller.rs) only when audio ends: that freezes the snapshot too late. Add recording-start admission/snapshot/session generation, then generation-tagged partial/final delivery. Port the §4.2 bounded queues, lifetime and cancellation guarantees to Rust workers; ASR callbacks from cancelled generations never route actions. Partials are display-only. Report language, input format, final/partial capability and unavailability reasons explicitly.

Proposed `acd-inbox`: one interactive user's Rust process owns `acd-client`, voice workers, snapshots and safety. Quickshell publishes ordered selection/visibility snapshots and displays generation-tagged HUD/microphone state with acknowledgement. Use a private `$XDG_RUNTIME_DIR/acd-inbox.sock` (0600, peer-UID checks) for structured commands/events; no transcript on command lines, clipboard, filesystem or journal. [Quickshell sockets](https://quickshell.org/docs/v0.3.2/types/Quickshell.Io/Socket/) fit a persistent channel; its [IPC handler](https://quickshell.org/docs/v0.3.0/types/Quickshell.Io/IpcHandler/) can support non-content control gestures. UI disconnect must stop recording and cancel unsent work: invisible confirmation/countdown cannot authorize execution.

Tie the user unit to the [graphical session](https://github.com/systemd/systemd/blob/main/docs/DESKTOP_ENVIRONMENTS.md), provided the actual Hyprland/UWSM session manages that target; import only needed display/runtime environment. Use [logind lock/sleep state](https://github.com/systemd/systemd/blob/main/man/org.freedesktop.login1.xml), also test Hyprland's lock integration and restart behavior. Do not keep mic capture alive through lingering user services. Native Arch/Omarchy package first, portable CPU baseline plus optional GPU packages; all hardware paths need fallback and explicit ISA checks, not binaries optimized for the build machine. Flatpak follows later with portals/audio permissions and a deliberate host-service boundary.

Windows: interactive per-user app/tray process, **not a Session 0 system service**. Tauri MSI/NSIS can ship CPU libraries and optional model downloads; Windows AI adapters add MSIX/App SDK requirements separately. Ship audited ONNX/ggml DLLs with a controlled search path, model hashes and notices. Microphone/hook availability must degrade independently. Reuse the same `acd-voice` safety rules and client countdowns on both platforms: no new shell executor, agent tools or daemon protocol.

## 7. Risks and proposed spikes

1. **Trigger/host admission first:** rootless Hyprland bindings and portal press/release; Windows hook versus 50 ms polling. Prove snapshot freeze on press, UI loss, countdown-trigger cancellation, lock/sleep, unplug, reload and lost release/60 s cutoff.
2. **Actual-machine ASR bake-off:** warm/cold Parakeet v3 int8, Whisper base/small multilingual, optional English Moonshine small streaming; CPU-only x86_64 first, then available GPUs. Corpus: 0.3–10 s English/Finnish, “approve/deny/option two”, mixed coding names, noise, silence. Record semantic errors, p50/p95 release-to-proposal, model load/RAM/CPU and streaming final stability; target roughly 1 s for fast-path proposals, excluding the specified 2 s countdown. No semantic substitutions accepted just to meet latency.
3. **CPAL/VAD/package spike:** native PipeWire, PulseAudio fallback, WASAPI, device switch/hotplug; pin Silero/ONNX tensor/runtime compatibility. Confirm no microphone activity outside the gesture and no endpointing delay after release.
4. **Voxtype reuse spike:** identify installed version/engine/model safely; test engine/model reuse first. Only evaluate a controlled child or upstream transcript IPC if it proves no persistence/injection/remote audio and carries session identity. Audit dependency logs and crash output, not just our tracing.
5. **Intent contract:** Qwen3 1.7B versus 4B through schema-constrained Ollama/llama.cpp; 20+ ordinary and adversarial contexts, ambiguous names, Finnish, changed cards, invented ids/payloads. Measure CPU prompt/response latency and cancellation. JSON validity alone is insufficient; keep mandatory confirmation and fast-path fallback.
6. **TTS/HUD acceptance:** local Speech Dispatcher/eSpeak/Piper versus Windows OneCore/SAPI; English/Finnish voice availability, first audio, stop-on-record, cancellation, coalesced alerts and complete payload visibility. Evaluate non-activating Quickshell/HUD behavior before voice delivery.
7. **Ship gate:** reproduce CPU packages on an older non-AVX2 machine, GPU failure fallback, denied permissions, offline assets, missing secret store, service restart and no-content-log audit. Optional cloud path must be explicitly enabled and disclose transmitted fields. Experimental Windows Speech remains a spike; check production status, locale coverage and schema control independently for other Windows AI adapters.
