# iOS spike: foreground inbox over Tailscale

Date: 2026-10-12. Scope: v1 iOS client, foreground inbox only, connecting to
the daemon over Tailscale, reusing `acd-client` and the Svelte UI. No push,
no relay. Throwaway code is in `spikes/ios/` and is labelled as such.

Hosts: macOS 27.0 (Darwin 27.0.0), Xcode 27.0 (27A266a), iOS 27.0 SDK and
simulator runtime (24A434), Rust 1.99.0 via rustup. No phone was used:
nothing here runs on a device.

## Method and environment

- Rust: `brew install rustup`, then `rustup default stable --profile minimal`
  and `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`. The
  Homebrew `cargo` and `rustc` on PATH have no iOS std, so every command
  below puts `~/.rustup/toolchains/stable-aarch64-apple-darwin/bin` first.
- iOS simulator runtime: `xcodebuild -downloadPlatform iOS` (8.05 GB).
  Booted: iPhone 18 Pro, iOS 27.0.
- Tauri CLI: `app/node_modules/.bin/tauri` (`@tauri-apps/cli` 2.12.1, from
  `npm ci` in `app/`). `tauri ios init` needs `xcodegen`, installed with
  `brew install xcodegen` (2.46.0). Homebrew also installed `libimobiledevice`
  and five dependencies as part of `tauri ios init`.
- Scratch daemon: `ACD_CONFIG_DIR=/tmp/ios-spike/acd-config`, ports 47810
  (acd/1) and 47811 (hooks), `listen = ["loopback"]`, herdr and T3 off. It
  does not touch the user's daemon on 47800. The pairing line came from
  `acd pair --host 127.0.0.1` and was written to a 600-mode file. It was
  never printed.
- Synthetic Claude requests came from `tests/e2e/hookpost.py`. It posts a
  synthetic hook payload and is not a live Claude session.

The first device check failed with `can't find crate for core`. The cause was
the Homebrew `rustc` on PATH, not the crate. It passed once the rustup
toolchain was first.

Platform code found by grep, with what happens on iOS:

- `conn.rs:159` uses `tokio::net::UnixStream` for the local `acd.sock`. It
  compiles on iOS. At runtime the local endpoint is unusable: the simulator
  showed "This Mac: local unavailable: acd is not set up". Verified.
- `acd-securefs` uses `libc::open` with `O_NOFOLLOW`, `geteuid` and mode
  checks. It compiles on iOS. Its owner and mode checks are not meaningful
  inside the iOS sandbox, but they are not needed there.
- `settings.rs` creates `settings.json` with mode 0600 and the config dir
  with 0700. The app wrote `settings.json` in its container. Verified in
  the simulator.
- `local.rs` test code uses `mkfifo` and unix permissions. Test only.

Smallest change needed to compile: none. The only gap is product behavior:
the iOS build should not offer the local machine. Today it shows a red
banner. Fix in the iOS client, not in `acd-client`.

Not verified: `cargo test` on iOS (tests cannot run on a device here), and a
linked app bundle for a device.

## 2. Tauri 2 iOS shell and the Svelte UI

Existing app crate (`app/src-tauri`), simulator target:

- `cargo check --target aarch64-apple-ios-sim` fails first in
  `tauri-nspanel` (80 errors, unresolved `objc2*`). Later errors are hidden
  behind it, so the full list is not enumerated. Verified.
- Desktop-only dependencies, from `Cargo.toml`: `tauri-nspanel`,
  `tauri-plugin-global-shortcut`, `tauri-plugin-notification` (registered
  only off macOS in `main.rs:32`), the `tauri` `tray-icon` feature (`tray.rs`),
  `mac-notification-sys`, and the Swift bridge in `build.rs` (already gated
  to macOS). `security-framework` and `tauri-plugin-clipboard-manager` are
  not desktop-only.

Spike shell, `spikes/ios/tauri-shell/src-tauri`:

- `cargo check --target aarch64-apple-ios-sim`: Finished in 1m57s. Verified.
- `tauri ios init --ci`: generated the Xcode project (`gen/apple`). Verified.
- `tauri ios build --debug --target aarch64-sim --ci`: passed after three
  fixes. Verified.
  1. `beforeBuildCommand` path is relative to the parent of `src-tauri`.
  2. The generated Xcode script runs `node tauri`, and no `tauri` module
     resolves from `gen/apple`. The workaround is a symlink
     `gen/apple/tauri` to `app/node_modules/@tauri-apps/cli/tauri.js`. This
     is inside the gitignored `gen/` and is not committed. The proper fix
     (a package.json the CLI can see) is not tested.
  3. The capability file only grants `core:event` to the `hud`, `panel` and
     `settings` windows. The iOS window is `main`, so inbox loading failed
     with "event.listen not allowed on window main". The spike capability
     lists `main`.
- Install and launch: `xcrun simctl install booted <app>` and
  `xcrun simctl launch booted dev.agentcaller.inbox.iosspike`. Verified.
- The Svelte UI renders in the simulator. It shows the paired machine, the
  filter chips and the needs-you section. Verified.
  - A held permission request shows the full card: the command block, the
    type tag "BASH APPROVAL", and the buttons Yes, Yes always (with its rule
    text) and No. Screenshot: `spikes/ios/screenshots/shot-app-4-held.png`.
  - A request whose hook connection had closed showed only a header and the
    "NEEDS YOU" tag. The probe showed `pending: null` for that agent while
    the daemon still listed it as NeedsYou. The card then has no reason, no
    options and no "Answer in terminal" text. Screenshots:
    `shot-app-2.png` and `shot-app-3-relaunch.png`. Verified as observed. The
    cause is the synthetic client closing its connection after 3 s, which
    left the agent without a held request. The spec describes this case as a
    read-only "Answer in terminal" card. The card does not show that text. This
    is a UI gap (Q6).
- Answering from the iOS UI was not tested. No tap was driven in the
  simulator, and no answer was sent to the daemon from the iOS build. The
  probe only reads the view.

Structure, using the evidence above. Recommendation: a separate iOS shell
crate that shares a core library with the Mac app. The spike shares
`keychain.rs` and `pairing.rs` through `#[path]` and changes neither file.
That sharing is a spike shortcut, not the target design. Reasons:

- The Mac crate is shaped by desktop code (panel, tray, global shortcut,
  Swift voice bridge, `notify`, `settings_window`, `frame`). Gating all of it
  inside the same crate touches the reference app's `Cargo.toml`, `main.rs`,
  `build.rs` and `tauri.conf.json` on every iOS change, with regression risk
  for the Mac app. The desktop-only dependencies are the real blocker, not
  the crate type. A Tauri mobile library entry is a small addition, but the
  Mac app would still change.
- The Svelte frontend already takes an injected `Api` (`app/src/lib/ipc.ts`,
  `App.svelte` prop `api`). The iOS shell can keep the same commands and
  drop the voice, hotkey and panel commands.

Not verified: that gating in place would compile. The in-place route was
only measured by the nspanel failure, not completed.

## 3. Secrets and pairing on iOS

- `security-framework` 3.7.0 (`KeychainSecrets`) compiles for the simulator.
  The spike imported a pairing line at launch through the real
  `CachedSecrets<KeychainSecrets>` store (`ACD_SPIKE_PAIRING_FILE`). After a
  relaunch without that variable, the machine was still Online with its card
  (`spikes/ios/screenshots/shot-app-3-relaunch.png`). Verified in the
  simulator, with an ad-hoc build and no entitlements.
- Not verified: Keychain on a device with a free personal team. Not checked:
  whether an explicit `keychain-access-groups` entitlement is needed. The
  Xcode project the spike generated has none.
- Pairing entry options, from what was built or checked:
  - Clipboard: the spike registers `tauri-plugin-clipboard-manager` and
    reuses `pairing.rs::import_text`. Not exercised in the UI. The Panel has
    no import control; the Mac app's import lives in Settings, which the
    spike does not render on iOS. Newer iOS versions show a paste prompt for
    clipboard reads. Not verified on device.
  - QR scan and share sheet: not built. The pairing line is an ordinary
    string (`acd://host:port?pin=sha256:...#token`), so either can carry it.
  - The token sits in the URL fragment and is never sent as a request
    target. Fine for transport. Still a secret: treat it as one in logs.

## 4. Simulator to local acd over the real acd/1 path

Daemon: scratch `acd run` on 127.0.0.1:47810. Pinned TLS 1.3 by SPKI pin,
token auth, snapshot sync.

Probe: `spikes/ios/probe` (`acd-ios-probe`), built for
`aarch64-apple-ios-sim` and run with
`xcrun simctl spawn booted ./acd-ios-probe` and
`SIMCTL_CHILD_ACD_PAIRING_FILE=/tmp/ios-spike/pairing.line`.

| Run | Result |
|---|---|
| Correct pin, no requests | Status Online after 23–38 ms. Machine listed. Cards 0. Verified. |
| Correct pin, one synthetic Claude permission (connection held) | Card `claude:…ios-spike-session-1`, `needs_you`, `Bash touch …`, answerable, options allow / allow_always / deny. Verified. |
| Correct pin, same request after its hook connection closed | Agent still listed, `pending: null`, not answerable. Verified. |
| Altered pin (first hash character flipped) | Never Online. Status `IdentityChanged`, "Re-pair this machine.", cards 0. Fail closed. Verified. |

Network facts, not tested here:

- The simulator shares the host loopback, so 127.0.0.1 reached the daemon.
  Verified.
- App Transport Security governs NSURLSession and CFNetwork. The Rust client
  opens TCP and TLS directly and does not use those APIs, so ATS should not
  apply. Not verified on a device.
- Local Network privacy prompts for LAN ranges. The simulator did not prompt
  for loopback. Not verified whether the simulator enforces Local Network
  privacy at all, so this is no evidence either way. Whether a Tailscale CGNAT
  address (100.64.0.0/10) triggers a prompt is not verified. If it does,
  `NSLocalNetworkUsageDescription` is needed.
- Tailscale iOS app: the phone must route 100.64.0.0/10 and fd7a:115c:a1e0::/48
  through the Tailscale tunnel for `vet()` to accept the address. Not tested
  (no device). `acd` `listen = tailscale` was not tested either.

## Recommended architecture

- A shared core crate (`agent-caller-core`, name TBD) holds `Inbox` setup,
  the command set that does not depend on the platform, pairing import,
  and the Keychain store. The Mac app and the iOS shell both depend on it.
  Extraction is a later change. Until then, the spike's `#[path]` approach
  is the shortcut.
- A separate iOS shell crate: mobile entry point, a command subset, no panel,
  tray, hotkey, voice or notifications.
- The existing Svelte app with a mobile layout flag. The flag gates the
  touch delta above. Frontend code is shared; components are not forked.
- Transport: unchanged `acd/1` over TLS with pinned SPKI. The iOS client
  never uses `acd.sock`.

## Risks

- Free-team 7-day expiry. A device install stops working after a week and needs a rebuild. Acceptable for a spike, not for daily use.
- Tailscale on iOS is not tested. If its route or address rules differ, the client's `vet()` refuses the daemon. This is the largest unknown.
- Local Network prompt for Tailscale addresses. Not verified.
- Keychain under a free team with no entitlements. Not verified on device.
- Answering from iOS is not verified. The probe only reads.
- The `node tauri` symlink and `#[path]` sharing are spike workarounds. Both must be replaced before any real build.
- A pairing token pasted by clipboard can remain in the clipboard. The product should clear it after import. Not built.
- Foreground-only means no notifications and no background refresh. Requests arrive only while the app is open.
