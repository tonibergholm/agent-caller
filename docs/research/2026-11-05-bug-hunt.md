# Correctness bug hunt, 2026-11-05

Scope: correctness, not security. Production code is unchanged.

## Method

Read the wire-reachable and file-reachable code for panics, overflow, slicing
off a char boundary, lock and await hazards, timers, state machines, time
handling, Unicode truncation and swallowed errors. Areas read: acd-protocol
(pairing, text), acd-core (idem, server limiter, registry revisions),
acd-client (commands, backoff, inbox notify gate and machine edits),
acd-adapters (text, hooks wire/mapping, claude_sessions, herdr screen
helpers, external clock), acd-inbox (protocol line fitting, line reader),
acd-voice (text). Each suspicion got a probe; real ones have an `#[ignore]`d
test that fails today:

```sh
cargo test -p acd-adapters --test bughunt_adapters -- --ignored
cargo test -p acd-voice --test bughunt_voice -- --ignored
```

Coverage is partial: the 3289-line `hooks/state.rs`, the T3 and herdr
reconcilers, `acd-client/conn.rs` reconnect/resume and `acd-core/engine.rs`
claim/deliver phases were skimmed, not audited. Treat them as open.

## Confirmed bugs

### B1: correlation keys are ambiguous when ids contain `:` (medium)
- Where: `crates/acd-adapters/src/hooks/wire.rs`, `claude_key` (~l.184) and
  `codex_key` (~l.193); ids pass `valid_id` (l.73), which allows `:`.
- Impact: `claude:{session}:{prompt}:{digest}` is a plain join. Session `s:p1`
  with prompt `x` and session `s` with prompt `p1:x` get the same key, so
  events of two different sessions can be matched to one request. Needs a
  hook caller that holds the hook token and picks ids, so low exposure, but
  it breaks the "prove which agent" rule.
- Test: `bughunt_adapters.rs::correlation_keys_of_different_sessions_differ`.
- Minimal fix: length-prefix or escape each component (`{len}:{id}`), or
  reject `:` in `valid_id`. Changing the key shape needs the stored-key
  consumers checked.

### B2: `cap_chars(text, 0)` returns one char (low)
- Where: `crates/acd-adapters/src/text.rs:55` (`take(max.saturating_sub(1))`
  then pushes `…`). Same for `max == 1`: only `…`, no text.
- Impact: contract "first `max` chars" is broken at 0. No current caller
  passes 0 (callers use fixed constants; `mapping.rs:106` passes
  `limit - 200`), so latent.
- Test: `bughunt_adapters.rs::cap_chars_never_exceeds_its_cap`.
- Minimal fix: `if max == 0 { return String::new(); }`.

### B4: voice `truncate(s, 0)` returns `…` (low)
- Where: `crates/acd-voice/src/text.rs:55`, same pattern as B2; `clean` goes
  through it. Latent for the same reason.
- Test: `bughunt_voice.rs::truncate_never_exceeds_max`.
- Minimal fix: as B2.

## Observations that are not bugs by the tests' own contract

- `clean_display` deletes `\n` and `\t` instead of replacing them with a
  space, so `"a\nb"` becomes `"ab"` (the existing test `clean_display("  a\tb  ")
  == "ab"` pins it). Words merge in titles. Intentional per the test; worth
  a product decision. `acd-voice::text::clean` does the opposite.
- Truncation by `char` can split a grapheme cluster (ZWJ emoji, combining
  marks). Display only.
- Without the `answer.revision` capability, `Commands::begin` clears the
  revision on `RequestAnswer`, so the stale-revision guard is lost against
  such a daemon (commands.rs ~l.150). Capability-gated by design; flag only.

## Suspicions disproved

- Pairing port `+8443`: rejected by `Pairing::parse`; no non-canonical form
  accepted (probe passed).
- `IdemCache` `Instant::duration_since`: saturates since Rust 1.60, cannot
  panic on clock skew.
- Request revision `expect("request revision overflow")` (registry.rs:271,
  730): needs 2^64 updates, and a test covers `u64::MAX`.
- `parse_lstart_utc`: bad month, 60 seconds and extra tokens return `None`;
  no overflow possible in the `abs()` compare (year range is bounded by
  chrono).
- `read_line` (acd-inbox): bounds checked before every extend; `max`
  boundary tested.
- `settings_line` / `view_line` / `fit_text`: size is not monotonic in the
  cap (cutting a string slightly over the cap adds 12 chars of marker), but
  the binary search only keeps results that fit, so output is correct,
  only sometimes not the largest.
- `Backoff`: `saturating_mul`, cannot overflow.
- `redact_log` and `blank_cursor`/`replace_path_start`: all slice offsets
  come from `find`/`trim_start` on the same string, always on boundaries.
- `NotifyGate`: a rate-limited request is marked seen and never notified
  later; documented ("the card still shows").
- `Commands` resend/retry: items in `NotDelivered` are not double-sent on
  welcome; I found no missing transition.
