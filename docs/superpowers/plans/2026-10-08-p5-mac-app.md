# P5: Mac app implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the agent-caller Mac app: a Tauri v2 menu bar app with a
status icon, a non-activating floating panel opened by ⌥Space, keyboard
control, a 2-second undo, notifications and machine settings. It talks
acd/1 to one daemon per machine. The local daemon is reached over
`acd.sock`, and remote daemons over TLS pinned to each daemon's own key.

**Architecture:** Before the client is frozen, acd's TCP listeners move
to WebSocket over TLS (`wss`) with a long-lived self-signed key (D1).
`acd pair` prints a pairing string, and the app pins that key on every
connect. The acd/1 JSON handshake stays exactly as it is inside the TLS
channel.

All app logic that can run without a window lives in a new workspace
crate, `crates/acd-client`:

- the connection, TLS pinning, resume and readiness;
- the command and retry rules;
- the undo countdown;
- card ordering and the view model.

Linux and macOS CI both test it. The Tauri app in `app/` is a thin
shell: `app/src-tauri` is a separate Cargo workspace that owns the
windows, tray, hotkey, notifications, clipboard import and Keychain, and
forwards a ready-made `InboxView` to a small Svelte frontend. Neither
stored nor pasted secrets ever enter the webview.

**Tech Stack:**
- Rust (edition 2024): tokio, tokio-tungstenite, serde, ts-rs (TypeScript
  bindings).
- TLS: rustls with the ring provider, tokio-rustls and rcgen.
- App shell: Tauri 2.12 with tauri-nspanel, plus the global-shortcut,
  notification and clipboard-manager plugins. security-framework for the
  Keychain.
- Frontend: Svelte 5, Vite 8, TypeScript 6.0, Vitest 5 with jsdom and
  @testing-library/svelte.

**Spec:** `docs/superpowers/specs/2026-10-07-agent-inbox-design.md`, mainly
§5 (data model), §7 (acd/1), §8 (Mac app), §9, §10, §12, §13 and §14
acceptance items 1, 4, 5, 6, 7 and 8. The wire contract is
`crates/acd-protocol` (`model.rs`, `messages.rs`, `PROTOCOL.md`,
`schema/`, `examples/`). Follow-ups this plan must close:
`docs/superpowers/plans/2026-10-07-p1-followups.md`, section "P5: Mac
app". Sol's review of the first draft is in the review log at the end.

## Decisions

Each decision states what was chosen, why, and what it costs.

### D1. Pinned TLS for every TCP connection; `acd.sock` for the local machine (controller ruling)

**Problem** (P1 follow-up). A TCP client sends `hello {token}` to whatever
process holds the port. Sol's round-1 review (finding 1) showed that a
proof-first plaintext handshake does not fix this:

- acd serves the same router on several addresses, including loopback.
- A different local user who takes a newly assigned Tailscale address
  can relay the nonce exchange to the real acd on loopback, then inject
  frames into the authenticated session.

The Tailscale range check in spec §7.1 is not authentication either.
`100.64.0.0/10` is also carrier-grade NAT space, and the check says
nothing about which process on the node answers.

**Decision.**

- **Server key.** `acd init` creates a long-lived TLS key and a
  self-signed certificate: ECDSA P-256 from rcgen. Both are stored as one
  bundle, `tls.pem` (mode 0600), in the config directory. One file is one
  coherent generation: it is published by an atomic rename under a
  writer lock, and read with descriptor-based checks (Task 3; Sol r2
  findings 6 and 7).
  - `init` repairs them like the other secrets: if either is missing or
    unreadable, it regenerates both.
  - The key is independent of the client token, so
    `acd token rotate client` never changes it.
  - Only the new command `acd tls rotate` replaces it.
- **Transport.**
  - Every TCP listener, loopback included, serves `wss` only. TLS 1.3
    only, through rustls with the ring provider.
  - A plaintext `ws` request on the TCP port fails the TLS handshake and
    never reaches the router.
  - `acd.sock` stays plain WebSocket. It is a 0600 socket in the 0700
    config directory, so only the user's own uid can reach it.
- **Pin.** The pin is the base64url (no padding) SHA-256 of the
  certificate's DER SubjectPublicKeyInfo. Its wire form is
  `sha256:<43 chars>`.
- **Pairing.**
  - `acd pair` prints one line:
    `acd://<host>:<port>?pin=sha256:<b64url>#<client token>`. Hosts
    are taken in this order:
    - `--host` if given;
    - otherwise the MagicDNS name from `tailscale status --json`
      (`Self.DNSName`, without its trailing dot);
    - otherwise the first Tailscale IP.

    It prints the line to stdout, with a warning on stderr that the
    line holds a secret.
  - In the app, "Add machine from clipboard" makes the **Rust backend**
    read the clipboard, parse the string, and store
    `{token, pin}` in the Keychain. The webview never sees the string
    (finding 15).
- **Verification.**
  - On every TCP connect, the client's rustls verifier compares the
    server certificate's SPKI hash with the stored pin, in constant time.
  - It also requires a valid TLS 1.3 signature from that key, through
    rustls's `verify_tls13_signature` with the provider's algorithms.
  - There is no trust on first use, no CA trust, no hostname check (the
    pin replaces it), no expiry check (the key is pinned and long-lived),
    and no plaintext fallback.
  - A mismatch fails inside the TLS handshake, so `hello` is never sent.
    The machine shows "Server identity changed. Re-pair this machine."
- **acd/1 is unchanged.** The JSON handshake inside the channel stays
  `hello {protocol: "acd/1", token, client, resume?}`, with no new
  message types and no protocol-string change. That resolves Sol
  finding 9.
- **Pre-authentication bounds** (Sol r2 finding 5). At most 32
  unauthenticated TCP connections daemon-wide, shared by every listener.
  Each must authenticate within 10 s of TCP accept. TLS handshakes are
  5 s each, at most 16 at once. P1's 8-slot, 5 s `hello` limit is
  unchanged. Task 2 has the stage table.
- **Rotation of the TLS key.**
  - `acd tls rotate` writes a new key pair atomically.
  - The daemon reloads it within about 2 s (the same poll as
    `client.token`), and new handshakes use it.
  - Sessions that are already open continue. They were authenticated
    under the old key.
  - Every client must re-pair, so the command says so.
  - TLS key rotation keeps open sessions **and the client token**. After
    a suspected key compromise, also run `acd token rotate client`. That
    closes every session and revokes any token an impersonator holding
    the old key may have captured. `acd tls rotate` prints this advice.
  - Out of scope: compromise of the user's own uid (it can read every
    secret, including `tls.pem`), and denial of service by a permitted
    peer (it can fill the pre-auth slots or drop traffic).

**Why TLS.**

- TLS authenticates the whole channel. A squatter can forward encrypted
  bytes or drop them, but it cannot read the token or inject frames
  without the private key. That closes the relay case.
- It is a standard protocol, so no custom cryptography sits in acd.
- It keeps acd/1 unchanged, so P1 and P2 code, schemas and examples do
  not change, apart from the transport.

**Cost.**

- New dependencies: rustls 0.23, tokio-rustls 0.26, rcgen 0.14,
  rustls-pki-types 1, and x509-parser 0.18 in the client, to read the
  SPKI.
- A TLS listener in acd-core.
- `init`, `tls rotate` and `pair` in acd.
- Transport text in PROTOCOL.md §1 and spec §7.1 and §9.
- Pairing replaces "paste the token" in the app.
- TLS handshake CPU on each connect, which is negligible for one client
  per machine.
- A key rotation forces a re-pair of every client.

**Server stack: tokio-rustls behind axum's `Listener` trait, not
axum-server.**

- axum 0.8.9 exposes `axum::serve::Listener` (checked in its source). A
  `TlsListener` that runs TLS handshakes in spawned tasks (5 s timeout,
  at most 16 at once) and yields finished streams lets the daemon keep
  `axum::serve` for both TCP and the Unix socket. The router, its limits
  and its tests stay the same.
- axum-server 0.8.0 would replace `axum::serve` on the TCP side only,
  and bring a second serving path.

**Out of scope.** `tailscale whois` node validation could be added later
as extra hardening. It cannot tell users or processes on one node apart,
and it is not part of this plan.

### D2. Local machine: `acd.sock` for transport, `client.token` for the credential, read on every connect

- The app adds a `Local` machine entry on first run (spec §8).
- It connects over `<config_dir>/acd.sock`, where `config_dir` is
  `$ACD_CONFIG_DIR` or `~/.config/acd`. An app launched from Finder has no
  `ACD_CONFIG_DIR`, so in practice it is `~/.config/acd`. The app must not
  be sandboxed; v1 builds locally with no App Store, so it is not.
- The socket is plain WebSocket. Only the user's uid can reach it, so TLS
  is not needed there (D1).
- On every connect the app reads `client.token` the safe way (finding 11):
  - open the directory and the file with
    `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`;
  - `fstat` the **opened descriptor**: the directory must be a directory
    and the file a regular file, both owned by the effective uid, with no
    group or other mode bits;
  - read at most 256 bytes;
  - decode with the same canonical base64url decoder acd uses
    (`URL_SAFE_NO_PAD`, 43 characters, exactly 32 bytes, trailing bits
    rejected).
- The ownership predicate takes the expected uid as a parameter, so a
  unit test can cover it. A test with a real second account is manual.
- The local token is never copied into the Keychain. A copy would go
  stale after `acd token rotate client`, and the file already has the
  right protection.
- After a 4401 close on the local machine, the app re-reads the file and
  reconnects with backoff.

### D3. Build split and CI

- `crates/acd-client` joins the workspace through `members = ["crates/*"]`.
  It has no Tauri dependency, so Linux CI builds and tests it.
- `app/src-tauri` has its own `[workspace]` table. It is listed under
  `exclude` in the root `Cargo.toml`. It pins versions directly, because
  `workspace = true` does not reach across workspaces.
- The reason for the split: tauri needs GTK and WebKit dev packages to
  build on Linux. `tauri-nspanel` pulls `objc2-app-kit`, which builds only
  on macOS. And `tauri::generate_context!` fails to compile unless
  `frontendDist` (`app/dist`) and `icons/icon.png` exist (verified in
  `tauri-codegen` 2.7.1, `context.rs`).
- **Lockfiles** (finding 16). These are all committed:
  - the root `Cargo.lock` (already tracked);
  - `app/src-tauri/Cargo.lock`;
  - `app/package-lock.json`.

  Rust CI runs `--locked` everywhere, and npm uses `npm ci`.
- CI gains a job `app` on `macos-latest`. It installs Node 24 and runs
  `npm ci` and `npm run verify` in `app/`. That script runs:
  - svelte-check and vitest;
  - the Vite build;
  - app clippy `-D warnings` and app tests, both `--locked`;
  - a production `tauri build --bundles app --ci` smoke build
    (finding 13).
- The existing `test` job (ubuntu and macOS) gains `--locked`. It covers
  `acd-client`, including the bindings drift test.

### D4. Frontend: Svelte 5 with Vite and TypeScript

- The UI is one list of cards, a reply field, a countdown and a settings
  view. Svelte compiles to small DOM code with no runtime framework, and
  its runes give reactive state without a store library. Tests use
  Vitest and @testing-library/svelte.
- Rejected:
  - React, for its runtime size and the hooks boilerplate for timers;
  - Preact, which would also do. It is a wash on size, and Svelte's
    templates are shorter for this UI;
  - vanilla TS, which needs hand-written DOM diffing for cards that
    update every few seconds.
- The package manager is npm, which ships with Node.
- Svelte text interpolation escapes everything. `{@html}` is forbidden,
  because `raw_screen`, `detail` and titles come from terminals that an
  attacker can influence.

### D5. TypeScript bindings: ts-rs 12

- ts-rs 12.0.1 is stable. specta 2 is still a release candidate
  (2.0.0-rc.25).
- It is an optional feature, `ts`, on `acd-protocol` and `acd-client`.
  Only the model types (`model.rs`) and the app view types derive `TS`.
- Generated files are committed under `app/src/lib/bindings/`. A drift
  test fails when they are stale; `UPDATE_BINDINGS=1` rewrites them.
- `u64` is exported as `number` (`Config::with_large_int("number")`).
- Timestamps use `#[ts(type = "string")]`.
- The `no-serde-warnings` feature silences ts-rs's printed note about
  `#[serde(other)]`.

### D6. The acd/1 client lives in the Rust backend; no secret enters the webview

The guarantee (finding 15) is that neither a stored token nor a pasted
pairing string ever reaches the webview.

- The webview receives `InboxView` and `MachineEntryView`, which hold no
  secrets. It calls narrow commands such as `pick_option`.
- Adding a machine calls the `import_pairing_from_clipboard` command. The
  Rust backend reads the clipboard through
  `tauri-plugin-clipboard-manager`'s Rust API, parses the string, and
  stores the secret. It returns only `{key, name, host, port}`.
- The user never types the token into a web form. The settings view says
  "Run `acd pair` on the machine, copy the line, then click Add from
  clipboard".
- After importing, the backend does not clear the clipboard: it does not
  own it. The settings view suggests copying something else.
- The Tauri capability grants the windows only `core:event:default`.
  There is no fs, shell, http or clipboard permission for the webview;
  only Rust uses the clipboard plugin.
- The CSP is strict: `default-src 'self'`.

### D7. Keychain through security-framework 3.7.0

- The app is macOS-only.
  `security_framework::passwords::{set,get,delete}_generic_password` is a
  small, stable API (checked in the 3.7.0 crate source).
- keyring 4 was restructured around `keyring-core`, with every platform
  store optional. Its API was not verified, so it is not used.
- One item per remote machine: service `dev.agentcaller.inbox`, account
  the machine entry key.
- The value is JSON, `{"token": "...", "pin": "sha256:..."}`. The pin is
  not secret, but keeping it next to the token means one write updates
  both atomically.
- The store sits behind the `SecretStore` trait in `acd-client`, with
  `MemorySecrets` for tests.
- Unsigned local builds can trigger a Keychain access prompt after each
  rebuild, because the item ACL is tied to the code signature. This is
  checked manually.

### D8. Undo, ordering, tray state and feedback text are Rust, in `acd-client`

- The 2-second countdown runs on tokio. A hidden WKWebView may throttle
  JavaScript timers; tokio is not throttled.
- The schedule logic is a pure `Actions` table with explicit instants,
  tested at the exact boundary (finding 12).
- The frontend shows `fires_at_ms` and calls `cancel_action` or
  `escape`.
- Card ordering, the tray color and count, and every user-facing feedback
  string are computed in `acd-client::view`. That code is pure and tested
  on Linux.

### D9. Countdown policy

- One countdown per card. A second pick on a card whose countdown is
  running is ignored. Different cards may count down at the same time.
- **`Esc` is one atomic backend call** (finding 5). `escape()` cancels
  the newest countdown that exists in Rust and returns `true`. Only if
  none exists does the frontend close the reply field or hide the panel.
  `pick_option` and `escape` are synchronous Tauri commands, which run in
  invoke order, so an `Esc` pressed right after a pick always sees the
  countdown.
- A click on a card's countdown bar cancels that countdown.
- Hiding the panel does not cancel a countdown.
- **Connection generation** (finding 4).
  - Every successful handshake increments the machine's `conn_gen`.
  - A countdown records the `conn_gen` it was started under.
  - The machine task sends `MachineEvent::ConnectionEnded { gen }`
    synchronously on **every** connection end: close, error, silence,
    resync, 4408, 4401, replacement or removal. The broadcast channel is
    lossless up to its capacity, and a lagged receiver cancels every
    countdown of that machine.
  - The Inbox cancels the countdowns of that generation at once.
  - At fire time, the command goes out with `expect_gen`, and the
    machine task refuses it (`NotSent(Offline)`) unless it is the current
    connection. A disconnect and reconnect that a `watch` channel
    coalesces can therefore never let a countdown survive.
- A countdown is cancelled, and nothing is sent, when any of these
  happens before it fires (finding 7):
  - the request resolves, changes id, or goes to `answering`;
  - the request is no longer answerable;
  - the option disappears, becomes unselectable, or changes its reviewed
    meaning. The meaning is the option's `(id, label, effect,
    description)`, plus the request's `kind`, `answer_path`, `title` and
    `detail`. That includes a changed `allow_always` rule;
  - the `answer` capability disappears (for a reply, `send`);
  - the connection generation ends;
  - the app quits.

  The card then shows the matching notice.

### D10. `⏎` submits the reply field only

Spec §8 says "⏎ confirms" without saying what. Options are picked with
`1`–`9` and already pass through the undo, so `⏎` is never an option
shortcut. That avoids an accidental approval.

- In the reply field, `⏎` submits, which starts the countdown.
- `Shift+⏎` inserts a newline.
- Outside the field, `⏎` does nothing.
- **Guards** (finding 8). Before any dispatch, ignore the key event when
  any of these holds:
  - `event.isComposing`;
  - `event.keyCode === 229`, the WebKit IME signal, which can arrive
    without `isComposing`;
  - Cmd, Ctrl or Alt is held.

  So the `Enter` that commits Japanese composition never submits, the
  `Escape` that cancels a composition never cancels a countdown, and
  shortcuts like Cmd+1 do nothing.

### D11. Readiness, liveness and reconnect

- **Authenticated is not ready** (finding 3).
  - `welcome` sets the status `Syncing` and records `welcome.seq` as
    the readiness watermark. It is never used as the cursor.
  - The machine becomes `Online` (ready) only when one of these holds:
    - a snapshot has been applied;
    - in a same-epoch resume, the applied cursor reaches the watermark.
      A zero-event resume, where the cursor already equals
      `welcome.seq`, is ready at once.
  - Cards are actionable only when the machine is `Online`.
  - Backoff resets only on `Online`.
- **Liveness.** When no frame has arrived for 15 s, the client sends
  `ping`. If no frame arrives within 10 s after that, it drops the
  connection and reconnects. This covers Tailscale paths that go silent
  across sleep.
- **One deadline per attempt** (finding 10). TCP connect, the TLS
  handshake, the WebSocket upgrade and `hello` → `welcome` share one
  absolute deadline of `timing.connect_total` (8 s). The server bounds
  each TLS handshake at 5 s and runs at most 16 at once. The acd/1
  `hello` timeout is unchanged from P1.
- **Backoff** runs 1, 2, 4, 8, 16, 30, 30 … seconds.
- **Ends of a connection:**

  | Event | Local machine | Remote machine |
  |---|---|---|
  | TLS pin mismatch | n/a (Unix socket) | status `identity_changed` ("Server identity changed. Re-pair this machine."); retry every 30 s silently, so a short-lived squatter clears itself; never sends `hello` |
  | 4401 (`unauthorized`, `token rotated`) | revoke in-flight commands (finding 2), re-read `client.token`, reconnect with backoff; status `auth_failed` until it succeeds | revoke in-flight commands; status `auth_failed` ("The token was rejected. Re-pair this machine."); stop until re-paired |
  | 4400 or `unsupported_protocol` | stop, status `incompatible`, until the user retries | same |
  | 4408 | reconnect at once, with resume | same |
  | any other close, I/O error, TLS error or silence | status `offline` with `since`, backoff | same |

- **Revocation on 4401** (finding 2). When an authenticated session ends
  with 4401, every in-flight command of that machine completes as
  `Uncertain` and is never resent. That holds whether or not it was
  delivered: the daemon has already cancelled or resolved it (spec §7.1).
  Replacing a machine's credentials, or removing it, does the same.

### D12. Notifications

- A notification is posted only for a `request.opened` event, live or
  replayed, and only while the panel is hidden. Never from a snapshot.
- Deduplicated by `(machine.id, request.id)` for the life of the app.
- The title is `<agent title> on <machine name>`. The body is the request
  `title`, for example the tool name, never `detail`, which can hold
  commands with secrets and shows on the lock screen.

### D13. Follow-up decisions

- **Sessions per token are uncapped, and the 16384-entry idempotency table
  is shared.** Accepted for v1, with no daemon change. A token holder can
  already approve prompts. The app opens one session per machine and
  creates command ids only for user actions. It shows the daemon's
  `bad_request` message as a notice.
- **`reason` on `request.resolved`** (stray keystroke, P3). P5 does not
  add it. serde ignores unknown fields, so a daemon that sends it does
  not break this client. P3 adds the mapping in
  `acd_client::view::resolution_notice` when it adds the field. This is
  recorded in the follow-ups file (Task 18).

### D14. The same daemon added twice

If two machine entries report the same `welcome.machine.id`:

- the later entry in settings order gets `duplicate_of`;
- its cards are hidden;
- notifications are already deduplicated by machine id (D12).

### D15. Feasibility gate before the full UI (finding 16)

Task 13 runs a throwaway spike before Tasks 14–17. It is manual, and
Task 13 stops and escalates if it fails. It checks:

- the non-activating panel taking key focus;
- typing and IME in its webview;
- notifications from an unsigned build;
- the Keychain round trip.

These are the riskiest assumptions in the plan, and none of them can be
tested in CI.

## Global Constraints

These apply to every task.

- **Workspace rules.**
  - Rust edition 2024 and `rust-version = "1.90"`.
  - Every task ends green on all of these:
    - `cargo test --workspace --locked`;
    - `cargo clippy --workspace --all-targets --locked -- -D warnings`;
    - from Task 12 on, `npm --prefix app run verify`. That script runs
      `svelte-check --fail-on-warnings`, `vitest run` and `vite build`,
      then app clippy `-D warnings` and `cargo test`, both `--locked`
      through `--manifest-path src-tauri/Cargo.toml`, and finally
      `tauri build --bundles app --ci`.
  - App cargo commands need `app/dist`, so build the frontend first.
    `verify` does.
- **No secrets in the webview** (D6).
  - No command argument, return value or event carries a token, a
    pairing string, or a pin.
  - Logs never contain tokens or pairing strings.
- **No `{@html}`** anywhere in `app/src`. Task 17 adds a test that fails
  if one appears. Render `raw_screen` in a `<pre>` as text.
- **Transport** (D1).
  - A remote machine is always `wss` with the stored pin.
  - The local machine is always `acd.sock`.
  - There is no plaintext TCP client path at all.
  - Before TLS, a TCP host must resolve to an allowed IP:
    `100.64.0.0/10`, `fd7a:115c:a1e0::/48`, or loopback. Resolve the
    name once, filter the addresses, and connect to a vetted
    `SocketAddr`. This range check is hygiene, not authentication; the
    pin is the authentication.
- **Capabilities** (spec §7.5). These paths check the current
  `welcome.capabilities` before sending (finding 7):
  - initial sends;
  - timer retries;
  - reconnect resends;
  - countdown fire.

  If the capability is missing, a command that was never sent completes
  `NotSent(NotAdvertised)`. A command that was sent before completes
  `Uncertain`, without a resend.
- **Answerable** (spec §5, §7.2). A card is answerable when all of these
  hold:
  - its machine is `Online` (ready, D11);
  - `answer` is advertised;
  - `pending.is_answerable()`;
  - `pending.status == Open`.

  An option is selectable only if its `effect` is not `Unknown`.
  Picking an `allow_always` option shows its `description`, the exact
  rule, during the countdown (spec §6.2).
- **Unknown input** (spec §7.2).
  - Use `acd_protocol::decode_server`, and skip `Ok(None)`.
  - A decode error on any frame forces a full resync: drop the
    connection, clear the cursor, and reconnect without `resume`.
  - Unknown enum values decode to `Unknown` (Task 1). They are grouped
    or rendered read-only. An unknown resolution gives "Check the
    terminal".
- **Sequencing** (spec §7.4).
  - The cursor is the `(epoch, seq)` of the last applied snapshot or
    event.
  - An event is applied only when its epoch equals the cursor epoch and
    `seq == cursor.seq + 1`. A `seq` at or below the cursor is a
    duplicate and is skipped. Anything else forces a resync.
  - After a `welcome` in a new epoch, nothing applies until the
    snapshot.
  - `welcome.seq` is only a readiness watermark (D11).
- **Commands** (spec §7.3, §7.4, §8).
  - Every command id is a fresh UUID v4.
  - **Same epoch.** If the connection drops before the result, and the
    session reconnects into the same epoch **without** a 4401, resend the
    identical id and payload.
  - **New epoch, or after a 4401.** The command becomes `Uncertain` and
    is never resent.
  - **`request_not_ready`** is retried with the same id every 250 ms. An
    absolute deadline of `first_sent + 3 s` is checked immediately before
    **every** resend, including resends after a reconnect. Past it, the
    command completes `Failed(request_not_ready)` (finding 6).
- **Undo.**
  - 2 s from the pick or reply submit to the send.
  - `Esc` (atomic, D9) or a click on the bar cancels.
  - Nothing is sent unless the countdown's connection generation is
    still current at the moment of sending.
- **Feedback strings** (exact text; `view::notice_for_*` owns them):

  | Condition | Text | Tone |

  | `not_supported`, or the capability is missing | `Not supported for this agent` | info |
  | the connection ended during the countdown, or the machine was not `Online` at fire | `Offline. Nothing was sent.` | warning |

```rust
//! JSON Schema generators. The committed files in `schema/` are exactly
//! `to_string_pretty` of these values.
use serde_json::{json, Value};

use crate::{ClientMessage, ServerMessage};

/// Adds `rule` to the `allOf` of the tagged-enum variant whose `type` is `name`.
fn add_rule(schema: &mut Value, name: &str, rule: Value) {
    let variants = schema["oneOf"].as_array_mut().expect("tagged enums render as oneOf");
    let v = variants
        .iter_mut()
        .find(|v| v["properties"]["type"]["const"] == name)
        .unwrap_or_else(|| panic!("no variant {name}"));
    let all = v.as_object_mut().expect("variant is an object").entry("allOf").or_insert_with(|| json!([]));
    all.as_array_mut().expect("allOf is an array").push(rule);
}

pub fn client_schema() -> Value {
    let mut s = serde_json::to_value(schemars::schema_for!(ClientMessage)).expect("schema");
    // request.answer carries exactly one of option_id or text (spec §7.3).
    // `null` counts as absent, as it does for the Rust decoder (Sol finding 14).
    add_rule(&mut s, "request.answer", json!({"oneOf": [
        {"required": ["option_id"], "properties": {"option_id": {"type": "string"}, "text": {"type": "null"}}},
        {"required": ["text"], "properties": {"text": {"type": "string"}, "option_id": {"type": "null"}}}
    ]}));
    s
}

pub fn server_schema() -> Value {
    let mut s = serde_json::to_value(schemars::schema_for!(ServerMessage)).expect("schema");
    // result: ok=true never has error; ok=false has error and no outcome.
    add_rule(&mut s, "result", json!({"oneOf": [
        {"properties": {"ok": {"const": true}, "error": {"type": "null"}}},
        {"required": ["error"], "properties": {"ok": {"const": false}, "error": {"type": "object"}, "outcome": {"type": "null"}}}
    ]}));
    s
}
```

**Pre-authentication stages** (Sol r2 finding 5). They are documented in
PROTOCOL.md §1 by Task 3.

| Stage | Bound |
|---|---|
| A. TCP accept → TLS finished | At most 16 handshakes at once. 5 s each, then the socket is dropped. |
| B. TLS finished → HTTP upgrade request complete | Covered by the pre-auth deadline below. A silent or trickling HTTP client is cut when the deadline passes. |
| C. Upgrade → `hello` authenticated | P1's limits, unchanged: at most 8 at once, `hello` within 5 s. |
| A + B + C | At most `MAX_UNAUTHENTICATED_TCP` (32) unauthenticated TCP connections **daemon-wide**, through one `Admission` shared by every TCP listener. Every one must be authenticated within `preauth_deadline` (10 s) of TCP accept, or `TlsIo` ends it: reads return EOF and writes `BrokenPipe`. |

**How it works:**

- At TCP accept, `TlsListener` calls `admission.try_acquire()`. If no
  permit is free, the socket is dropped at once.
- The permit moves into an `Admit` that lives with the `TlsIo`. It is
  released by `Admit::authenticated()`, or when the connection drops.
- `TlsIo` holds a deadline timer that `authenticated()` disarms.
- The daemon serves TCP with
  `app.into_make_service_with_connect_info::<Admit>()`. The acd-core
  `upgrade` handler takes `Option<ConnectInfo<Admit>>`, which is `None`
  on the Unix socket. After successful token authentication, `session`
  calls `admit.authenticated()`.

**Listener lifecycle** (Sol r2 finding 4).

- `TlsListener` owns its accept task through an abort-on-drop handle.
- The accept task owns the `TcpListener` and a `JoinSet` of handshake
  tasks.
- The delivery channel to `Listener::accept` is bounded at 16. When the
  receiver is gone, `send` fails and the task exits.
- Dropping the `TlsListener` aborts the accept task. That drops the
  `TcpListener`, which releases the port, and aborts the `JoinSet`, which
  ends pending handshakes.
- Aborting the `axum::serve` task drops the listener, so the port is free
  without waiting for another incoming connection.
- Already-handed-off connections are axum's. Tests end them with the
  `KillSwitch`.

**`pairing.rs`.** Parse by hand:

1. Trim the input.
2. Strip the `acd://` prefix (`Scheme`).
3. Split once at `#`. The token must pass the canonical decode: 43
   characters, `URL_SAFE_NO_PAD`, exactly 32 bytes (`Token`).
4. Split once at `?pin=`. The pin must be `sha256:` plus 43 characters
   that decode to 32 bytes (`Pin`).
5. The host is `[...]` for IPv6; otherwise split at the last `:`. The
   port must be `1..=65535` (`Port`). The host must be non-empty, with
   no whitespace, `/`, `@`, `?` or `#` (`Host`).

`to_line` brackets hosts that contain `:`.

**`acd-securefs` (`src/lib.rs`).** This is Task 4's descriptor-based checker, moved into its own crate
so that the daemon and the client share one implementation.

- `open` uses `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` (plus `O_DIRECTORY`
  for `check_private_dir`). The errors map like this:
  - `ELOOP` gives `Symlink`;
  - `ENOENT` gives `Missing`;
  - `ENOTDIR` gives `NotRegular`.
- Then `fstat` the descriptor (`File::metadata`), and check:
  - the type (a regular file, or a directory);
  - `owner_ok(uid, euid())`;

- `read_private` reads `take(max_len + 1)`. Reading more than `max_len`

```rust
pub fn generate(common_name: &str) -> KeyFiles {
    let key = rcgen::KeyPair::generate().expect("P-256 key generation");
    let mut params = rcgen::CertificateParams::new(Vec::<String>::new()).expect("empty SAN list");
    params.distinguished_name.push(rcgen::DnType::CommonName, common_name);
    let cert = params.self_signed(&key).expect("self-signed certificate");
    KeyFiles { key_pem: key.serialize_pem(), cert_pem: cert.pem() }
}

pub fn check_pair(f: &KeyFiles) -> Result<String, TlsError> {
    let key = rcgen::KeyPair::from_pem(&f.key_pem).map_err(|e| TlsError::Pem(e.to_string()))?;
    let cert_der = CertificateDer::from_pem_slice(f.cert_pem.as_bytes()).map_err(|e| TlsError::Pem(e.to_string()))?;
    let (_, cert) = x509_parser::parse_x509_certificate(cert_der.as_ref()).map_err(|e| TlsError::Cert(e.to_string()))?;
    let spki = cert.tbs_certificate.subject_pki.raw;
    if key.public_key_der() != spki { return Err(TlsError::Cert("key does not match certificate".into())); }
    Ok(acd_protocol::pairing::spki_pin(spki))
}
```

**`TlsListener`.** The accept task:

```text
loop {
  select! { _ = closed (rx dropped) => return,
            r = tcp.accept() => {
              let Some(permit) = admission.try_acquire() else { drop(stream); continue };
              if handshakes.len() >= max_handshakes { drop(stream); continue }
              let admit = Admit::new(permit, limits.preauth_deadline from accept time);
              handshakes.spawn(timeout(limits.handshake, acceptor(config.borrow().clone()).accept(stream))
                               -> on Ok: tx.send(TlsIo::new(tls, admit, kill.subscribe())).await (bounded; Err => return));
            }
            Some(_) = handshakes.join_next() => {} }
}
```

**`TlsIo`.** It forwards reads and writes to the inner stream unless:

- killed;
- or the pre-auth deadline passed before `admit.authenticated()`.

In both cases reads return `Ok(0)` and writes return `BrokenPipe`. The
deadline is an `Instant` checked on every poll, together with a
`tokio::time::Sleep` stored in the `TlsIo` and polled in `poll_read`, so
that a silent peer is woken and cut. `TlsIo::admit()` returns a clone of
the `Admit`.

`upgrade`, and pass it into `session`. Call `admit.authenticated()`

  - `crates/acd/src/tls.rs`:
    - `publish(dir, &KeyFiles) -> Result<()>`. It takes an exclusive
      `flock` on `dir/tls.lock` (created 0600), which serializes writers
      across processes. It writes the bundle to a unique temporary file,
      `tls.pem.<pid>.<16 hex random>.tmp` (`O_CREAT|O_EXCL`, 0600), then
      fsyncs it, renames it over `tls.pem`, and fsyncs the directory.
    - Failpoint: in debug builds only (`#[cfg(debug_assertions)]`),
      `ACD_TEST_FAILPOINT=publish_before_rename` makes `publish` return
      an error after the temporary bundle is written and fsynced, and
      before the rename. The temporary file is left behind, as after a
      crash. Release builds compile the check out.
    - `load(dir) -> Result<(KeyFiles, String /*pin*/)>` reads and
      validates one generation.
    - `ensure(dir)`, used by `init`: keep a valid bundle; otherwise
      generate and `publish`. Leftover `tls.pem.*.tmp` files older than
      a minute are removed.
    - `rotate(dir)` always generates and publishes.
    - `watch(dir, tx)` polls `load` every 2 s and sends a new
      `ServerConfig` when the pin changes.
  - `acd tls rotate` prints "TLS key replaced. Re-pair every app with
    `acd pair`. If you rotated because the key may be compromised, also
    run `acd token rotate client`."
  - `acd pair [--host H]` prints `Pairing::to_line()`, built from a
    single `load` (one generation).

```rust
//! Where a machine's acd lives, and the Tailscale address rule (spec §7.1).
//! The range check is not authentication (100.64/10 is also CGNAT space);
//! the D1 handshake authenticates the server.
use std::net::{IpAddr, SocketAddr};
use std::path::PathBuf;

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Endpoint {
    Local { config_dir: PathBuf },
    /// Always wss, verified against `pin` (decision D1).
    Tcp { host: String, port: u16, pin: String },
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum EndpointError {
    #[error("cannot resolve {0}")]
    Resolve(String),
    #[error("{host} resolves to {addrs:?}; none is a Tailscale or loopback address")]
    NotTailscale { host: String, addrs: Vec<IpAddr> },
}

pub fn allowed_ip(ip: IpAddr) -> bool {
    match ip {
        IpAddr::V4(v4) => v4.is_loopback() || (v4.octets()[0] == 100 && v4.octets()[1] & 0xC0 == 0x40),
        IpAddr::V6(v6) => match v6.to_ipv4_mapped() {
            Some(v4) => allowed_ip(IpAddr::V4(v4)),
            None => v6.is_loopback() || v6.segments()[..3] == [0xfd7a, 0x115c, 0xa1e0],
        },
    }
}

/// Resolves once and keeps only allowed addresses. Callers connect to the
/// returned addresses and never resolve the name again.
pub async fn vet(host: &str, port: u16) -> Result<Vec<SocketAddr>, EndpointError> {
    let all: Vec<SocketAddr> = tokio::net::lookup_host((host, port))
        .await
        .map_err(|_| EndpointError::Resolve(host.to_string()))?
        .collect();
    let ok: Vec<SocketAddr> = all.iter().copied().filter(|a| allowed_ip(a.ip())).collect();
    if ok.is_empty() {
        return Err(EndpointError::NotTailscale { host: host.to_string(), addrs: all.iter().map(|a| a.ip()).collect() });
    }
    Ok(ok)
}
```

```rust
    Changed,

    pub fn resume(&self) -> Option<Cursor>;
    pub fn has(&self, capability: &str) -> bool;
    pub fn welcome(&mut self, machine: Machine, capabilities: Vec<String>, epoch: &str, seq: u64) -> EpochChange;
    pub fn apply(&mut self, msg: &ServerMessage) -> Applied;
    pub fn force_resync(&mut self);
    pub fn synced(&self) -> bool;    // a snapshot or replay base is in place (cursor is Some and not awaiting)

```

- `known_epoch` survives `force_resync`. A resync in the same epoch is
  therefore `Same`, not `New`, and does not make in-flight commands
  uncertain.
- `cursor` is cleared by `force_resync`, and by a `welcome` whose epoch
  differs from the cursor's.
- `welcome(.., seq)` stores `seq` as the readiness watermark. It never
  moves the cursor (spec §7.4).
- `ready()` is `synced() && cursor.seq >= watermark`. After a snapshot,
  the cursor is at least the watermark, because the daemon builds the
  snapshot after accepting. After a same-epoch resume, the cursor reaches
  the watermark once the replay has been applied. A zero-event resume
  (`cursor.seq == welcome.seq`) is ready at once.

```rust
#[derive(Clone, Debug, Default)]
pub struct Session {
    pub machine: Option<Machine>,
    pub capabilities: Vec<String>,
    pub agents: BTreeMap<String, Agent>,
    cursor: Option<Cursor>,
    known_epoch: Option<String>,
    welcome_epoch: Option<String>,
    awaiting_snapshot: bool,

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum EpochChange { First, Same, New }

pub enum Applied {
    Ignored,
    Changed,
    Opened(Request),
    Resolved { request_id: String, agent_id: String, by: ResolvedBy, option_id: Option<String> },
    Resync(&'static str),
}

fn event_pos(msg: &ServerMessage) -> Option<(&str, u64)> {
    match msg {
        ServerMessage::AgentUpdated { epoch, seq, .. }
        | ServerMessage::AgentRemoved { epoch, seq, .. }
        | ServerMessage::RequestOpened { epoch, seq, .. }
        | ServerMessage::RequestResolved { epoch, seq, .. }
        | ServerMessage::MachineUpdated { epoch, seq, .. } => Some((epoch, *seq)),
        _ => None,
    }
}

impl Session {
    pub fn cursor(&self) -> Option<&Cursor> { self.cursor.as_ref() }
    pub fn resume(&self) -> Option<Cursor> { self.cursor.clone() }
    pub fn has(&self, capability: &str) -> bool { self.capabilities.iter().any(|c| c == capability) }
    pub fn synced(&self) -> bool { self.cursor.is_some() && !self.awaiting_snapshot }

    pub fn ready(&self) -> bool { self.synced() && self.cursor.as_ref().is_some_and(|c| c.seq >= self.watermark) }

    pub fn welcome(&mut self, machine: Machine, capabilities: Vec<String>, epoch: &str, seq: u64) -> EpochChange {
        self.watermark = seq;
        let change = match self.known_epoch.as_deref() {
            None => EpochChange::First,
            Some(e) if e == epoch => EpochChange::Same,
            Some(_) => EpochChange::New,
        };
        self.machine = Some(machine);
        self.capabilities = capabilities;
        self.known_epoch = Some(epoch.to_string());
        self.welcome_epoch = Some(epoch.to_string());
        if self.cursor.as_ref().is_some_and(|c| c.epoch != epoch) { self.cursor = None; }
        self.awaiting_snapshot = self.cursor.is_none();
        change
    }

    pub fn force_resync(&mut self) {
        self.cursor = None;
        self.awaiting_snapshot = true;
    }

    pub fn apply(&mut self, msg: &ServerMessage) -> Applied {
        if let ServerMessage::Snapshot { epoch, seq, agents } = msg {
            if self.welcome_epoch.as_deref() != Some(epoch.as_str()) { return Applied::Resync("snapshot from another epoch"); }
            self.agents = agents.iter().map(|a| (a.id.clone(), a.clone())).collect();
            self.cursor = Some(Cursor { epoch: epoch.clone(), seq: *seq });
            self.awaiting_snapshot = false;
            return Applied::Changed;
        }
        let Some((epoch, seq)) = event_pos(msg) else { return Applied::Ignored };
        if self.awaiting_snapshot { return Applied::Resync("event before snapshot"); }
        let Some(cursor) = self.cursor.as_mut() else { return Applied::Resync("event before snapshot") };
        if cursor.epoch != epoch { return Applied::Resync("event from another epoch"); }
        if seq <= cursor.seq { return Applied::Ignored; }
        if seq != cursor.seq + 1 { return Applied::Resync("sequence gap"); }
        cursor.seq = seq;
        match msg {
            ServerMessage::AgentUpdated { agent, .. } => { self.agents.insert(agent.id.clone(), agent.clone()); Applied::Changed }
            ServerMessage::AgentRemoved { agent_id, .. } => { self.agents.remove(agent_id); Applied::Changed }
            ServerMessage::MachineUpdated { machine, .. } => { self.machine = Some(machine.clone()); Applied::Changed }
            ServerMessage::RequestOpened { request, .. } => Applied::Opened(request.clone()),
            ServerMessage::RequestResolved { request_id, agent_id, by, option_id, .. } => Applied::Resolved {
                request_id: request_id.clone(), agent_id: agent_id.clone(), by: *by, option_id: option_id.clone(),
            },
            _ => Applied::Ignored,
        }
    }
}
```

```rust
//! the pin from pairing, and the server must prove possession of that key.
use std::sync::Arc;

use acd_protocol::pairing::{pins_equal, spki_pin};
use rustls::client::danger::{HandshakeSignatureValid, ServerCertVerified, ServerCertVerifier};
use rustls::crypto::{verify_tls12_signature, verify_tls13_signature, CryptoProvider, WebPkiSupportedAlgorithms};
use rustls::pki_types::{CertificateDer, ServerName, UnixTime};
use rustls::{DigitallySignedStruct, Error, SignatureScheme};

#[derive(Debug)]
pub struct PinVerifier { pin: String, algs: WebPkiSupportedAlgorithms }

pub const PIN_MISMATCH: &str = "acd: server key does not match the pairing pin";

impl ServerCertVerifier for PinVerifier {
    fn verify_server_cert(&self, end_entity: &CertificateDer<'_>, _inter: &[CertificateDer<'_>], _name: &ServerName<'_>,
                          _ocsp: &[u8], _now: UnixTime) -> Result<ServerCertVerified, Error> {
        let (_, cert) = x509_parser::parse_x509_certificate(end_entity.as_ref())
            .map_err(|_| Error::General(PIN_MISMATCH.into()))?;
        if pins_equal(&spki_pin(cert.tbs_certificate.subject_pki.raw), &self.pin) {
            Ok(ServerCertVerified::assertion())
        } else {
            Err(Error::General(PIN_MISMATCH.into()))
        }
    }
    fn verify_tls12_signature(&self, m: &[u8], c: &CertificateDer<'_>, d: &DigitallySignedStruct) -> Result<HandshakeSignatureValid, Error> {
        verify_tls12_signature(m, c, d, &self.algs)   // unreachable: TLS 1.3 only, kept for the trait
    }
    fn verify_tls13_signature(&self, m: &[u8], c: &CertificateDer<'_>, d: &DigitallySignedStruct) -> Result<HandshakeSignatureValid, Error> {
        verify_tls13_signature(m, c, d, &self.algs)
    }
    fn supported_verify_schemes(&self) -> Vec<SignatureScheme> { self.algs.supported_schemes() }
}

pub fn client_config(pin: &str) -> Arc<rustls::ClientConfig> {
    let provider: Arc<CryptoProvider> = Arc::new(rustls::crypto::ring::default_provider());
    let algs = provider.signature_verification_algorithms;
    let cfg = rustls::ClientConfig::builder_with_provider(provider)
        .with_protocol_versions(&[&rustls::version::TLS13])

        .with_custom_certificate_verifier(Arc::new(PinVerifier { pin: pin.to_string(), algs }))
        .with_no_client_auth();
    Arc::new(cfg)
}
```

```rust
    PinMismatch,
    Incompatible(String),     // 4400 / unsupported_protocol: wait for retry_now
```

**`open(cfg, deadline) -> Result<(Ws, String), End>`.** It returns the
WebSocket and the token. Everything runs under `timeout_at(deadline, …)`,
where `deadline = Instant::now() + timing.connect_total` (finding 10).

- The token comes from `Credential::Token`, or from
  `read_local_token(dir)` for `LocalFile`. A `LocalError` gives
  `End::Local`.
- `Endpoint::Local`: `UnixStream::connect(socket_path(dir))`, then
  `client_async("ws://localhost/", Box::new(stream))`.
- `Endpoint::Tcp { host, port, pin }`:
  1. `vet(host, port)`; an error gives `Offline`.
  2. `TcpStream::connect` to each vetted address in turn.
  3. `tokio_rustls::TlsConnector::from(tls::client_config(pin)).connect(server_name, tcp)`.
     `server_name` is `ServerName::try_from(host)`. For an IP literal,
     use `ServerName::IpAddress`. If neither parses, use the fixed name
     `acd.invalid`; the verifier ignores names.
  4. A TLS error where `is_pin_mismatch` holds gives `PinMismatch`. Any
     other TLS error gives `Offline`.
  5. `client_async(format!("wss://{host_for_url}:{port}/"), Box::new(tls_stream))`.
     If tungstenite refuses the `wss` scheme over a stream it did not
     open, use `ws://` in the URL; only the Host header matters. Write
     down which one worked.

**`handshake(ws, token, client, resume, deadline) -> Result<(Machine, Vec<String>, String, u64), End>`.**

1. Send `ClientMessage::Hello { protocol: PROTOCOL.into(), token: token.to_string(), client: client.clone(), resume }`.
2. Read until `Welcome { machine, capabilities, epoch, seq }`, under the
   same deadline. The mapping:
   - `Error { code: UnsupportedProtocol }` or close 4400 gives
     `Incompatible`;
   - `Error { code: Unauthorized }` or close 4401 gives `Unauthorized`;
   - any other `Error` gives `Offline(message)`;
   - a deadline overrun gives `Offline("handshake timed out")`.

**`run(cfg, ctl_rx, state_tx, events_tx)`:**

```text
session = Session::default(); backoff = Backoff::new(base, max); offline_since = None; gen = 0
loop:
  if status is not one of AuthFailed/IdentityChanged/Incompatible/LocalUnavailable: publish(Connecting)
  deadline = now + connect_total
  end = match open(..) {
    Err(e) => e,
    Ok((ws, token)) => match handshake(.., session.resume(), deadline) {
      Err(e) => e,
      Ok((machine, caps, epoch, wseq)) => {
        gen += 1
        change = session.welcome(machine, caps, &epoch, wseq)
        events.send(Welcomed { gen, change })
        offline_since = None
        publish(if session.ready() { Online } else { Syncing })   // zero-event resume is ready at once
        if session.ready() { events.send(Ready { gen }); backoff.reset() }
        let end = serve(ws, &mut session, gen, ..).await
        events.send(ConnectionEnded { gen })     // synchronously, before any status publish (D9)
        end
      } } }
  delay = match end:
    Offline(err)      => { offline_since.get_or_insert(now_ms()); publish(Offline{since_ms, error}); backoff.next_delay() }
    Resync(why)       => { session.force_resync(); publish(Connecting); backoff.next_delay() }
    TooSlow           => { publish(Connecting); Duration::ZERO }
    Unauthorized      => local: publish(AuthFailed{"acd rejected client.token; re-reading it"}); backoff.next_delay()
                         remote: publish(AuthFailed{"The token was rejected. Re-pair this machine."}); wait_for_retry_now(); continue
    PinMismatch       => { publish(IdentityChanged{"Server identity changed. Re-pair this machine."}); timing.identity_retry }
    Local(msg)        => { publish(LocalUnavailable{msg}); backoff.next_delay() }
    Incompatible(msg) => { publish(Incompatible{msg}); wait_for_retry_now(); continue }
  wait `delay`, returning early on RetryNow
```

- `publish` calls `send_replace` with
  `MachineState { status, session: session.clone(), conn_gen: gen }`.
- While the machine is not `Online`, the session keeps its last agents,
  and the view shows them greyed and read-only.

**`serve(ws, session, gen, ..) -> End`.** Its `select!` arms:

- **Frames.** Record `last_frame` and clear the ping deadline. Then run
  `decode_server`:
  - an `Err` gives `End::Resync("undecodable frame")`;
  - `Ok(None)` is skipped;
  - `Pong` is ignored;
  - `Result` goes to Task 8;
  - `Error` is logged at warn level;
  - anything else goes to `session.apply`:
    - `Changed` publishes;
    - `Opened(r)` publishes and sends the event;
    - `Resolved` sends the event;
    - `Resync(why)` returns `End::Resync(why)`.

    After each apply, on the first transition to `session.ready()`,
    publish `Online`, send `Ready { gen }` and reset the backoff.
- **Close frames.** 4401 gives `Unauthorized`, 4400 `Incompatible`, and
  4408 `TooSlow`; any other code gives `Offline("closed")`.
- **Ping timer.** After `idle_ping` with no frame, send
  `Ping { id: Uuid::new_v4() }`. If `ping_timeout` passes without a
  frame, return `End::Offline("no reply to ping")`.
- **`ctl_rx`.** `DropConnection` closes the socket and returns
  `Offline("dropped by request")`. `RetryNow` is ignored. `Submit` goes
  to Task 8; until then, reply `NotSent(Offline)`.

Outside `serve`, every `Submit` is answered with `NotSent(Offline)`. The
receiver is drained while waiting, so submits never hang.

`MachineHandle::submit`:

- if sending the `Submit` control fails (the task is gone), return

```rust
pub(crate) struct Inflight {
    pub id: String,
    pub cmd: Command,
    pub msg: ClientMessage,
    pub first_sent: Instant,
    pub retry_at: Option<Instant>,           // Some only after request_not_ready
    pub delivery: Delivery,                  // what the last attempt proved (Sol r2 finding 1)
    pub cred: [u8; 32],                      // sha256 of the token that authorized it (Sol r2 finding 2)
    pub reply: oneshot::Sender<Outcome>,
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Delivery { Unknown, NotDelivered }   // NotDelivered only between a request_not_ready result and the next send
impl Commands {
    pub fn begin(&mut self, cmd: Command, reply: oneshot::Sender<Outcome>, caps: &[String], cred: [u8; 32], now: Instant) -> Option<ClientMessage>; // None: NotSent(NotAdvertised)
    pub fn on_result(&mut self, r: &CommandResult, now: Instant, t: &Timing);
    pub fn due(&mut self, now: Instant, caps: &[String], t: &Timing) -> Vec<ClientMessage>;
    pub fn next_due(&self) -> Option<Instant>;
    pub fn on_welcome(&mut self, change: EpochChange, caps: &[String], now: Instant, t: &Timing) -> Vec<ClientMessage>;
    pub fn revoke_all(&mut self);                                    // every item -> Uncertain (finding 2)
    pub fn revoke_other_creds(&mut self, cred: [u8; 32]);            // items authorized by another token -> Uncertain
}
```

**Rules.** These close round-1 findings 2, 6 and 7, and round-2 findings
1, 2 and 8.

- **States.** Every item starts `Unknown`: once a frame may have been
  written, delivery is unknown. A partial or failed write is treated as
  `Unknown` too. Only a `request_not_ready` result sets `NotDelivered`,
  and the **next send attempt sets it back to `Unknown` immediately
  before writing** (r2 finding 1). Expiry can therefore claim
  non-delivery only for an item whose last attempt is proven not
  delivered.
- **`begin`.** If the capability is missing, complete
  `NotSent(NotAdvertised)` and send nothing. Otherwise create the id
  (UUID v4), store the item with `delivery = Unknown` and `cred`, and
  return the message.
- **`on_result`.**
  - `ok` with `delivered` completes `Delivered`; `ok` alone completes
    `Done`.
  - `request_not_ready` sets `delivery = NotDelivered`. If
    `now + interval <= first_sent + window`, it sets
    `retry_at = now + interval`. Otherwise it completes
    `Failed(request_not_ready)`.
  - Any other error completes `Failed`.
- **`due(now)`.** For each item with `retry_at <= now` (always
  `NotDelivered`):
  - if `now > first_sent + window`, complete `Failed(request_not_ready)`
    without sending (the absolute deadline);
  - else if the capability is missing, complete `NotSent(NotAdvertised)`;
  - else clear `retry_at`, **set `delivery = Unknown`**, and return the
    message.
- **`on_welcome(change)`:**
  - `New`: `revoke_all()`.
  - `Same` or `First`:
    - `NotDelivered` items follow the `due` rules: expired ones fail, the
      rest wait for `retry_at`;
    - `Unknown` items older than `stale_inflight`, or whose capability is
      now missing, complete `Uncertain`, because they may have been
      delivered;
    - every other `Unknown` item is returned for an identical resend.
      These are never expired as `request_not_ready`.
- **Credentials** (r2 finding 2). `conn.rs` computes
  `cred = sha256(token)` for every connection attempt, right after
  reading the token and **before** the handshake. If it differs from the
  credential of the previous attempt, it calls
  `commands.revoke_other_creds(cred)` before anything is sent with the
  new token. That covers a local token rotated while the client was
  disconnected, with no 4401 received. `begin` tags new items with the
  current `cred`.
- **`conn.rs`:**
  - after a session that was authenticated ends with `Unauthorized`
    (4401), call `commands.revoke_all()` before any reconnect;
  - after `Welcomed`, call `on_welcome` and send what it returns;
  - a `select!` arm on `sleep_until(next_due)` sends `due(now)`;
  - a `Submit` whose `expect_gen` does not match, or that arrives while
    not `Online`, gets `NotSent(Offline)`.

**`check(action, state)`.** Every failure returns the notice shown after
the arrow:

- `state.instance != action.instance`, or
  `state.conn_gen != action.conn_gen`, or the status is not `Online` →
  `Offline. Nothing was sent.`
- The capability for the action is missing → `Not supported for this
  agent`.
- `Answer`:
  - the agent is missing → `The agent is gone`;
  - `pending` is `None`, has another id, or its status is not `Open` →
    `Answered elsewhere`;
  - `!pending.is_answerable()`, or `Semantics::of(pending, option_id)`
    differs from the stored one, or the option's effect is `Unknown` →
    `The request changed. Nothing was sent.`
- `Reply`:
  - the agent is missing → `The agent is gone`;
  - `!agent.can_send` → `The agent is busy. Try again when it is idle.`

**Firing.**

- One timer task per Inbox sleeps until `actions.next_due()`, and is
  woken when the table changes.
- On wake, `due(now)` removes the due actions. Each one is checked
  against the current state. On success it is sent with
  `handle.submit(cmd, Some(action.conn_gen))`, so the machine task also
  refuses a stale generation.
- The outcome becomes a notice through `notice_for_outcome`.
- `busy` holds the card key while the submit is awaited.

**Generations.**

- For each machine, a task forwards its `(instance, MachineEvent)`s.
  Under the Inbox lock, an event whose instance is not the machine's
  current instance is **discarded**. A late `ConnectionEnded` from a
  replaced task can then never cancel the new task's countdowns (Sol r2
  finding 3).
- `ConnectionEnded { gen }` calls `actions.end_generation(key, gen)`
  **at once**, and sets the notice `Offline. Nothing was sent.` on each
  removed card.
- A `broadcast::error::RecvError::Lagged` calls `end_machine(key)`.
- Then `wake`.

**`escape`.** Lock, run `actions.cancel_latest()`, then wake. Return
`true` if an action was removed. The Tauri command is synchronous (Task
14), so it runs after any `pick` invoked before it.

```rust
//! Remote machine secrets in the login Keychain (decision D7).
use acd_client::settings::{SecretError, SecretStore};
use security_framework::passwords::{delete_generic_password, get_generic_password, set_generic_password};

const NOT_FOUND: i32 = -25300; // errSecItemNotFound

pub struct KeychainSecrets { service: String }
impl KeychainSecrets { pub fn new(service: &str) -> Self { Self { service: service.into() } } }

impl SecretStore for KeychainSecrets {
    fn get(&self, key: &str) -> Result<Option<String>, SecretError> {
        match get_generic_password(&self.service, key) {
            Ok(b) => String::from_utf8(b).map(Some).map_err(|_| SecretError("stored value is not UTF-8".into())),
            Err(e) if e.code() == NOT_FOUND => Ok(None),
            Err(e) => Err(SecretError(e.to_string())),
        }
    }
    fn set(&self, key: &str, value: &str) -> Result<(), SecretError> {
        set_generic_password(&self.service, key, value.as_bytes()).map_err(|e| SecretError(e.to_string()))
    }
    fn delete(&self, key: &str) -> Result<(), SecretError> {
        match delete_generic_password(&self.service, key) {
            Ok(()) => Ok(()),
            Err(e) if e.code() == NOT_FOUND => Ok(()),
            Err(e) => Err(SecretError(e.to_string())),
        }
    }
}
```

```rust
    match color {

        TrayColor::Blue => [66, 133, 244, 255],
        TrayColor::Green => [52, 168, 83, 255],

pub fn summary_icon(color: TrayColor) -> Vec<u8> {
    let c = rgba(color);
    let (mid, r) = (SIZE as f32 / 2.0, SIZE as f32 * 0.32);
    let mut out = Vec::with_capacity((SIZE * SIZE * 4) as usize);
    for y in 0..SIZE {
        for x in 0..SIZE {

            out.extend_from_slice(if dx * dx + dy * dy <= r * r { &c } else { &[0, 0, 0, 0] });
        }
```

**Keyboard rules** (spec §8, D9 and D10):

- **Guards first** (finding 8). If `composing`, or `keyCode === 229`, or
  `meta`, `ctrl` or `alt` is held, the effect is `none` and the browser
  keeps the event. This applies to every key, Escape and Enter included.
- **`Escape`** gives `escape`. It is a single effect. Panel then runs:

  ```ts
  if (await api.escape()) return;           // a countdown was cancelled in Rust
  if (st.replyFor) { st.replyFor = null; return; }
  await api.hide();
  ```

  The decision never reads `view.actions`, which may be stale
  (finding 5).
- **In the reply field (`inField`):** `Enter` without Shift gives
  `submitReply`. Anything else gives `none`.
- **`j` / `ArrowDown` and `k` / `ArrowUp`:** move and clamp. With no
  selection, select the first card.
- **`1`–`9`:** on the selected `answerable` card, option `n` of
  `agent.pending.options` in display order. It gives `pick` only when
  that option id is in `selectable_options`.
- **`r`:** `openReply` when `can_reply`. **`e`:** `markSeen` when
  `can_mark_seen`.
- **`Enter` outside a field:** `none`. Letters match
  case-insensitively.

```rust
/// Simulates an acd restart on the same port and key: every TLS session is
/// cut (kill switch, no token rotation), the listener goes away, and a fresh
/// Core (new epoch) with the same token and key takes the port after `delay`.
pub async fn restart_after(d: &mut Daemon, delay: Duration) {
    d.kill.kill();
    d.task.abort();
    let _ = (&mut d.task).await;
    tokio::time::sleep(delay).await;
    let tcp = tokio::net::TcpListener::bind(("127.0.0.1", d.port)).await.unwrap();
    let files = tls::KeyFiles { key_pem: d.files.key_pem.clone(), cert_pem: d.files.cert_pem.clone() };
    *d = serve_on(tcp, d.port, FakeAdapter::new(), files).await;
}
pub async fn restart(d: &mut Daemon) { restart_after(d, Duration::ZERO).await }
```
