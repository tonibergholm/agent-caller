# P5: Mac app implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the agent-caller Mac app: a Tauri v2 menu bar app with a
status icon, a non-activating floating panel opened by ⌥Space, keyboard
control, a 2-second undo, notifications and machine settings. It talks
acd/1 to one daemon per machine, the local one over `acd.sock` and remote
ones over Tailscale.

**Architecture:** All logic that can run without a window lives in a new
workspace crate, `crates/acd-client`. It holds the acd/1 connection,
resume and resync, the command and retry rules, the undo countdown, card
ordering and the view model. Linux and macOS CI both test it. The Tauri
app in `app/` is a thin shell. `app/src-tauri` is a separate Cargo
workspace that owns the windows, tray, hotkey, notifications and
Keychain, and forwards a ready-made `InboxView` to a small Svelte
frontend. Tokens stay in the Rust backend. Before the client is frozen,
Tasks 2 and 3 change the acd/1 handshake so that a client never sends its
token to a server that has not proved it holds the same token (decision
D1).

**Tech Stack:** Rust (edition 2024), tokio, tokio-tungstenite, serde,
ts-rs (TypeScript bindings), hmac and sha2 (handshake), Tauri 2.12 with
tauri-nspanel, global-shortcut and notification plugins, security-framework
(Keychain), Svelte 5, Vite 8, TypeScript 6.0, Vitest 5 with jsdom and
@testing-library/svelte.

**Spec:** `docs/superpowers/specs/2026-10-07-agent-inbox-design.md`, mainly
§5 (data model), §7 (acd/1), §8 (Mac app), §9, §10, §12, §13 and §14
acceptance items 1, 4, 5, 6, 7 and 8. The wire contract is
`crates/acd-protocol` (`model.rs`, `messages.rs`, `PROTOCOL.md`,
`schema/`, `examples/`). Follow-ups this plan must close:
`docs/superpowers/plans/2026-10-07-p1-followups.md`, section "P5: Mac
app".

## Decisions

Each decision states what was chosen, why, and what it costs. D1 changes
merged P1 code and the published protocol, so it needs an independent
review before Tasks 2 and 3 run.

### D1. The server proves it holds the token before the client reveals anything (needs independent review)

**Problem** (P1 follow-up). Today a client sends `hello {token}` as its
first frame. Whatever process holds the TCP port receives the token.

- The spec already treats a port squatter as a threat. That is why
  `acd status` uses `acd.sock`.
- Concrete windows where a squatter can hold the port:
  - acd exits with code 75 when Tailscale addresses change, and is
    restarted by its supervisor;
  - acd has crashed or is not yet running;
  - on a shared Linux box, another local user binds the Tailscale address
    first.
- The Tailscale range check in spec §7.1 is not authentication.
  `100.64.0.0/10` is also carrier-grade NAT space, and the check says
  nothing about which process on the node answers.
- With the token, an attacker can approve permission prompts. That is
  code execution as the user.

**Decision.** Replace the token in `hello` with a mutual nonce and HMAC
handshake. The server speaks second but proves first:

```text
client → hello     {protocol: "acd/1", client: {id, name, version}, nonce: Nc, resume?}
server → challenge {nonce: Ns, proof: Ps}
client → auth      {proof: Pc}
server → welcome … (unchanged from here on)

Nc, Ns = 32 random bytes, base64url without padding (43 characters)
Ps = b64url(HMAC-SHA256(key = token, "acd/1 server-proof\0" Nc "\0" Ns "\0" client.id))
Pc = b64url(HMAC-SHA256(key = token, "acd/1 client-proof\0" Nc "\0" Ns "\0" client.id))
```

- The client checks `Ps` in constant time. On a mismatch it closes the
  connection without sending `auth`, and shows the `auth_failed`
  message from D11.
- The server checks `Pc` in constant time against its current token. On a
  mismatch it sends `error {code: "unauthorized"}` and closes with 4401,
  as today.
- `hello`, `challenge` and `auth` must all complete within the existing
  5 s `hello` timeout.
- The token never crosses the wire, on TCP or on `acd.sock`. A squatter
  learns only an HMAC over two random nonces, which it cannot replay,
  because the next connection uses fresh nonces.
- The labels differ between server and client proofs, so a proof cannot
  be reflected.
- The protocol name stays `acd/1`. acd/1 has not been released and its
  only clients are `acd status` and the tests, so this is a breaking edit
  of an unreleased draft, recorded in PROTOCOL.md.

**Relay case.** There is no channel binding, because there is no TLS. A
process that sits between the app and the real acd could relay the
handshake and then read and inject frames. That needs:

- a position on the path. On Tailscale that means being on the server
  node, because WireGuard authenticates the peer node;
- the real acd being reachable on a different address or port at the same
  time.

A squatter on the port cannot also have the real acd listening on that
port. Reaching acd through `acd.sock` needs the user's own uid. This
leaves only a same-node attacker who controls a second listener that the
user configured by mistake. That is accepted for v1.

**Cost.**

- Protocol:
  - three message shapes change or are added (`hello`, `challenge`,
    `auth`);
  - schemas, golden examples and PROTOCOL.md §1 and §3;
  - spec §7.1 and §7.3.
- acd-core: `server.rs` `session()` (the pre-auth flow) and
  `Auth::check`.
- `acd status` (`crates/acd/src/status.rs`).
- Test helpers in `crates/acd-core/tests/server.rs` and
  `crates/acd-adapters/tests/herdr_e2e.rs`.
- New dependencies: `hmac` 0.13.0. It shares `digest` 0.11 with the
  existing `sha2` 0.11.
- Every client needs a few dozen more lines.
- One extra round trip per connect.

**Alternatives rejected.**

- **TLS with a pinned certificate per daemon.** It adds rustls, a cert
  lifecycle, a fingerprint for the user to copy next to the token, and a
  second secret to rotate. Tailscale already encrypts, so TLS would buy
  only server authentication, which D1 gets without certificates.
- **Pinning the Tailscale node through LocalAPI `whois`.** It does not
  stop a different user on the same node, and it makes the app depend on
  the Tailscale LocalAPI.
- **Accept and document.** The exit-75 restart window makes the risk
  routine rather than exotic.

**If D1 is rejected:** skip Tasks 2 and 3. In Task 6, the handshake sends
`hello {token}` as today. The rest of the plan does not change.

### D2. Local machine: `acd.sock` for transport, `client.token` for the credential, read on every connect

- The app adds a `Local` machine entry on first run (spec §8).
- It connects over `<config_dir>/acd.sock`, where `config_dir` is
  `$ACD_CONFIG_DIR` or `~/.config/acd`. An app launched from Finder has no
  `ACD_CONFIG_DIR`, so in practice it is `~/.config/acd`. The app must not
  be sandboxed. v1 builds locally with no App Store, so it is not.
- On every connect it reads `client.token` and refuses it unless all of
  these hold:
  - the file is a regular file, not a symlink;
  - its owner is the current effective uid;
  - its mode has no group or other bits;
  - the directory is owned by the uid and has no group or other bits;
  - the content is a well-formed token (43 base64url characters).
- The local token is never copied into the Keychain. A copy would go
  stale after `acd token rotate client`, and the file already has the
  right protection.
- After a 4401 close on the local machine, the app re-reads the file and
  reconnects with backoff.

### D3. Build split and CI

- `crates/acd-client` joins the workspace through `members = ["crates/*"]`.
  It has no Tauri dependency, so Linux CI builds and tests it.
- `app/src-tauri` has its own `[workspace]` table. It is listed under
  `exclude` in the root `Cargo.toml` and has its own committed
  `Cargo.lock`. It pins versions directly, because `workspace = true`
  does not reach across workspaces.
- The reason for the split: tauri needs GTK and WebKit dev packages to
  build on Linux. `tauri-nspanel` pulls `objc2-app-kit`, which builds only
  on macOS. And `tauri::generate_context!` fails to compile unless
  `frontendDist` (`app/dist`) and `icons/icon.png` exist (verified in
  `tauri-codegen` 2.7.1, `context.rs`).
- CI gains a job `app` on `macos-latest`. It installs Node 24 and runs
  `npm ci` and `npm run verify` in `app/`. That script runs svelte-check,
  vitest, the Vite build, app clippy `-D warnings`, and app tests.
- The existing `test` job (ubuntu and macOS) is unchanged. It covers
  `acd-client`, including the bindings drift test.

### D4. Frontend: Svelte 5 with Vite and TypeScript

- The UI is one list of cards, a reply field, a countdown and a settings
  form. Svelte compiles to small DOM code with no runtime framework. Its
  runes give reactive state without a store library. Tests use Vitest
  and @testing-library/svelte.
- Rejected:
  - React, for its runtime size and the hooks boilerplate for timers.
  - Preact, which would also do. It is a wash on size; Svelte's
    templates are shorter for this UI.
  - Vanilla TS, which would need hand-written DOM diffing for cards
    that update every few seconds.
- The package manager is npm, which ships with Node, with a committed
  `package-lock.json`.
- Svelte text interpolation escapes everything. `{@html}` is forbidden
  (see Global Constraints), because `raw_screen`, `detail` and titles come
  from terminals that an attacker can influence.

### D5. TypeScript bindings: ts-rs 12

- ts-rs 12.0.1 is stable. specta 2 is still a release candidate
  (2.0.0-rc.25).
- It is an optional feature, `ts`, on `acd-protocol` and on
  `acd-client`. Only the model types (`model.rs`) and the app view types
  derive `TS`. The frontend never sees wire messages.
- Generated files are committed under `app/src/lib/bindings/`. A drift
  test fails when they are stale; `UPDATE_BINDINGS=1` rewrites them. This
  mirrors `UPDATE_SCHEMA`.
- `u64` is exported as `number`, through `Config::with_large_int("number")`.
  acd/1 keeps integers within ±2^53.
- Timestamps use `#[ts(type = "string")]`, which ts-rs requires next to
  `serde(with)`.
- The `no-serde-warnings` feature silences ts-rs's printed note about
  `#[serde(other)]`.

### D6. The acd/1 client lives in the Rust backend

- The webview never holds a token. It receives `InboxView`, which has no
  secrets, and calls narrow commands such as `pick_option`.
- There is one exception: a token typed into the settings form passes
  through the webview once, inside the `save_machine` argument. The
  backend writes it to the Keychain and never returns it. `list_machines`
  reports only `has_token`.
- The Tauri capability grants the windows `core:event:default` and
  nothing else. There is no fs, shell or http plugin.
- The CSP is strict: `default-src 'self'`.

### D7. Keychain through security-framework 3.7.0

- The app is macOS-only. `security_framework::passwords::{set,get,delete}_generic_password`
  is a small, stable API (checked in the 3.7.0 source).
- keyring 4 was restructured around `keyring-core`, with every platform
  store optional. Its API was not verified, so it is not used.
- The service is `dev.agentcaller.inbox` and the account is the machine
  entry key.
- The store sits behind the `SecretStore` trait in `acd-client`, with
  `MemorySecrets` for tests.
- Unsigned local builds can trigger a Keychain access prompt after each
  rebuild, because the item ACL is tied to the code signature. This is
  checked manually.

### D8. Undo, ordering, tray state and feedback text are Rust, in `acd-client`

- The 2-second countdown runs on tokio. Tests use the paused clock. A
  hidden WKWebView may throttle JavaScript timers; tokio is not
  throttled.
- The frontend shows `fires_at_ms` and calls `cancel_action`.
- Card ordering, the tray color and count, and every user-facing feedback
  string are computed in `acd-client::view`. That code is pure and tested
  on Linux.

### D9. Countdown policy

- One countdown per card. A second pick on a card whose countdown is
  running is ignored. Different cards may count down at the same time.
- `Esc` cancels the most recently started countdown. A click on a card's
  countdown bar cancels that one.
- Hiding the panel, by `Esc` with no countdown running or by clicking
  elsewhere, does not cancel a countdown.
- A countdown is cancelled, and nothing is sent, when any of these
  happens before it fires:
  - the request resolves;
  - the agent's pending request changes id;
  - the request goes to `answering`;
  - the option ids change (an in-place upgrade);
  - the option disappears;
  - the machine goes offline;
  - the app quits.

  The card then shows the matching notice.
- A reply countdown is cancelled when the agent disappears, `can_send`
  turns false, or the machine goes offline.

### D10. `⏎` submits the reply field only

Spec §8 says "⏎ confirms" without saying what. Options are picked with
`1`–`9` and already pass through the undo countdown, so `⏎` is never an
option shortcut. That avoids an accidental approval.

- In the reply field, `⏎` submits, which starts the countdown.
- `Shift+⏎` inserts a newline.
- Outside the reply field, `⏎` does nothing.

### D11. Liveness and reconnect

- When no frame has arrived for 15 s, the client sends `ping`. If no
  frame arrives within 10 s after that, it drops the connection and
  reconnects. This covers Tailscale paths that go silent across sleep.
- Backoff runs 1, 2, 4, 8, 16, 30, 30 … seconds. It resets after a
  session reaches a fully applied snapshot or replay.
- Close codes and handshake failures:

  | Event | Local machine | Remote machine |
  |---|---|---|
  | 4401, or the server's proof does not match (D1) | re-read `client.token` and reconnect with normal backoff; status `auth_failed` until it succeeds | status `auth_failed`; retry every 30 s; saving a new token retries at once |
  | 4400 or `unsupported_protocol` | stop, status `incompatible`, until the user retries | same |
  | 4408 | reconnect at once, with resume | same |
  | any other close, I/O error or silence | status `offline` with `since`, backoff | same |

- With D1, a wrong token on the client also fails the server's proof,
  because the client verifies with its own token. A proof mismatch
  therefore means either a wrong or rotated token, or an impostor. The
  client never sends `auth` in either case. It keeps retrying slowly
  rather than stopping, because the impostor case can be a short-lived
  squatter during an acd restart. The `auth_failed` message says both:
  "This machine's acd did not accept the token, or could not prove it
  holds it. Check the token in Settings, or whether another process holds
  the port."

### D12. Notifications

- A notification is posted only for a `request.opened` event, live or
  replayed, and only while the panel is hidden. Never from a snapshot.
- Notifications are deduplicated by `(machine.id, request.id)` for the
  life of the app.
- The title is `<agent title> on <machine name>`. The body is the request
  `title`, for example the tool name, never `detail`. Notifications can
  show on the lock screen, and `detail` can hold commands with secrets.

### D13. Follow-up decisions

- **Sessions per token are uncapped, and the 16384-entry idempotency table
  is shared.** Accepted for v1, with no daemon change. A token holder can
  already approve prompts, so a token holder flooding the table is not in
  the threat model. The app opens one session per machine. It creates
  command ids only for user actions (`ping` reserves nothing). It shows
  the daemon's `bad_request` message (`too many recent commands; retry
  later`) as a notice.
- **`reason` on `request.resolved`** (stray keystroke, P3). P5 does not
  add it. serde ignores unknown fields, so a daemon that sends it does not
  break this client. When P3 adds the field, P3 also adds the mapping in
  `acd_client::view::resolution_notice`. "a stray keystroke may be in the
  input box" then replaces "Check the terminal". This is recorded in the
  follow-ups file (Task 15).

### D14. The same daemon added twice

If two machine entries report the same `welcome.machine.id` (for example
the auto-added local entry, and the same Mac added by its MagicDNS name):

- the later entry in settings order gets `duplicate_of`;
- its cards are hidden;
- notifications are already deduplicated by machine id (D12).

## Global Constraints

These apply to every task.

- **Workspace rules.**
  - Rust edition 2024 and `rust-version = "1.90"`.
  - Every task ends green on all of these:
    - `cargo test --workspace`;
    - `cargo clippy --workspace --all-targets -- -D warnings`;
    - from Task 11 on, `npm --prefix app run verify`. That one script runs
      `svelte-check --fail-on-warnings`, `vitest run`, `vite build`, then
      app clippy `-D warnings` and `cargo test` through
      `--manifest-path src-tauri/Cargo.toml`.
  - App cargo commands need `app/dist`, so always build the frontend
    first. `verify` does.
- **No secrets in the webview.**
  - No command returns a token.
  - No event payload contains a token.
  - Logs never contain tokens or proofs.
- **No `{@html}`** anywhere in `app/src`. Task 14 adds a test that fails
  if one appears. Render `raw_screen` in a `<pre>` as text.
- **Address vetting** (spec §7.1). A TCP endpoint may connect only to an
  IP in one of these ranges:
  - `100.64.0.0/10`;
  - `fd7a:115c:a1e0::/48`;
  - loopback (needed for the local fallback and tests).

  Resolve the name once, filter the addresses, and connect to a vetted
  `SocketAddr`. Never resolve a second time at connect.
- **Capabilities** (spec §7.5). Never send a command whose capability is
  missing from the current `welcome.capabilities`. The UI disables
  answering, `R` and `E` accordingly.
- **Answerable** (spec §5, §7.2). A card is answerable when all of these
  hold:
  - its machine is online;
  - `answer` is advertised;
  - `pending.is_answerable()`;
  - `pending.status == Open`.

  An option is selectable only if its `effect` is not `Unknown`. Picking
  an `allow_always` option shows its `description`, the exact rule,
  during the countdown (spec §6.2).
- **Unknown input** (spec §7.2).
  - Use `acd_protocol::decode_server`. Skip `Ok(None)`.
  - A decode error on any frame forces a full resync: drop the
    connection, clear the cursor, and reconnect without `resume`.
  - Unknown enum values decode to `Unknown` (Task 1). They map like
    this:
    - an unknown agent state is grouped as unknown;
    - an unknown kind, answer path or request status is read-only;
    - an unknown resolution gives "Check the terminal".
- **Sequencing** (spec §7.4).
  - The cursor is `(epoch, seq)` of the last applied snapshot or event.
  - An event is applied only when its epoch equals the cursor epoch and
    `seq == cursor.seq + 1`.
  - A `seq` at or below the cursor is a duplicate and is skipped.
  - Anything else forces a resync.
  - After a `welcome` in a new epoch, nothing applies until the
    snapshot.
- **Commands** (spec §7.3, §7.4, §8).
  - Every command id is a fresh UUID v4.
  - If the connection drops before the result arrives and the session
    reconnects into the **same** epoch, resend the identical id and
    payload.
  - If it reconnects into a **new** epoch, the command becomes
    `uncertain` and is never resent.
  - `request_not_ready` is retried with the same id every 250 ms until
    3 s after the first send. Then it fails with the not-ready notice.
- **Undo.**
  - 2 s from the pick or the reply submit to the send.
  - `Esc` or a click on the bar cancels.
  - Nothing is sent when the machine is offline at fire time (spec §12).
  - D9 lists the other cancel triggers.
- **Feedback strings** (exact text; `view::notice_for_*` owns them):

  | Condition | Text | Tone |
  |---|---|---|
  | `request_gone`; the request resolved, changed id or went `answering` during the countdown | `Answered elsewhere` | info |
  | the option ids changed during the countdown | `The request changed. Nothing was sent.` | warning |
  | resolved `by: terminal` | `Answered in the terminal` | info |
  | resolved `by: uncertain`, `lost` or unknown; command `uncertain`; new epoch with a command in flight | `Check the terminal` | warning |
  | `request_not_ready` after 3 s | `Not ready yet. Enlarge the pane to answer here.` | warning |
  | `screen_mismatch` | `The terminal shows a different dialog. Nothing was sent.` | warning |
  | `request_busy` | `Another answer is in progress` | info |
  | `not_answerable` | `Answer in terminal` | info |
  | `agent_gone` | `The agent is gone` | info |
  | `agent_busy` | `The agent is busy. Try again when it is idle.` | warning |
  | `source_unavailable` | `The source is unavailable. Nothing was sent.` | warning |
  | `not_supported` | `Not supported for this agent` | info |
  | machine offline at fire time, or offline during the countdown | `Offline. Nothing was sent.` | warning |
  | any other error code | `Could not send: <server message>` | warning |

  Notices last 10 s. While a command of ours is in flight, or the request
  is `answering`, the card shows a spinner (`busy: true`).
- **Ids.**
  - A card key is `<machine entry key>/<agent id>`.
  - Agent ids contain colons, so a card key is split only at the
    **first** `/`. Machine entry keys are UUIDs or `local`, so they never
    contain `/`.
- **Timing constants** live in `acd_client::Timing`, and tests shrink
  them:
  - connect: 3 s;
  - handshake: 5 s;
  - idle ping: 15 s;
  - ping timeout: 10 s;
  - undo: 2 s;
  - not-ready window: 3 s;
  - not-ready interval: 250 ms;
  - notice lifetime: 10 s;
  - stale in-flight limit: 14 min (the daemon keeps results for 15).
- **CI trigger.** Push and PR events do not start Actions in this repo
  yet. After pushing, run `gh workflow run CI --ref <branch>` and watch
  both jobs.
- **Parallel plans.** P3 and P4 may run at the same time. Tasks 1–3 edit
  `acd-protocol`, `acd-core/src/server.rs`, `acd-core/src/registry.rs`
  (one match arm) and the acd/1 test helpers. Land Tasks 1–3 as their own
  PR, after the D1 review, before P3 or P4 touch those files.

## Review Focus

These are the inputs most likely to hurt a real user that no single task's
happy path covers. Each has a pinned test in the task named.

1. **The answer goes out after the user already lost the race.** The
   request resolves, is superseded, or is upgraded in place while the
   countdown runs. Expected: nothing is sent, and the notice says
   `Answered elsewhere`. Tests: Task 10
   (`countdown_cancels_when_request_resolves`,
   `countdown_cancels_when_options_change`).
2. **The connection drops between send and result.**
   - In the same epoch, the answer is delivered exactly once.
   - In a new epoch, it is shown as `Check the terminal` and never

```rust
//! JSON Schema generators. The committed files in `schema/` are exactly
//! `to_string_pretty` of these values.
use serde_json::{json, Value};

use crate::{ClientMessage, ServerMessage};

/// Adds `rule` to the `allOf` of the tagged-enum variant whose `type` is `name`.
fn add_rule(schema: &mut Value, name: &str, rule: Value) {
    let variants = schema["oneOf"].as_array_mut().expect("tagged enums render as oneOf");
    let v = variants
        .iter_mut()
        .find(|v| v["properties"]["type"]["const"] == name)
        .unwrap_or_else(|| panic!("no variant {name}"));
    let all = v.as_object_mut().expect("variant is an object").entry("allOf").or_insert_with(|| json!([]));
    all.as_array_mut().expect("allOf is an array").push(rule);
}

pub fn client_schema() -> Value {
    let mut s = serde_json::to_value(schemars::schema_for!(ClientMessage)).expect("schema");
    // request.answer carries exactly one of option_id or text (spec §7.3).
    add_rule(&mut s, "request.answer", json!({"oneOf": [
        {"required": ["option_id"], "not": {"required": ["text"]}},
        {"required": ["text"], "not": {"required": ["option_id"]}}
    ]}));
    s
}

pub fn server_schema() -> Value {
    let mut s = serde_json::to_value(schemars::schema_for!(ServerMessage)).expect("schema");
    // result: ok=true never has error; ok=false has error and no outcome.
    add_rule(&mut s, "result", json!({"oneOf": [
        {"properties": {"ok": {"const": true}}, "not": {"required": ["error"]}},
        {"properties": {"ok": {"const": false}}, "required": ["error"], "not": {"required": ["outcome"]}}
    ]}));
    s
}
```

```rust
//! The acd/1 handshake (PROTOCOL.md §1, "Authentication"). The token never
//! crosses the wire: each side proves knowledge of it with an HMAC over two
//! fresh nonces, the server first.
use base64::engine::general_purpose::URL_SAFE_NO_PAD;
use base64::Engine;
use hmac::{Hmac, KeyInit, Mac};
use sha2::Sha256;
use subtle::ConstantTimeEq;

pub const NONCE_LEN: usize = 43;
const SERVER_LABEL: &[u8] = b"acd/1 server-proof";
const CLIENT_LABEL: &[u8] = b"acd/1 client-proof";

pub fn new_nonce() -> String {
    let mut bytes = [0u8; 32];
    getrandom::fill(&mut bytes).expect("OS randomness is available");
    URL_SAFE_NO_PAD.encode(bytes)
}

pub fn valid_nonce(s: &str) -> bool {
    s.len() == NONCE_LEN && URL_SAFE_NO_PAD.decode(s).is_ok_and(|b| b.len() == 32)
}

fn proof(label: &[u8], token: &str, client_nonce: &str, server_nonce: &str, client_id: &str) -> String {
    let mut mac = Hmac::<Sha256>::new_from_slice(token.as_bytes()).expect("HMAC takes any key length");
    for (i, part) in [label, client_nonce.as_bytes(), server_nonce.as_bytes(), client_id.as_bytes()].iter().enumerate() {
        if i > 0 { mac.update(b"\0"); }
        mac.update(part);
    }
    URL_SAFE_NO_PAD.encode(mac.finalize().into_bytes())
}

pub fn server_proof(token: &str, client_nonce: &str, server_nonce: &str, client_id: &str) -> String {
    proof(SERVER_LABEL, token, client_nonce, server_nonce, client_id)
}

pub fn client_proof(token: &str, client_nonce: &str, server_nonce: &str, client_id: &str) -> String {
    proof(CLIENT_LABEL, token, client_nonce, server_nonce, client_id)
}

pub fn proofs_equal(a: &str, b: &str) -> bool {
    a.len() == b.len() && bool::from(a.as_bytes().ct_eq(b.as_bytes()))
}
```

```rust
//! Where a machine's acd lives, and the Tailscale address rule (spec §7.1).
//! The range check is not authentication (100.64/10 is also CGNAT space);
//! the D1 handshake authenticates the server.
use std::net::{IpAddr, SocketAddr};
use std::path::PathBuf;

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Endpoint {
    Local { config_dir: PathBuf },
    Tcp { host: String, port: u16 },
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum EndpointError {
    #[error("cannot resolve {0}")]
    Resolve(String),
    #[error("{host} resolves to {addrs:?}; none is a Tailscale or loopback address")]
    NotTailscale { host: String, addrs: Vec<IpAddr> },
}

pub fn allowed_ip(ip: IpAddr) -> bool {
    match ip {
        IpAddr::V4(v4) => v4.is_loopback() || (v4.octets()[0] == 100 && v4.octets()[1] & 0xC0 == 0x40),
        IpAddr::V6(v6) => match v6.to_ipv4_mapped() {
            Some(v4) => allowed_ip(IpAddr::V4(v4)),
            None => v6.is_loopback() || v6.segments()[..3] == [0xfd7a, 0x115c, 0xa1e0],
        },
    }
}

/// Resolves once and keeps only allowed addresses. Callers connect to the
/// returned addresses and never resolve the name again.
pub async fn vet(host: &str, port: u16) -> Result<Vec<SocketAddr>, EndpointError> {
    let all: Vec<SocketAddr> = tokio::net::lookup_host((host, port))
        .await
        .map_err(|_| EndpointError::Resolve(host.to_string()))?
        .collect();
    let ok: Vec<SocketAddr> = all.iter().copied().filter(|a| allowed_ip(a.ip())).collect();
    if ok.is_empty() {
        return Err(EndpointError::NotTailscale { host: host.to_string(), addrs: all.iter().map(|a| a.ip()).collect() });
    }
    Ok(ok)
}
```

```rust
fn check(path: &Path, want_dir: bool, max_mode: u32) -> Result<(), LocalError> {
    let md = match fs::symlink_metadata(path) {
        Ok(m) => m,
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => return Err(LocalError::Missing(path.into())),
        Err(e) => return Err(LocalError::Io(path.into(), e)),
    };
    if md.file_type().is_symlink() { return Err(LocalError::Symlink(path.into())); }
    if md.is_dir() != want_dir { return Err(LocalError::Malformed(path.into())); }
    if md.uid() != euid() { return Err(LocalError::Owner(path.into())); }
    let mode = md.permissions().mode() & 0o777;
    if mode & !max_mode != 0 { return Err(LocalError::Mode { path: path.into(), mode, want: max_mode }); }
    Ok(())
}

pub fn read_local_token(dir: &Path) -> Result<String, LocalError> {
    check(dir, true, 0o700)?;
    let path = dir.join("client.token");
    check(&path, false, 0o600)?;
    let raw = fs::read_to_string(&path).map_err(|e| LocalError::Io(path.clone(), e))?;
    let token = raw.trim();
    if !crate::settings::valid_token(token) { return Err(LocalError::Malformed(path)); }
```

```rust
                s.save(path)?;

        f.sync_all().map_err(io)?;
        fs::rename(&tmp, path).map_err(io)
    }
```

```rust
//! One connection's model of a daemon (spec §7.4). Pure: no I/O, no clock.
use std::collections::BTreeMap;

use acd_protocol::{Agent, Cursor, Machine, Request, ResolvedBy, ServerMessage};

#[derive(Clone, Debug, Default)]
pub struct Session {
    pub machine: Option<Machine>,
    pub capabilities: Vec<String>,
    pub agents: BTreeMap<String, Agent>,
    cursor: Option<Cursor>,
    known_epoch: Option<String>,
    welcome_epoch: Option<String>,
    awaiting_snapshot: bool,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum EpochChange { First, Same, New }

#[derive(Clone, Debug, PartialEq)]
pub enum Applied {
    Ignored,
    Changed,
    Opened(Request),
    Resolved { request_id: String, agent_id: String, by: ResolvedBy, option_id: Option<String> },
    Resync(&'static str),
}

fn event_pos(msg: &ServerMessage) -> Option<(&str, u64)> {
    match msg {
        ServerMessage::AgentUpdated { epoch, seq, .. }
        | ServerMessage::AgentRemoved { epoch, seq, .. }
        | ServerMessage::RequestOpened { epoch, seq, .. }
        | ServerMessage::RequestResolved { epoch, seq, .. }
        | ServerMessage::MachineUpdated { epoch, seq, .. } => Some((epoch, *seq)),
        _ => None,
    }
}

impl Session {
    pub fn cursor(&self) -> Option<&Cursor> { self.cursor.as_ref() }
    pub fn resume(&self) -> Option<Cursor> { self.cursor.clone() }
    pub fn has(&self, capability: &str) -> bool { self.capabilities.iter().any(|c| c == capability) }
    pub fn synced(&self) -> bool { self.cursor.is_some() && !self.awaiting_snapshot }

    pub fn welcome(&mut self, machine: Machine, capabilities: Vec<String>, epoch: &str) -> EpochChange {
        let change = match self.known_epoch.as_deref() {
            None => EpochChange::First,
            Some(e) if e == epoch => EpochChange::Same,
            Some(_) => EpochChange::New,
        };
        self.machine = Some(machine);
        self.capabilities = capabilities;
        self.known_epoch = Some(epoch.to_string());
        self.welcome_epoch = Some(epoch.to_string());
        if self.cursor.as_ref().is_some_and(|c| c.epoch != epoch) { self.cursor = None; }
        self.awaiting_snapshot = self.cursor.is_none();
        change
    }

    pub fn force_resync(&mut self) {
        self.cursor = None;
        self.awaiting_snapshot = true;
    }

    pub fn apply(&mut self, msg: &ServerMessage) -> Applied {
        if let ServerMessage::Snapshot { epoch, seq, agents } = msg {
            if self.welcome_epoch.as_deref() != Some(epoch.as_str()) { return Applied::Resync("snapshot from another epoch"); }
            self.agents = agents.iter().map(|a| (a.id.clone(), a.clone())).collect();
            self.cursor = Some(Cursor { epoch: epoch.clone(), seq: *seq });
            self.awaiting_snapshot = false;
            return Applied::Changed;
        }
        let Some((epoch, seq)) = event_pos(msg) else { return Applied::Ignored };
        if self.awaiting_snapshot { return Applied::Resync("event before snapshot"); }
        let Some(cursor) = self.cursor.as_mut() else { return Applied::Resync("event before snapshot") };
        if cursor.epoch != epoch { return Applied::Resync("event from another epoch"); }
        if seq <= cursor.seq { return Applied::Ignored; }
        if seq != cursor.seq + 1 { return Applied::Resync("sequence gap"); }
        cursor.seq = seq;
        match msg {
            ServerMessage::AgentUpdated { agent, .. } => { self.agents.insert(agent.id.clone(), agent.clone()); Applied::Changed }
            ServerMessage::AgentRemoved { agent_id, .. } => { self.agents.remove(agent_id); Applied::Changed }
            ServerMessage::MachineUpdated { machine, .. } => { self.machine = Some(machine.clone()); Applied::Changed }
            ServerMessage::RequestOpened { request, .. } => Applied::Opened(request.clone()),
            ServerMessage::RequestResolved { request_id, agent_id, by, option_id, .. } => Applied::Resolved {
                request_id: request_id.clone(), agent_id: agent_id.clone(), by: *by, option_id: option_id.clone(),
            },
            _ => Applied::Ignored,
        }
    }
}
```

```rust
//! One task per machine: connect, handshake (D1), mirror the session,
//! keep it alive, reconnect with backoff (D11).
use std::path::PathBuf;
use std::time::{Duration, SystemTime, UNIX_EPOCH};

use acd_protocol::{auth, decode_server, ClientInfo, ClientMessage, Cursor, ErrorCode, Machine, ResolvedBy, Request, ServerMessage, PROTOCOL};
use futures_util::{SinkExt, StreamExt};
use serde::Serialize;
use tokio::io::{AsyncRead, AsyncWrite};
use tokio::sync::{broadcast, mpsc, watch};
use tokio::time::Instant;
use tokio_tungstenite::tungstenite::protocol::frame::coding::CloseCode;
use tokio_tungstenite::tungstenite::Message;
use tokio_tungstenite::{client_async, WebSocketStream};

use crate::backoff::Backoff;
use crate::endpoint::{vet, Endpoint};
use crate::local::{read_local_token, socket_path};
use crate::session::{Applied, EpochChange, Session};
use crate::Timing;

trait Io: AsyncRead + AsyncWrite + Unpin + Send {}
impl<T: AsyncRead + AsyncWrite + Unpin + Send> Io for T {}
type Ws = WebSocketStream<Box<dyn Io>>;

pub fn now_ms() -> f64 {
    SystemTime::now().duration_since(UNIX_EPOCH).map(|d| d.as_millis() as f64).unwrap_or(0.0)
}

/// How a connection attempt or a live session ended.
enum End {
    Offline(String),                // I/O error, close, silence, timeout: backoff
    Resync(&'static str),           // decode error or seq rule: clear cursor, backoff
    TooSlow,                        // 4408: reconnect at once
    AuthFailed,                     // 4401 or proof mismatch (D11)
    Incompatible(String),           // 4400 / unsupported_protocol: wait for retry_now
    Local(String),                  // local token unreadable: backoff
}
```

**`open(cfg) -> Result<(Ws, String), End>`.** It returns the WebSocket
and the token to prove.

- The token comes from `Credential::Token(t)` as is, or from
  `read_local_token(dir)` for `LocalFile`. A `LocalError` gives
  `End::Local(e.to_string())`.
- For `Endpoint::Local`, connect `UnixStream` to `socket_path(dir)` with
  the URL `ws://localhost/`.
- For `Endpoint::Tcp`:
  - call `vet(host, port)`; an error gives `End::Offline(e.to_string())`;
  - try each vetted `SocketAddr` with `TcpStream::connect` inside
    `timing.connect`;
  - the URL is `ws://{host}:{port}/`. Bracket IPv6 literals.
- Then call `client_async(url, Box::new(stream) as Box<dyn Io>)`,
  wrapped in `timing.connect`.

**`handshake(ws, token, client, resume, within) -> Result<(Machine, Vec<String>, String), End>`.**
Use one deadline, `Instant::now() + within`.

1. `let cn = auth::new_nonce()`. Send `ClientMessage::Hello { protocol: PROTOCOL.into(), client: client.clone(), nonce: cn.clone(), resume }`.
2. Read frames until the deadline, skipping non-text frames and unknown
   types.
   - `Challenge { nonce: sn, proof }`: if
     `!auth::proofs_equal(&proof, &auth::server_proof(token, &cn, &sn, &client.id))`,
     close the socket **without sending anything else**, and return
     `End::AuthFailed`.
   - `Error { code: UnsupportedProtocol, .. }`: return `End::Incompatible`.
   - `Error { code: Unauthorized, .. }`: return `End::AuthFailed`.
   - `Error { code, message, .. }`: return `End::Offline(message)`.
   - A close frame with 4400 is `Incompatible`, 4401 is `AuthFailed`,
     and anything else is `Offline`.
3. Send `ClientMessage::Auth { proof: auth::client_proof(token, &cn, &sn, &client.id) }`.
4. Read until `Welcome { machine, capabilities, epoch, .. }`, with the
   same error mapping, and return it.

A timeout is `End::Offline("handshake timed out")`.

**`run(cfg, ctl_rx, state_tx, events_tx)`.** The task body:

```text
session = Session::default(); backoff = Backoff::new(base, max); offline_since = None
loop:
  publish(Connecting) unless the current status is AuthFailed/Incompatible/LocalUnavailable (keep showing those while retrying)
  end = match open(cfg) { Err(e) => e, Ok((ws, token)) => match handshake(...session.resume()...) {
          Err(e) => e,
          Ok((machine, caps, epoch)) => {
              change = session.welcome(machine, caps, &epoch); events.send(Welcomed(change));
              offline_since = None; publish(Online)
              serve(ws, &mut session, &mut backoff, ...).await     // returns End
          } } }
  delay = match end:
     Offline(err)       => { offline_since.get_or_insert(now_ms()); publish(Offline{since_ms, error: err}); backoff.next_delay() }
     Resync(why)        => { session.force_resync(); tracing::warn!(why); backoff.next_delay() }
     TooSlow            => Duration::ZERO
     AuthFailed if Local endpoint => { publish(AuthFailed{message: AUTH_MSG}); backoff.next_delay() }
     AuthFailed         => { publish(AuthFailed{message: AUTH_MSG}); timing.auth_retry }
     Local(msg)         => { publish(LocalUnavailable{message: msg}); backoff.next_delay() }
     Incompatible(msg)  => { publish(Incompatible{message: msg}); wait_for_retry_now(); continue }
  wait `delay`, but return early on RetryNow; DropConnection while waiting is a no-op
```

`AUTH_MSG` is the D11 sentence. `publish` sends a new `MachineState`
with a clone of `session`. Use `watch::Sender::send_replace`. While a
machine is not `Online`, the session keeps its last agents; the view
greys them.

**`serve(ws, session, backoff, ctl_rx, state_tx, events_tx, timing) -> End`.**
It runs `tokio::select!` over:

- **`ws.next()`.** Record `last_frame = Instant::now()` and clear any
  ping deadline. Text frames go through `decode_server`:
  - an `Err` gives `End::Resync("undecodable frame")`;
  - `Ok(None)` is skipped;
  - `Ok(Some(msg))` is matched:
    - `Pong` is ignored.
    - `Result` goes to Task 8; until then, ignore it.
    - `Error { message, .. }` is logged at warn level.
    - Anything else goes to `session.apply(&msg)`:
      - `Changed` publishes;
      - `Opened(r)` publishes and sends `MachineEvent::Opened(r)`;
      - `Resolved {..}` sends `MachineEvent::Resolved {..}` (agent
        changes arrive in their own `agent.updated`);
      - `Resync(why)` returns `End::Resync(why)`;
      - `Ignored` does nothing.

      After any apply, if `session.synced()` and the backoff was not yet
      reset for this connection, call `backoff.reset()`.

  Close frames: 4401 is `AuthFailed`, 4400 is `Incompatible`, 4408 is
  `TooSlow`, anything else is `Offline("closed")`. `None` or an error
  gives `Offline`.
- **The ping timer**, `sleep_until(last_frame + timing.idle_ping)` while
  no ping is outstanding. It sends
  `ClientMessage::Ping { id: Uuid::new_v4() }` and sets
  `ping_deadline = now + ping_timeout`. When `ping_deadline` passes with
  no frame, return `End::Offline("no reply to ping")`.
- **`ctl_rx.recv()`.** `DropConnection` returns
  `End::Offline("dropped by request")` after closing the socket.
  `RetryNow` is ignored while online.

A send error anywhere is `End::Offline`.

Spawn with `tokio::spawn`. `spawn_machine` must be called inside a tokio
runtime. Tauri's async runtime is tokio, and Task 12 calls it from
`tauri::async_runtime::spawn`.

```rust
    pub id: String,
    pub msg: ClientMessage,
    pub epoch: String,
    pub first_sent: Instant,

```

- **`begin(cmd, reply, epoch, now) -> ClientMessage`.** Build the
  message with `id = Uuid::new_v4().to_string()`. `Answer` becomes
  `RequestAnswer { option_id: Some, text: None }`, `Send` becomes
  `AgentSend`, and `MarkSeen` becomes `AgentMarkSeen`. Push an
  `Inflight` and return a clone of the message to send.
- **`on_result(r: &CommandResult, now, timing)`.** Find the item by id.
  An unknown id is ignored, for example the result of a command that was
  already completed.
  - `ok` with `outcome == Some(Delivered)` completes `Delivered`; `ok`
    without an outcome completes `Done`.
  - An error `request_not_ready` while
    `now + interval <= first_sent + window` sets
    `retry_at = Some(now + interval)` and keeps the item.
  - Any other error, or `request_not_ready` past the window, completes
    `Failed { code, message }`.
- **`due(now) -> Vec<ClientMessage>`.** Items whose `retry_at <= now`.
  Clear their `retry_at`, and return clones of their messages.
  `next_due() -> Option<Instant>` is the earliest `retry_at`.
- **`on_welcome(change, now, timing) -> Vec<ClientMessage>`.**
  - `New`: complete every item `Uncertain` and return nothing.
  - `Same` or `First`: complete as `Uncertain` every item older than
    `stale_inflight`. Return the messages of the rest that have no
    `retry_at`, to resend now. Items with a `retry_at` wait for it.
- **`fail_all_offline()`** is not needed. In-flight commands survive a
  disconnect, by design.

`conn.rs` changes:

- Add `Control::Submit { cmd: Command, reply: oneshot::Sender<Outcome> }`.
  `MachineHandle::submit` sends it and awaits the reply. A closed
  channel means the task has stopped, which is
  `Outcome::NotSent(NotSent::Offline)`.
- `Commands` lives in `run`, outside the per-connection loop, so it
  survives reconnects.
- Outside `serve` (connecting, backing off or stopped), reply
  `NotSent(Offline)` to every `Submit`. Drain `ctl_rx` while waiting, so
  that submits never hang.
- In `serve`:
  - a `Submit` whose capability is missing gets
    `NotSent(NotAdvertised)`;
  - otherwise call `begin` with the current epoch, then send;
  - `ServerMessage::Result(r)` calls `on_result`;
  - add a `select!` arm, `sleep_until(next_due)`, that resends `due()`.
- After each successful `handshake`, call `on_welcome(change, ..)` and
  send the returned messages, **after** `session.welcome` and before
  reading frames. Resent commands may get their results interleaved with
  the replay, which is fine.

  - `pending.is_some()` or `state == NeedsYou` gives `Request`;
  - `Done` gives `Done`, `Working` gives `Working`, `Idle` gives `Idle`;
  - `Unknown` gives `Unknown`.
- **Order:**
  - by group index (Request 0 … Idle 4);
  - in `Request`, by `pending.opened_at` ascending, falling back to
    `state_since` when there is no pending request;
  - in the other groups, by `state_since` descending;
  - ties go by `machine_name`, then `agent.id`.

  Compare timestamps as parsed `chrono` values. `acd-protocol` already
  depends on chrono, so `Agent` fields are `DateTime<Utc>`.
- **`live`:** `status == Online`.
  `offline_since_ms = Some(since_ms)` only for `Offline`.
- **`answerable`:** `live && session.has("answer") && pending.is_answerable() && pending.status == RequestStatus::Open`.
- **`selectable_options`:** the ids of `pending.options` whose `effect`
  is not `Effect::Unknown`. They are empty when the card is not
  answerable.
- **`can_reply`:** `live && has("send") && agent.can_send`.
  **`can_mark_seen`:** `live && has("mark_seen") && state == Done`.
- **`busy`:** `pending.status == Answering || busy.contains(key)`.
- **`notice`, `action`:** looked up by card key.
- **Machine status for display:**
  - `MachineInput.state == None` gives
    `AuthFailed { message: NOTICE_NO_TOKEN }` and no cards;
  - otherwise the state's status.
- **`machine_name`:** `entry.name`.
- **`machine_id`:** `session.machine.map(|m| m.id)`.
- **`is_local`:** `entry.endpoint == EndpointConfig::Local`.
- **Duplicates:** walk entries in settings order. The first entry to
  report a machine id owns it, and later ones get `duplicate_of` and
  contribute no cards.
- **Tray:** over all live cards, including hidden idle ones.
  - `needs_you` = the count of agents with `state == NeedsYou`.
  - The color is `Amber` if `needs_you > 0`, else `Blue` if any is
    `Working`, else `Green` if any is `Done`, else `Grey`.
- **Notice mapping** (exact strings, from the Global Constraints table):
  - `notice_for_outcome`:
    - `Failed { code, message }` maps through `notice_for_error`;
    - `Uncertain` is the warning `Check the terminal`;
    - `NotSent(Offline)` is the warning `Offline. Nothing was sent.`;
    - `NotSent(NotAdvertised)` is the info `Not supported for this agent`.
  - Tones follow the table.

```rust
struct Action {
    id: String,
    card_key: String,
    machine_key: String,
    agent_id: String,
    kind: ActionKind,
    view: ActionView,
}
enum ActionKind {
    Answer { request_id: String, option_id: String, option_ids: Vec<String> },
    Reply { text: String },
}
struct Machine { entry: MachineEntry, handle: Option<MachineHandle> }   // None: remote with no token
struct Inner {
    settings: Settings,
    machines: Vec<Machine>,
    actions: Vec<Action>,                       // start order
    busy: HashSet<String>,
    notices: HashMap<String, (Notice, Instant)>,
    notified: HashSet<(String, String)>,        // (machine id or entry key, request id)
}
pub struct Inbox {
    inner: Mutex<Inner>,
    secrets: Arc<dyn SecretStore>,
    opts: InboxOptions,
    view_tx: watch::Sender<InboxView>,
    events_tx: broadcast::Sender<InboxEvent>,
    wake: Notify,
}
```

Rules:

- **`start`.** For each entry, call `spawn_for(entry)`. Then spawn the
  view loop:

  ```text
  loop { rebuild(); select! { wake.notified(), sleep_until(earliest notice expiry or +1h) } }
  ```

- **`spawn_for(entry)`.**
  - `Local` gives `Endpoint::Local { config_dir }` with
    `Credential::LocalFile(config_dir)`. The directory is
    `local::default_config_dir()`. If it is `None`, there is no handle,
    and the view shows the no-token status.
  - `Tcp` takes the token from `secrets.get(key)`. Missing, there is no
    handle. Present, `Credential::Token`.
  - The client is
    `ClientInfo { id: settings.client_id, name: opts.client_name, version: opts.client_version }`.
  - Spawn two forwarding tasks:
    - state changes call `wake.notify_one()`;
    - events call `self.on_machine_event(&key, ev)`.

    Both hold a `Weak<Inbox>` and end when the receiver closes.
- **`rebuild`.** Lock. Then:
  1. Drop expired notices.
  2. For each action, run `check(action, state)`. An `Err(notice)`
     removes the action and sets the notice on its card.
  3. Call `build_view`.
  4. `view_tx.send_replace`.
- **`check(action, state) -> Result<(), Notice>`.** The checks run in
  this order. Each failure gives the notice shown after the arrow:
  - The handle is missing, or the status is not `Online` →
    `Offline. Nothing was sent.`
  - `Answer`, agent missing → `The agent is gone`.
  - `Answer`, `pending` is `None`, or its id differs from `request_id`,
    or its status is not `Open` → `Answered elsewhere`.
  - `Answer`, the pending option ids differ from `option_ids`, or
    `option_id` is gone →
    `The request changed. Nothing was sent.`
  - `Reply`, agent missing → `The agent is gone`.
  - `Reply`, `!agent.can_send` →
    `The agent is busy. Try again when it is idle.`
- **`pick`.** Validate against the current state with the same rules as
  the view (`answerable`, and `option_id` in `selectable_options`).
  Errors:
  - `UnknownCard`;
  - `NotAnswerable`;
  - `StaleRequest`, when `request_id` is not the current pending id;
  - `UnknownOption`;
  - `AlreadyCounting`, when an action already exists for the card.

  Then create the action:
  - `id = Uuid::new_v4()`;
  - `label` = the option's label;
  - `detail` = `option.description` when `effect == AllowAlways`, the
    exact rule (spec §6.2);
  - `fires_at_ms = now_ms() + undo`.

  Spawn
  `{ sleep(undo); if let Some(ib) = weak.upgrade() { ib.fire(id).await } }`,
  call `wake`, and return the id.
- **`reply`.** `text.trim().is_empty()` or `text.len() > 64 * 1024`
  gives `BadText`. The card must be `can_reply`, otherwise
  `CannotReply`. The label is `Reply`, and the detail is the first 80
  characters of the text. The rest is the same as `pick`.
- **`fire(id)`.** Lock and remove the action. If it is absent, it was
  cancelled, so return. Re-run `check`. An `Err` sets the notice and
  sends nothing. Otherwise, insert `busy(card)`, clone the handle,
  unlock, and run
  `outcome = handle.submit(Command::Answer{..} | Command::Send{..}).await`.
  Lock again, remove `busy`, and set the notice from
  `notice_for_outcome(&outcome)` if it is `Some`. Call `wake`.
- **`cancel(id)`** removes the action and wakes. It returns whether an
  action was found. `cancel_latest` cancels the last one in `actions`.
- **`mark_seen`.** The card must be `can_mark_seen`. It submits
  `Command::MarkSeen` without undo, in a spawned task. A failure becomes
  a notice.
- **`on_machine_event`.**
  - `Opened(req)`:
    - the dedupe key is the session's `machine.id`, or the entry key if
      there is none yet, plus `req.id`. If it is new, insert it and send
      `InboxEvent::RequestOpened`;
    - `agent_title` is the agent's title from the session, or the
      `agent_id`;
    - `request_title` is `req.title`.
  - `Resolved { agent_id, by, .. }`: if `resolution_notice(by)` is
    `Some`, set it on `card_key(machine_key, agent_id)`. Call `wake`, so
    that `check` cancels an action for that request.
  - `Welcomed(_)`: wake.
- **`save_machine(entry, token)`.**
  - `entry.validate()` must pass.
  - For `Tcp`: with `token` `Some(t)`, require `valid_token(t)` (the
    error is "That is not a valid acd client token (43 characters).")
    and call `secrets.set(key, t)`. With `None`, require an existing
    secret.
  - Replace or append the entry and save the settings if
    `settings_path` is set.
  - Drop the old handle, which aborts its task, and call
    `spawn_for(entry)`.
  - Return a `String` error for the UI.
- **`remove_machine(key)`.** Delete the secret, which may be absent.
  Remove the entry, save, and drop the handle.
- **`machines()`.** Return `MachineEntryView`s. `has_token` is `true`
  for `Local`. For `Tcp` it is `secrets.get(key)?.is_some()`.

```rust
//! Remote machine tokens in the login Keychain (decision D7).
use acd_client::settings::{SecretError, SecretStore};
use security_framework::passwords::{delete_generic_password, get_generic_password, set_generic_password};

const NOT_FOUND: i32 = -25300; // errSecItemNotFound

pub struct KeychainSecrets { service: String }

impl KeychainSecrets {
    pub fn new(service: &str) -> Self { Self { service: service.into() } }
}

impl SecretStore for KeychainSecrets {
    fn get(&self, key: &str) -> Result<Option<String>, SecretError> {
        match get_generic_password(&self.service, key) {
            Ok(bytes) => String::from_utf8(bytes).map(Some).map_err(|_| SecretError("token is not UTF-8".into())),
            Err(e) if e.code() == NOT_FOUND => Ok(None),
            Err(e) => Err(SecretError(e.to_string())),
        }
    }
    fn set(&self, key: &str, value: &str) -> Result<(), SecretError> {
        set_generic_password(&self.service, key, value.as_bytes()).map_err(|e| SecretError(e.to_string()))
    }
    fn delete(&self, key: &str) -> Result<(), SecretError> {
        match delete_generic_password(&self.service, key) {
            Ok(()) => Ok(()),
            Err(e) if e.code() == NOT_FOUND => Ok(()),
            Err(e) => Err(SecretError(e.to_string())),
        }
    }
}
```

```rust
pub const SIZE: u32 = 36;

fn rgba(color: TrayColor) -> [u8; 4] {
    match color {
        TrayColor::Amber => [245, 166, 35, 255],
        TrayColor::Blue => [66, 133, 244, 255],
        TrayColor::Green => [52, 168, 83, 255],
        TrayColor::Grey => [142, 142, 147, 255],
    }
}

pub fn summary_icon(color: TrayColor) -> Vec<u8> {
    let c = rgba(color);
    let (mid, r) = (SIZE as f32 / 2.0, SIZE as f32 * 0.32);
    let mut out = Vec::with_capacity((SIZE * SIZE * 4) as usize);
    for y in 0..SIZE {
        for x in 0..SIZE {
            let (dx, dy) = (x as f32 + 0.5 - mid, y as f32 + 0.5 - mid);
            out.extend_from_slice(if dx * dx + dy * dy <= r * r { &c } else { &[0, 0, 0, 0] });
        }
    }
    out
}
```

Keyboard rules (spec §8, D9 and D10):

- **`Escape`:** with `view.actions.length > 0`, `cancelLatest`; else
  with `replyFor` set, `closeReply`; else `hide`. This holds in the reply
  field too.
- **In the reply field (`inField`):** `Enter` without Shift gives
  `submitReply`. Every other key gives `none`, and the browser handles
  it.
- **`j` / `ArrowDown` and `k` / `ArrowUp`:** move the selection. They
  clamp at the ends. With no selection, select the first card.
- **`1`–`9`:**
  - on the selected card, when `answerable`, take option `n` of
    `agent.pending.options` in display order;
  - it gives `pick` only if that option's id is in
    `selectable_options`;
  - otherwise `none`.
- **`r`:** `openReply` when `can_reply`.
- **`e`:** `markSeen` when `can_mark_seen`.
- **`Enter` outside a field:** `none` (D10).
- **Letters:** match case-insensitively. Ignore keys pressed with
  Cmd, Ctrl or Alt.
