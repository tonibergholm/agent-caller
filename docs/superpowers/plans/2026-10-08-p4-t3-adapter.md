# P4: T3 adapter implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make T3 Code threads show up in acd as agents, turn pending T3
runtime requests (approvals and questions) into acd requests, answer them
through `runtime-request.respond`, send follow-ups through
`message.dispatch`, and publish the provider session id of each thread so
P3 can apply ownership rule 1 (spec §6.2).

**Architecture:** A `t3` module in `crates/acd-adapters`, next to `herdr`.
One WebSocket connection to the T3 server carries every stream and call.
A connection layer (`conn.rs`) owns the socket: a reader task that acks
every Chunk, a writer task, keepalive pings, and calls with absolute
deadlines. One **reconciler task** (`reconciler.rs`) owns all T3 state: it
consumes the shell stream and a bounded set of per-thread streams, keeps
resume cursors, and is the only code that upserts T3 agents and opens or
ends their requests. `T3Adapter` implements `acd_core::Adapter`. Its
`deliver` and `send` make one `dispatchCommand` call each, with a fresh
`commandId`, and classify the result in one function.

**Tech Stack:** Rust (edition 2024), tokio, tokio-tungstenite 0.30 (`ws://`
only, no TLS), serde and serde_json, uuid v4, regex (log redaction),
async-trait, tracing. Tests use an in-process fake T3 server (axum
WebSocket) built from the recorded gate-3 fixtures.

**Spec:** `docs/superpowers/specs/2026-10-07-agent-inbox-design.md`, mainly
§4 (invariants 2 and 4), §5 and §5.1 (lifecycle, non-reusable keys,
attribution), §6 (adapter contract), §6.2 (ownership rule 1), §6.5 (T3,
rewritten from the gate-3 evidence in the same commit as this plan), §9,
§12, §13 and §14 items 3, 4 and 5. Evidence:
`docs/research/2026-10-08-t3-gate3.md` and the 76 frames in
`tests/fixtures/t3/`. Every wire type and test in this plan is based on
those fixtures.

## Global Constraints

These apply to every task.

- **T3 version.** Pinned to `v0.0.46-nightly.20261008.2801`, orchestration
  protocol 2, shell `schemaVersion` 2. Unknown fields are ignored
  everywhere. Unknown shell or thread item kinds and unknown event types
  are ignored (debug log), never errors.
- **Connection** (gate 3 §1):
  - URL: `ws://<host>:<port>/ws?orchestrationProtocol=2`, built from
    `t3.url`.
  - Auth: `Authorization: Bearer <t3.token>` on the WebSocket upgrade.
    acd does not use the ticket endpoint (decision D2).
  - HTTP 401 on the upgrade: the source is `degraded` with "T3 rejected
    the token". HTTP 426: `degraded` with "T3 does not speak
    orchestration protocol 2". Both retry with the maximum backoff.
  - `t3.url` must be `http://` or `ws://`, with an IP literal that is
    loopback or in `100.64.0.0/10` / `fd7a:115c:a1e0::/48`, or the name
    `localhost`, and an explicit port. No path, query or user info.
    Anything else leaves the source `unconfigured` with a message. The
    token travels in plain text over `ws://`, so it never goes to another
    host.
- **Envelope** (gate 3 §2):
  - Client frames: `{"_tag":"Request","id","tag","payload","headers":[]}`,
    `{"_tag":"Ack","requestId"}`, `{"_tag":"Interrupt","requestId"}`,
    `{"_tag":"Ping"}`.
  - Server frames: `Chunk {requestId, values}`, `Exit {requestId, exit}`,
    `Pong`, and possibly `Ping`. A text frame may hold one object or an
    array of objects.
  - **Every Chunk gets an Ack**, sent by the reader task after the chunk's
    values are queued for the reconciler. Without acks only the first
    chunk arrives.
  - `exit` is `{"_tag":"Success","value"}` or
    `{"_tag":"Failure","cause":[...]}`, where each cause is `Fail {error}`,
    `Die {defect}` or `Interrupt {fiberId}`.
  - Request ids are per-connection decimal counters.
- **Keepalive.** A Ping every 20 s. If no frame of any kind arrives within
  10 s after a Ping, the connection is dead.
- **Needs-you rule** (gate 3 §3). An agent is `needs_you` exactly when its
  shell entry has `pendingRuntimeRequest != null`. `waiting` without a
  request is `working` (the post-terminal drain).
- **State mapping** (when no request is pending):

  | T3 `status` | acd state |
  |---|---|
  | `running`, `starting`, `preparing`, `queued`, `waiting` | `working` |
  | `completed` | `done` |
  | `failed`, `interrupted` | `done`, `failed: true` |
  | `idle`, `cancelled`, `rolled_back` | `idle` |
  | anything else, or `null` | `unknown` |

- **Resume** (gate 3 §4):
  - A shell snapshot that carries the key `resolvedRepositoryIdentityRoots`
    is **project-only**. It updates projects and nothing else: it never
    removes threads and never moves the cursor.
  - Any other snapshot replaces state and sets the cursor to its
    `snapshotSequence`.
  - Events at or below the cursor are dropped. Other events set the cursor
    to their `sequence`.
  - Resume never errors. There is no "expired cursor" path to handle.
- **Requests** (spec §5.1, gate 3 §3, §7):
  - Key: `CorrelationKey(<T3 runtime request id>)`, `reusable_key: false`,
    `ready: true`.
  - The shell's `pendingRuntimeRequest.id` decides **which** request is
    surfaced. The thread stream's `runtimeRequests[]` decides **when it
    ends**: `resolved` gives `terminal`, `cancelled` or any other
    non-pending status gives `lost`.
  - Ends from the reconciler always use `RequestEndedIfOpen`. An end seen
    while the request is `answering` is kept and re-applied once the
    request is `open` again (Task 6, "deferred ends").
- **Delivery classification** (one function, `t3::outcome::classify`, used
  by both `deliver` and `send`):

  | Call result | Classification |
  |---|---|
  | not connected, or the writer never took the frame (still queued at the deadline or close, or cancelled by a dropped caller) | `NotDelivered(SourceUnavailable)` |
  | `Exit Success` | delivered |
  | `Fail EnvironmentAuthorizationError` | `NotDelivered(SourceUnavailable)`, source degraded |
  | `Fail OrchestrationV2DispatchCommandError`, message exactly `Runtime request <our id> is resolved.` | `NotDelivered(RequestGone)`, request ends `terminal` |
  | the same with `is cancelled.` or `was not found.` | `NotDelivered(RequestGone)`, request ends `lost` |
  | the writer started the frame, then a send error, write timeout, reply timeout, connection loss, `Die`, `Interrupt`, or any other `Fail` | `Uncertain` |

  A send error after the writer started a frame is `Uncertain`, never
  `NotDelivered`: the flush may have delivered the whole frame (Sol round
  1, finding 1).
- **Delivery guarantee.** At most one dispatch attempt per acd command id
  within the idempotency window (15 minutes, §7.4). `Success` confirms
  delivery; anything else after the write is `uncertain`, and acd never
  resends.

- **commandId.** A fresh UUID v4 for every `dispatchCommand`. Never derived
  from an acd command id, never reused, never resent. T3 returns the old
  receipt for a reused `commandId` even when the payload differs (gate 3
  §6), so reuse would report a delivery that never happened. acd's own
  idempotency cache (§7.4) handles client retries and `duplicate_mismatch`.
- **Timeouts.** WebSocket connect and upgrade: 3 s. Every socket write:
  5 s, then the connection closes. One absolute deadline of 8 s per
  `dispatchCommand`. `deliver`, `send` and `mark_seen` finish within 10 s.
- **No waiting on the writer** (Sol round 1, finding 2). Control frames
  (acks, pongs, pings, interrupts, subscriptions) use their own lane of
  1024 frames, written before calls, and are queued without waiting. A
  full control lane closes the connection. The reconciler never awaits the
  connection, and opens at most 16 thread streams per policy pass.
- **Timers.** The reconciler's tick is one persistent interval, never a
  sleep re-created per loop turn (Sol round 1, finding 3).
- **Cancellation.** A frame queued by a call whose future was dropped is
  never written. A frame whose write had started may still take effect;
  the core already resolves a dropped delivery `uncertain`.
- **Thread streams** (decision D4; one definition used everywhere):
  - **request streams**, mandatory and uncapped: every thread with a
    pending request or a surfaced acd request. Their number is bounded by
    the outstanding requests;
  - **working streams**: at most 32, most recently updated first;
  - **one discovery stream** at a time, for session ids: working threads
    over the cap, then Claude or Codex threads updated in the last 24 h,
    with at most 3 overflow picks in a row while a recent thread waits. A
    thread whose native id is still null is retried at most every 60 s, in
    both groups;
  - every thread stream must deliver its first `synchronized` within 15 s,
    or it is interrupted, its detail dropped, and the thread skipped for
    60 s;
  - a stream is interrupted 10 s after its thread stops qualifying
    (a discovery stream right after its `synchronized`), and **releasing a
    stream drops that thread's detail and cursor**.
- **Retained detail** (Sol round 1, finding 5). Only threads with an open
  stream keep detail. A detail keeps pending and surfaced runtime
  requests, their turn items, at most 64 command items and at most 8
  provider threads. Targets of superseded requests are removed when the
  new request is surfaced.
- **Ids.** Agent id `t3:<thread id>`. Ids are never parsed back. The
  adapter keeps `agent id -> thread id` and `T3 request id -> Target`
  maps.
- **Display text.** Every string from T3 that reaches a client goes
  through `text::clean_display` (titles, labels) or `text::clean_screen`
  (multi-line detail). Caps: title 200 chars, `last_message` 500, request
  detail 4000.
- **Follow-up text** follows the §6.4 rules through
  `text::check_prompt_text` (16 KiB, no control or bidi characters).
- **Logs and diagnostics** (Sol round 1, finding 6). Never log the token
  or the upgrade request. T3 frames and failure text are logged only at
  `debug`, through `text::redact_log`, truncated to 4 KiB. Everything
  that reaches the core (`DeliverError::Uncertain`, which the core logs at
  `warn`) or a source status message is one of the fixed strings in
  `t3::outcome` and `t3::conn`, never server text.
- **Adapter-to-reconciler signals** go through `Mailbox`, which never
  drops an entry (Sol round 1, finding 7).
- **Locks.** No lock is held across an `.await` or a `Core` call. Clone out
  of shared maps first.
- **Workspace rules.** Rust edition 2024 and `rust-version = "1.90"`, from
  the workspace. CI runs `cargo test --workspace` and
  `cargo clippy --workspace --all-targets -- -D warnings` on macOS and
  Linux. Every task ends with both green.
- **CI trigger.** Push and PR events do not start Actions in this repo yet.
  After pushing, run `gh workflow run CI --ref <branch>` and watch it.

## Review Focus

These are the inputs most likely to hurt a real user that no single task's
happy path covers. Each has a pinned test in the task named.

1. **T3 restarts while a request is pending** (gate 3 §4). The socket
   closes with 1001. The source becomes `degraded` and T3 agents show
   `unknown`. After the reconnect the thread resumes, the request shows
   `cancelled`, and acd resolves it `lost`. A later inbox answer gets
   `request_gone`. Test: Task 6 (`restart_cancels_the_pending_request_as_lost`).
2. **The user answers in T3 while an inbox claim is in flight.** T3
   refuses acd's respond with "is resolved". The request resolves
   `terminal`, the client gets `request_gone`, and nothing is sent twice.
   An end seen during a claim that then fails before the write still ends
   the request. Tests: Task 7 (`answered_in_t3_first_gives_request_gone`)
   and Task 6 (`end_seen_during_a_claim_is_applied_after_release`).
3. **A project-only snapshot on resume.** It must not wipe threads or move
   the cursor, or the resumed event at the same sequence is dropped.
   Test: Task 5 (`project_only_snapshot_keeps_threads_and_cursor`).
4. **A reply lost after the frame was written, or a send error after it
   started.** The result is `uncertain`, and acd never resends. A client retry with the same acd
   command id sends one `message.dispatch`. Two calls never share a T3
   `commandId`. Tests: Task 3 (`reply_lost_after_write_is_no_reply`,
   `a_send_error_after_the_frame_went_out_is_no_reply`), Task 7
   (`a_send_error_after_a_complete_write_is_never_redispatched`),
   Task 7 (`each_dispatch_uses_a_fresh_command_id`) and Task 8
   (`follow_up_retry_sends_once`).
5. **Malformed or hostile T3 data.** An unknown item kind or event type is
   ignored. An undecodable thread entry makes only that agent `unknown`
   and the source `degraded`. A title with ANSI escapes or bidi controls
   reaches clients cleaned. Tests: Task 1 (`unknown_kinds_decode_as_other`),
   Task 2 (`hostile_text_is_cleaned`) and Task 5
   (`bad_thread_entry_degrades_only_that_agent`).

## Decisions

Each decision below is settled for this plan. The rationale is recorded
because most are hard to reverse once P3 and P5 build on them.

- **D1. WebSocket client: tokio-tungstenite 0.30**, already in the
  workspace, without TLS features. T3 runs locally or over Tailscale, so
  `wss://` is out of scope.
- **D2. Bearer header on the upgrade, no ticket.** Gate 3 verified that the
  server accepts `Authorization: Bearer` on the upgrade. The ticket path
  needs an extra HTTP request and an HTTP client crate, and the ticket only
  guards the upgrade anyway (an open socket outlives its ticket). The token
  is re-read from `t3.token` on every connect, so replacing the file takes
  effect at the next reconnect without a restart. If a later T3 version
  drops header auth, the ticket path is a contained change in `conn.rs`.
- **D3. One connection, one serial reconciler.** All streams share one
  socket. All state changes for T3 agents come from one task, so results
  apply in arrival order (the P2 lesson). `deliver` and `send` call T3
  directly through the shared connection handle, like the P2 keys engine,
  and report outcomes through `Core::observe`.
- **D4. Bounded thread subscriptions.** Request detail and the provider
  session id exist only in thread detail (gate 3 §3, §8). Subscribing to
  every thread is unbounded, so acd subscribes to threads with a pending
  request (always), threads that are `working` (up to 32 live in total),
  and one discovery stream at a time for session ids. A Claude session
  only fires hooks while it runs, so discovery serves working threads over
  the cap first, then recently active ones. Discovery is keyed by the
  active provider thread: a null native id is retried, and a provider
  switch clears the old owner at once. Ownership is published only while
  the shell and the thread detail agree on the active provider thread.
  Overflow and recent threads share one retry rule and take turns. A
  working thread over the cap gets
  its session id within one discovery round, not instantly; until then
  ownership falls back to rules 2 to 4 (the default entrypoint filter
  hides T3's `sdk-ts` sessions anyway).
- **D5. Request identity.** The key is the T3 runtime request id, not
  reusable (spec §5.1). The shell picks the surfaced request; the thread
  stream ends it. This keeps one request per agent even if
  `runtimeRequests[]` ever holds two pending entries.
- **D6. Approval options.** Neither provider sends `options[]`, so acd
  always offers the spec's fallback set: `accept` "Yes" (allow),
  `acceptForSession` "Yes, for this session" (allow_always), `decline`
  "No" (deny). The option id is the T3 decision literal. Approvals are
  answerable only for `requestKind: "command"`, the only kind gate 3
  observed. Any other approval kind, and any pending request without a
  matching turn item, opens a read-only request ("answer in T3").
- **D7. Claude command join.** The approval's `prompt` is Claude's
  description, not the command. acd joins the `command_execution` turn
  item with the same `nativeItemRef.nativeId` and shows its `input` as the
  detail, with the prompt on a second line when it differs. Codex's
  prompt is already the command; the same join gives the same text.
- **D8. Questions.** Kept in full. Option ids are `o1`…`oN`. The answer is
  `answers: {<question id>: option.value ?? option.label}`. The value comes
  from the `Target` recorded when the request opened, and `deliver`
  checks that the claimed option's label matches it.
- **D9. Attribution.** A `Success` exit for acd's respond is `by: "inbox"`.
  T3 accepts exactly one answer per request (the second gets "is
  resolved"), so the acknowledgement is the outcome evidence. The adapter
  observes `RequestEndedById { by: Inbox }` itself before `deliver`
  returns, and tells the reconciler to treat that request as gone so the
  agent's next upsert is `working`, not a stale `needs_you`. Gate 3 only
  showed a *sequential* second respond failing. Concurrent exclusivity is
  a pre-merge gate (Task 8 Step 4); if it fails, P4 does not merge and
  this rule is reopened.
- **D10. Follow-ups** use `message.dispatch` with `createdBy: "user"`,
  `creationSource: "web"`, `messageId` (new UUID), `attachments: []`,
  `deliveryIntent: "auto"` and `dispatchMode: {"type":"start_immediately"}`,
  exactly as recorded. T3 queues a message sent while a run is active, so
  `can_send` is `true` for every active thread; the core already refuses
  `needs_you` agents with `agent_busy`.
- **D11. Session map for ownership rule 1.** `T3Adapter::sessions()`
  returns an `Arc<SessionMap>`: `owner(session_id) -> Option<agent_id>`
  plus a `watch` channel that ticks on every change. The value is
  `providerThreads[].nativeThreadRef.nativeId` of the provider thread whose
  id equals the thread's `activeProviderThreadId`. An entry changes when
  the detail's answer changes (including to none), is cleared when the
  shell reports another active provider thread, and is removed with the
  agent. A disconnect does not clear it.
- **D12. Decode errors.** An undecodable envelope frame closes the
  connection and the reconnect resumes from the cursor. An undecodable
  item inside a chunk is skipped: its thread (if its id is readable)
  becomes `unknown`, and the source stays `degraded` with "N T3 items
  could not be read" until the next reconnect.
- **D13. `mark_seen`** stays local (trait default). T3's `lastVisitedAt`
  command was not verified.

## Out of scope (owned elsewhere)

- **Ownership rule 1 consumers, owned by P3.** P3 reads `SessionMap`,
  drops Claude-adapter state for T3-owned sessions, and re-evaluates
  unknown sessions when the map changes.
- **Starting threads, attachments, multi-select and free-text answers.**
  Not in v1 (spec §2).
- **The ticket auth path and `wss://`.** See D1 and D2.
- **Live end-to-end (`just e2e`).** Runs after P3, P4 and P5 merge
  (roadmap).

```rust
#[derive(Clone, Debug, PartialEq)]
pub enum Failure {
    /// Exactly one cause, and it is a typed error. `tag` is `error._tag`,
    /// `message` is `error.message`. Only this shape can ever be read as
    /// "nothing happened" (Task 4).
    Fail { tag: String, message: String },
    /// Every cause is a `Die`; the first defect is kept for the debug log.
    Die(String),
    /// Every cause is an `Interrupt` (the recorded interrupted stream has
    /// four).
    Interrupted,
    /// More than one cause of different kinds, or more than one `Fail`
    /// (Sol round 2, finding 6). The whole set is kept for the debug log.
    Mixed(Vec<Cause>),
    /// No causes, or only kinds this version does not know.
    Unknown,
}

/// Classifies the whole cause set. Nothing is dropped: a mixed set never
/// looks like a single typed error.
pub fn failure(causes: &[Cause]) -> Failure {
    let all = |f: fn(&Cause) -> bool| !causes.is_empty() && causes.iter().all(f);
    match causes {
        [Cause::Fail { error }] => Failure::Fail {
            tag: error["_tag"].as_str().unwrap_or("").to_owned(),
            message: error["message"].as_str().unwrap_or("").to_owned(),
        },
        _ if all(|c| matches!(c, Cause::Die { .. })) => {
            let Cause::Die { defect } = &causes[0] else { unreachable!() };
            Failure::Die(defect.as_str().map(str::to_owned).unwrap_or_else(|| defect.to_string()))
        }
        _ if all(|c| matches!(c, Cause::Interrupt {})) => Failure::Interrupted,
        _ if causes.iter().all(|c| matches!(c, Cause::Other)) => Failure::Unknown,
        _ => Failure::Mixed(causes.to_vec()),
    }
}
```

```rust
//! What acd keeps from one thread's projection (gate 3 §3, §7, §8).
use std::collections::{HashMap, HashSet, VecDeque};

use serde::Deserialize;
use serde_json::Value;

use super::wire::{NativeRef, ProviderThread, RuntimeRequest, ThreadEvent, TurnItem, turn_item};

#[derive(Clone, Debug, Default)]
pub struct ThreadDetail {
    pub active_provider_thread: Option<String>,
    /// Provider thread id -> native id (null until the first turn).
    natives: HashMap<String, Option<String>>,
    pub requests: HashMap<String, RuntimeRequest>,
    /// Only approval, user-input and command-execution items, by item id.
    items: HashMap<String, TurnItem>,
    /// Command-execution item ids, oldest first.
    command_order: VecDeque<String>,
    /// Provider thread ids, oldest first.
    provider_order: VecDeque<String>,
}

pub const MAX_COMMAND_ITEMS: usize = 64;

#[derive(Clone, Debug)]
pub struct PendingView {
    pub request: RuntimeRequest,
    pub item: Option<TurnItem>,
    /// `input` of the `command_execution` item that shares the approval's
    /// `nativeItemRef.nativeId` (D7).
    pub command: Option<String>,
}

impl ThreadDetail {
    pub fn from_projection(p: &Value) -> (ThreadDetail, usize) {
        let mut d = ThreadDetail {
            active_provider_thread: p["thread"]["activeProviderThreadId"].as_str().map(str::to_owned),
            ..ThreadDetail::default()
        };
        let mut skipped = 0;
        let arr = |k: &str| p[k].as_array().cloned().unwrap_or_default();
        for v in arr("providerThreads") {
            match ProviderThread::deserialize(&v) { Ok(t) => d.put_provider_thread(t), Err(_) => skipped += 1 }
        }
        for v in arr("runtimeRequests") {
            match RuntimeRequest::deserialize(&v) { Ok(r) => { d.requests.insert(r.id.clone(), r); } Err(_) => skipped += 1 }
        }
        for v in arr("turnItems") {
            match turn_item(&v) { Ok(i) => d.put_item(i), Err(_) => skipped += 1 }
        }
        (d, skipped)
    }

    pub fn apply(&mut self, ev: &ThreadEvent) -> Result<(), serde_json::Error> {
        match ev.kind.as_str() {
            "runtime-request.updated" => {
                let r = RuntimeRequest::deserialize(&ev.payload)?;
                self.requests.insert(r.id.clone(), r);
            }
            "turn-item.updated" => self.put_item(turn_item(&ev.payload)?),
            "provider-thread.updated" => self.put_provider_thread(ProviderThread::deserialize(&ev.payload)?),
            "thread.metadata-updated" => {
                if let Some(v) = ev.payload.get("activeProviderThreadId") {
                    self.active_provider_thread = v.as_str().map(str::to_owned);
                }
            }
            _ => {}
        }
        Ok(())
    }

    fn put_provider_thread(&mut self, t: ProviderThread) {
        let native = t.native_thread_ref.and_then(|r| r.native_id);
        self.provider_order.retain(|i| *i != t.id);
        self.provider_order.push_back(t.id.clone());
        self.natives.insert(t.id, native);
    }

    /// Drops history the reconciler no longer needs (see Interfaces).
    pub fn prune(&mut self, keep: &[&str]) {
        self.requests.retain(|id, r| r.status == "pending" || keep.contains(&id.as_str()));
        let requests = &self.requests;
        let mut joined: HashSet<String> = HashSet::new();
        self.items.retain(|_, i| match i {
            TurnItem::ApprovalRequest { request_id, native_item_ref, .. } => {
                let kept = requests.contains_key(request_id);
                if kept { if let Some(n) = native_item_ref.as_ref().and_then(|r| r.native_id.clone()) { joined.insert(n); } }
                kept
            }
            TurnItem::UserInputRequest { request_id, .. } => requests.contains_key(request_id),
            _ => true,
        });
        let terminal = |s: &Option<String>| matches!(s.as_deref(), Some("completed" | "failed" | "declined" | "cancelled"));
        let items = &mut self.items;
        self.command_order.retain(|id| match items.get(id) {
            Some(TurnItem::CommandExecution { status, native_item_ref, .. }) => {
                let referenced = native_item_ref.as_ref().and_then(|r| r.native_id.as_ref()).is_some_and(|n| joined.contains(n));
                let keep = referenced || !terminal(status);
                if !keep { items.remove(id); }
                keep
            }
            _ => false,
        });
        // Cap only the unreferenced ones; a live approval's command survives.
        let unreferenced: Vec<String> = self.command_order.iter().filter(|id| !matches!(self.items.get(*id),
            Some(TurnItem::CommandExecution { native_item_ref: Some(NativeRef { native_id: Some(n) }), .. }) if joined.contains(n)))
            .cloned().collect();
        for old in unreferenced.iter().take(unreferenced.len().saturating_sub(MAX_COMMAND_ITEMS)) {
            self.items.remove(old);
            self.command_order.retain(|i| i != old);
        }
        let active = self.active_provider_thread.clone();
        while self.provider_order.len() > 8 {
            let Some(pos) = self.provider_order.iter().position(|i| Some(i) != active.as_ref()) else { break };
            if let Some(old) = self.provider_order.remove(pos) { self.natives.remove(&old); }
        }
    }

    pub fn retained(&self) -> (usize, usize) { (self.requests.len(), self.items.len()) }

    fn put_item(&mut self, i: TurnItem) {
        let id = match &i {
            TurnItem::ApprovalRequest { id, .. } | TurnItem::UserInputRequest { id, .. } => id.clone(),
            TurnItem::CommandExecution { id, .. } => {
                if !self.items.contains_key(id) { self.command_order.push_back(id.clone()); }
                id.clone()
            }
            TurnItem::Other => return,
        };
        self.items.insert(id, i);
    }

    /// The provider session id of the active provider thread (gate 3 §8).
    pub fn native_session_id(&self) -> Option<&str> {
        let active = self.active_provider_thread.as_ref()?;
        self.natives.get(active)?.as_deref()
    }

    pub fn request_status(&self, id: &str) -> Option<&str> {
        self.requests.get(id).map(|r| r.status.as_str())
    }

    pub fn pending_view(&self, id: &str) -> Option<PendingView> {
        let request = self.requests.get(id).filter(|r| r.status == "pending")?.clone();
        let item = self.items.values().find(|i| match i {
            TurnItem::ApprovalRequest { request_id, .. } | TurnItem::UserInputRequest { request_id, .. } => request_id == id,
            _ => false,
        }).cloned();
        let native = match &item {
            Some(TurnItem::ApprovalRequest { native_item_ref: Some(NativeRef { native_id: Some(n) }), .. }) => Some(n.clone()),
            _ => None,
        };
        let command = native.and_then(|n| self.items.values().find_map(|i| match i {
            TurnItem::CommandExecution { native_item_ref: Some(NativeRef { native_id: Some(m) }), input, .. } if *m == n => input.clone(),
            _ => None,
        }));
        Some(PendingView { request, item, command })
    }
}
```

```rust
                Some(c) if !prompt.is_empty() && c != prompt => format!("{c}\n{prompt}"),
                Some(c) => c.to_owned(),
                None => prompt.to_owned(),
            };
            obs.title = "Run a command".into();
            obs.detail = detail(&text);
            obs.answer_path = AnswerPath::T3;
            obs.options = FALLBACK.iter().map(|(id, label, effect)| RequestOption {
                id: (*id).into(), label: (*label).into(), description: None, effect: *effect,
            }).collect();
            answer = TargetAnswer::Decision;
        }
        Some(TurnItem::UserInputRequest { questions, .. }) if !questions.is_empty() => {
            let qs: Vec<Question> = questions.iter().map(|q| Question {
                id: q.id.clone(),
                header: q.header.as_deref().map(|h| clean_display(h, TITLE_CHARS)),
                text: detail(&q.question),
                multi_select: q.multi_select,
                options: q.options.iter().enumerate().map(|(i, o)| RequestOption {
                    id: format!("o{}", i + 1),
                    label: clean_display(&o.label, TITLE_CHARS),
                    description: o.description.as_deref().map(|d| clean_display(d, TITLE_CHARS)),
                    effect: Effect::Choose,
                }).collect(),
            }).collect();
            let q0 = &questions[0];
            answer = TargetAnswer::Question {
                question_id: q0.id.clone(),
                choices: q0.options.iter().enumerate().map(|(i, o)| Choice {
                    option_id: format!("o{}", i + 1),
                    label: clean_display(&o.label, TITLE_CHARS),
                    value: o.value.clone().unwrap_or_else(|| o.label.clone()),
                }).collect(),
            };
            obs.kind = RequestKind::Question;
            obs.title = qs[0].header.clone().unwrap_or_else(|| "Question".into());
            obs.detail = qs[0].text.clone();
            obs.options = qs[0].options.clone();
            obs.questions = Some(qs);
            obs.answer_path = AnswerPath::T3;
        }
        _ => {}
    }
    let target = Target { agent_id: agent_id.into(), thread_id: thread_id.into(), t3_request_id: rid, answer };
    (obs, target)
}

/// The `runtime-request.respond` payload for a claimed answer. Errors mean
/// the answer cannot be expressed; nothing is sent.
pub fn respond_payload(command_id: &str, target: &Target, request: &Request, answer: &Answer) -> Result<Value, &'static str> {
    let Answer::Option(option_id) = answer else { return Err("T3 requests take an option, not text") };
    let mut p = json!({
        "type": "runtime-request.respond", "commandId": command_id,
        "threadId": target.thread_id, "requestId": target.t3_request_id,
    });
    match &target.answer {
        TargetAnswer::Decision => {
            if !DECISIONS.contains(&option_id.as_str()) { return Err("not a T3 decision"); }
            p["decision"] = json!(option_id);
        }
        TargetAnswer::Question { question_id, choices } => {
            let shown = request.options.iter().find(|o| &o.id == option_id).ok_or("unknown option")?;
            let choice = choices.iter().find(|c| &c.option_id == option_id && c.label == shown.label)
                .ok_or("option does not match the recorded question")?;
            p["answers"] = json!({ question_id.clone(): choice.value });
        }
        TargetAnswer::ReadOnly => return Err("read-only request"),
    }
    Ok(p)
}

pub fn dispatch_payload(command_id: &str, message_id: &str, thread_id: &str, text: &str) -> Value {
    json!({
        "type": "message.dispatch", "createdBy": "user", "creationSource": "web",
        "commandId": command_id, "threadId": thread_id, "messageId": message_id,
        "text": text, "attachments": [], "deliveryIntent": "auto",
        "dispatchMode": {"type": "start_immediately"},
    })
}
```

**Design** (Sol round 1, findings 1 and 2).

- **Two writer lanes.** Control frames (Ack, Pong, Ping, Interrupt and
  subscription requests) go on a lane of capacity `CONTROL_CAPACITY`;
  calls go on a lane of capacity `CALL_CAPACITY`. The writer uses a
  `biased` select that always drains the control lane first, so acks and
  pings never queue behind calls.
- **Nothing that the reader or the reconciler does waits for the writer.**
  Control frames are queued with `try_send`. A full control lane means the
  writer is not making progress: the connection closes with "T3 write
  queue full", and the reconcile loop reconnects and resumes. The reader
  only ever waits on the events channel, which the reconciler drains; the
  reconciler never waits on the connection. That breaks the
  reader-writer-reconciler cycle.
- **Every socket write has a deadline.** Each `sink.send` runs under
  `write_timeout`; on expiry the connection closes with "T3 write
  stalled". Closing drops the socket, so every task and waiting call ends
  within `write_timeout` plus one scheduler turn.
- **Calls are close-aware.** Each await in `call` (queueing, the write
  verdict, the Exit) selects against the close signal and the absolute
  deadline.
- **Conservative write verdicts.** Only a frame that the writer never
  took (`QUEUED`, or `CANCELLED` by the caller's drop) is `NotWritten`.
  Once the writer has started a frame (`WRITING`), any later problem,
  including a send error, is `NoReply`: `SinkExt::send` includes a flush,
  and a reported error does not prove that T3 received nothing.

FakeT3 is an axum server on `127.0.0.1:0` with one route, `GET /ws`. It
mimics the recorded server where acd depends on it:

- **Upgrade checks.** A missing or wrong `orchestrationProtocol` query
  parameter gets HTTP 426 with the body of
  `http_ws_upgrade_426_protocol_incompatible.json`. A missing or wrong
  `Authorization: Bearer` gets 401 with
  `http_ws_upgrade_401_invalid_credential_expired_ticket.json`.
- **Acks.** Each subscription sends one item per Chunk and sends the next
  Chunk of that stream only after the client's Ack for the previous one.
- **Shell resume** (gate 3 §4). With no `afterSequence`, or one at or past
  the head: a full snapshot, then a project-only snapshot (with
  `resolvedRepositoryIdentityRoots`), then `synchronized`. With
  `afterSequence: N` below the head: a project-only snapshot, the shell
  events after `N`, then `synchronized`. A negative value gets the Exit in
  `shell_resume_negative_afterSequence_exit.json`. Live events follow.
- **Thread resume.** With `afterSequence: N` below the head: that thread's
  events after `N`, then `synchronized`. Otherwise a snapshot
  `{kind:"snapshot", snapshotSequence: head, projection}` and
  `synchronized`. An unknown thread gets the Exit in
  `thread_subscribe_unknown_thread_exit.json`.
- **One global sequence.** Every shell and thread event takes the next
  number.
- **`runtime-request.respond`.** A pending request becomes `resolved` with
  the `decision` or `answers`. The fake pushes `runtime-request.updated`
  for it, sets the shell entry's `pendingRuntimeRequest` to `null` and
  `status` to `running`, and replies `Success {sequence}`. A resolved,
  cancelled or unknown request gets the `Fail` from
  `cmd_exit_respond_fail_already_resolved.json`,
  `cmd_exit_respond_fail_cancelled_after_restart.json` or
  `cmd_exit_respond_fail_not_found.json`, with the message rewritten to the
  actual request id. A reused `commandId` returns the stored receipt
  whatever the payload (gate 3 §6).
- **`message.dispatch`.** Recorded, the shell `status` becomes `running`,
  reply `Success {sequence}`.
- **Unknown tags** get the Exit in `rpc_exit_die_unknown_tag.json`.
  `Ping` gets `Pong`. `Interrupt` ends the stream with the Exit in
  `rpc_exit_interrupted_stream.json`.

- [ ] **Step 4: Implement `conn.rs`**

Four tasks per connection, all stopped by one close signal
(`watch::Sender<Option<&'static str>>`; the first `close` wins):

- **Reader.** Reads text frames, records `last_rx`, and parses with
  `wire::parse_frames`. A parse error logs
  `tracing::debug!(frame = %redact_log(&text))` and closes with
  "T3 sent a frame acd cannot read". `Chunk` for a known stream: send
  `StreamMsg::Chunk` on the events channel (capacity 256,
  `send().await`, raced against the close signal), then `try_send` the
  Ack on the control lane. A Chunk for an unknown stream (already
  interrupted) is acked and dropped. `Exit`: a pending call gets it
  through its oneshot; a stream gets `StreamMsg::End`. `Ping` queues
  `{"_tag":"Pong"}`. Close frames, EOF and errors close with "connection
  to T3 lost".
- **Writer.** `biased` select: the control lane first, then the call lane,
  then the close signal. Call frames are written only after
  `ticket.state.compare_exchange(QUEUED, WRITING)` succeeds; otherwise
  they are skipped. Every `sink.send(Message::text(..))` runs under
  `timeout(write_timeout)`. On success a call frame's ticket becomes
  `WRITTEN`; on error or timeout it becomes `FAILED` and the connection
  closes ("T3 write stalled" for the timeout, "connection to T3 lost"
  otherwise). The writer notifies the ticket in every case.
- **Keepalive.** Every `ping_every`, `try_send` a `PING_FRAME` on the
  control lane, wait `pong_timeout`, and close with "T3 did not answer a
  ping" if `last_rx` is older than the ping.
- **Control enqueue helper.** `fn control(&self, text: String) -> Result<(), CallError>`:
  `NotConnected` when closed; on `TrySendError::Full` it closes with "T3
  write queue full" and returns `NotConnected`.

On close, the reader drops every pending call's oneshot sender and the
events sender, so the reconciler sees `recv() == None`.

The call path:

```rust
const QUEUED: u8 = 0;
const WRITING: u8 = 1;
const CANCELLED: u8 = 2;
const FAILED: u8 = 3;
const WRITTEN: u8 = 4;

struct Ticket { state: Arc<AtomicU8>, done: oneshot::Sender<()> }

/// Cancels a queued frame when the caller's future is dropped. A frame the
/// writer already took (`WRITING`) is not affected: it may still take effect.
struct CancelOnDrop(Arc<AtomicU8>);
impl Drop for CancelOnDrop {
    fn drop(&mut self) { let _ = self.0.compare_exchange(QUEUED, CANCELLED, SeqCst, SeqCst); }
}

impl Conn {
    pub async fn call(&self, tag: &str, payload: &Value, deadline: Instant) -> Result<Value, CallError> {
        if self.is_closed() { return Err(CallError::NotConnected); }
        let id = self.next_id();
        let (exit_tx, exit_rx) = oneshot::channel();
        self.inner.calls.lock().expect("calls").insert(id.clone(), exit_tx);
        let _forget = ForgetCall(self.inner.clone(), id.clone()); // removes the entry on drop
        let state = Arc::new(AtomicU8::new(QUEUED));
        let _cancel = CancelOnDrop(state.clone());
        let (done_tx, done_rx) = oneshot::channel();
        let out = Outgoing { text: request_frame(&id, tag, payload), ticket: Ticket { state: state.clone(), done: done_tx } };
        let mut closed = self.closed_signal();
        tokio::select! {
            r = timeout_at(deadline, self.inner.calls_tx.send(out)) => if !matches!(r, Ok(Ok(()))) {
                return Err(CallError::NotConnected); // never queued
            },
            _ = closed.wait() => return Err(CallError::NotConnected),
        }
        tokio::select! {
            _ = timeout_at(deadline, done_rx) => {}
            _ = closed.wait() => {}
        }
        // The ticket state is the only verdict on whether the frame went out.
        // Cancel first: if the writer has not taken it, it never will.
        if state.compare_exchange(QUEUED, CANCELLED, SeqCst, SeqCst).is_ok() {
            return Err(CallError::NotWritten("not written before the deadline or close"));
        }
        match state.load(SeqCst) {
            CANCELLED => return Err(CallError::NotWritten("not written before the deadline or close")),
            WRITTEN => {}
            // WRITING or FAILED: the writer started this frame. A send error
            // does not prove T3 received nothing (Sol round 1, finding 1).
            _ => return Err(CallError::NoReply("the write started but was not confirmed")),
        }
        tokio::select! {
            r = timeout_at(deadline, exit_rx) => match r {
                Ok(Ok(ExitValue::Success { value })) => Ok(value),
                Ok(Ok(ExitValue::Failure { cause })) => Err(CallError::Failed(failure(&cause))),
                Ok(Err(_)) => Err(CallError::NoReply("connection closed before the reply")),
                Err(_) => Err(CallError::NoReply("no reply before the deadline")),
            },
            _ = closed.wait() => Err(CallError::NoReply("connection closed before the reply")),
        }
    }
}
```

```rust
//! The one place that decides what a dispatch result means (Global
//! Constraints). Server text never leaves this module except in a redacted
//! debug log.
use acd_protocol::{ErrorCode, ResolvedBy};
use serde_json::Value;

use super::conn::CallError;
use super::wire::Failure;
use crate::text::redact_log;

pub const NO_REPLY: &str = "T3 did not confirm the command";
pub const DEFECT: &str = "T3 reported an internal error";
pub const INTERRUPTED: &str = "T3 interrupted the command";
pub const REFUSED: &str = "T3 refused the command";
pub const SCOPE: &str = "the T3 token lacks the orchestration:operate scope";
pub const MIXED: &str = "T3 reported several failures";

#[derive(Clone, Debug, PartialEq)]
pub enum Outcome {
    Delivered,
    /// Nothing reached T3's orchestrator. `end` says how the request ended
    /// at the source when T3 said so; `degrade` is a source status message.
    NotDelivered { code: ErrorCode, end: Option<ResolvedBy>, degrade: Option<&'static str> },
    Uncertain(&'static str),
}

const DISPATCH_ERROR: &str = "OrchestrationV2DispatchCommandError";

pub fn classify(res: &Result<Value, CallError>, t3_request_id: Option<&str>) -> Outcome {
    if let Err(e) = res {
        tracing::debug!(error = %redact_log(&format!("{e:?}")), "T3 dispatch failed");
    }
    let not = |code, end, degrade| Outcome::NotDelivered { code, end, degrade };
    match res {
        Ok(_) => Outcome::Delivered,
        Err(CallError::NotConnected) | Err(CallError::NotWritten(_)) => not(ErrorCode::SourceUnavailable, None, None),
        Err(CallError::Failed(Failure::Fail { tag, .. })) if tag == "EnvironmentAuthorizationError" => {
            not(ErrorCode::SourceUnavailable, None, Some(SCOPE))
        }
        Err(CallError::Failed(Failure::Fail { tag, message })) if tag == DISPATCH_ERROR => {
            let Some(id) = t3_request_id else { return Outcome::Uncertain(REFUSED) };
            if *message == format!("Runtime request {id} is resolved.") {
                not(ErrorCode::RequestGone, Some(ResolvedBy::Terminal), None)
            } else if *message == format!("Runtime request {id} is cancelled.") || *message == format!("Runtime request {id} was not found.") {
                not(ErrorCode::RequestGone, Some(ResolvedBy::Lost), None)
            } else {
                Outcome::Uncertain(REFUSED)
            }
        }
        Err(CallError::Failed(Failure::Fail { .. })) | Err(CallError::Failed(Failure::Unknown)) => Outcome::Uncertain(REFUSED),
        // Several causes: never read as "nothing happened" (Sol round 2, finding 6).
        Err(CallError::Failed(Failure::Mixed(_))) => Outcome::Uncertain(MIXED),
        Err(CallError::Failed(Failure::Die(_))) => Outcome::Uncertain(DEFECT),
        Err(CallError::Failed(Failure::Interrupted)) => Outcome::Uncertain(INTERRUPTED),
        Err(CallError::NoReply(_)) => Outcome::Uncertain(NO_REPLY),
    }
}
```

The same rule applies to everything else that reaches the core or the
source status: connection close reasons and `ConnectError` messages are
fixed `&'static str`s, and decode errors produce the fixed "N T3 items
could not be read (see the debug log)".

```rust
use std::collections::HashMap;
use std::sync::RwLock;
use tokio::sync::watch;

pub struct SessionMap {
    by_session: RwLock<HashMap<String, String>>,
    by_agent: RwLock<HashMap<String, String>>,
    tx: watch::Sender<u64>,
}

impl Default for SessionMap {
    fn default() -> Self { SessionMap { by_session: Default::default(), by_agent: Default::default(), tx: watch::channel(0).0 } }
}

impl SessionMap {
    pub fn owner(&self, session_id: &str) -> Option<String> {
        self.by_session.read().expect("sessions").get(session_id).cloned()
    }
    pub fn changes(&self) -> watch::Receiver<u64> { self.tx.subscribe() }

    pub(crate) fn set(&self, agent_id: &str, session_id: Option<&str>) {
        let changed = {
            let mut by_agent = self.by_agent.write().expect("sessions");
            let mut by_session = self.by_session.write().expect("sessions");
            let old = by_agent.get(agent_id).cloned();
            if old.as_deref() == session_id { false } else {
                if let Some(o) = old { by_session.remove(&o); by_agent.remove(agent_id); }
                if let Some(s) = session_id {
                    by_session.insert(s.to_owned(), agent_id.to_owned());
                    by_agent.insert(agent_id.to_owned(), s.to_owned());
                }
                true
            }
        };
        if changed { self.tx.send_modify(|n| *n += 1); }
    }

    pub(crate) fn remove_agent(&self, agent_id: &str) { self.set(agent_id, None) }
```

```rust
async fn run(cfg: SyncConfig, core: Arc<Core>, shared: Arc<Shared>) {
    let mut s = Sync::new(core, shared, cfg.timing.clone());
    let mut backoff = cfg.timing.backoff_start;
    loop {
        let url = match &cfg.ws_url {
            Ok(u) => u.clone(),
            Err(why) => { s.status(SourceState::Unconfigured, Some(format!("t3.url: {why}"))); return; } // `why` is acd's own text
        };
        let token = match read_token(&cfg.token_path) {
            Ok(t) => t,
            Err(why) => { s.status(SourceState::Unconfigured, Some(why)); sleep(cfg.timing.backoff_max).await; continue; }
        };
        match conn::connect(&url, &token, &cfg.timing.conn).await {
            Err(e) => {
                s.status(SourceState::Degraded, Some(e.to_string())); // fixed messages (Task 3)
                let wait = if matches!(e, ConnectError::Unreachable) { backoff } else { cfg.timing.backoff_max };
                sleep(wait).await;
                backoff = (backoff * 2).min(cfg.timing.backoff_max);
            }
            Ok((conn, mut events)) => {
                let synced = s.serve(conn, &mut events).await;
                if synced { backoff = cfg.timing.backoff_start; }
                s.connection_lost();
                sleep(backoff).await;
                backoff = (backoff * 2).min(cfg.timing.backoff_max);
            }
        }
    }
}
```

`read_token(path) -> Result<String, String>`: missing file gives
"T3 token missing: save `t3 auth session issue` output to <path> with
mode 0600"; a mode with any group or other bit gives "t3.token must be
mode 0600"; contents are trimmed and must be non-empty visible ASCII,
otherwise "t3.token is not a valid token". The message never includes the
token.

`serve` stores the connection in `shared.conn` and subscribes **only to
the shell** (`{"requestCompletionMarker": true}` plus `afterSequence` when
`shell_cursor` is set) before entering the loop. Thread streams are opened
by the policy pass (Step 6), at most `OPEN_PER_PASS` per pass, so the loop
drains events between passes. `Conn::subscribe` never waits for the writer
(Task 3), so nothing here can block on the socket.

The tick is one persistent interval created before the loop, so a steady
flow of chunks cannot postpone it (Sol round 1, finding 3):

`on_tick` applies the stream policy, enforces sync deadlines, drains

`on_end` for the shell stream closes the connection (the shell must never

- [ ] **Step 5: Implement shell handling**

For each value of a shell chunk, in order:

1. `is_project_only(v)`: decode the snapshot, merge its projects into
   `projects`, re-upsert threads whose project changed. **No cursor
   change, no thread removal.**
2. Otherwise, if `item_sequence(v)` is `Some(n)` and `n <= shell_cursor`,
   skip it. If it is `Some(n)`, set `shell_cursor = n` before decoding, so
   an undecodable or unknown item is never replayed.
3. `ShellItem::decode(v)`:
   - `Snapshot`: replace `projects`; decode each thread entry; every known
     thread not in the snapshot is removed (`gone`); set
     `shell_cursor = snapshot_sequence`.
   - `Synchronized`: set the source `Ok` when `decode_errors == 0`,
     otherwise `Degraded` with "N T3 items could not be read (see the
     debug log)". Re-upsert every thread (this restores agents that went
     `unknown`).
   - `ThreadUpdated { location, thread, .. }`: `location != "active"`, or
     `archivedAt` or `deletedAt` set, means `gone`. Otherwise decode with
     `ShellThread::decode` and upsert.
   - `ThreadRemoved { thread_id, .. }`: `gone`.
   - `ProjectUpdated { project, .. }`: store it and re-upsert its threads.
   - `Other`: ignore.
4. A decode error: `decode_errors += 1`, log the value at debug through
   `redact_log`, set the source `Degraded`. If `v["thread"]["id"]` is a
   string, set that thread's `shell = None` and upsert it as `unknown`
   (D12).

`upsert(thread_id)`: with a decoded shell entry, `map::agent_obs(shell,
project, &hidden)`; with none, the last observation with `state:
Unknown`. Insert `agent id -> thread id` into `shared.threads` **before**

**Published-owner rule** (Sol round 2, finding 1). Ownership is
published only when the shell and the thread detail agree on the active
provider thread. `publish_owner(thread)` runs after every shell update of
the thread and after every value of its stream:

```rust
fn publish_owner(&mut self, thread_id: &str) {
    let Some(t) = self.threads.get_mut(thread_id) else { return };
    let agent = map::agent_id(thread_id);
    let shell_pt = t.shell.as_ref().and_then(|s| s.active_provider_thread_id.clone());

    // 1. Invalidation, before any synchronization gate (Sol round 4). A
    //    validated owner is removed only by identity evidence: the shell
    //    names another active provider thread, or the detail names another
    //    provider thread (or none), or a null or different native id.
    //    A stall, a timeout or a missing detail is not evidence.
    if let Some((owner_pt, owner_session)) = t.owner.clone() {
        let detail_says = t.detail.as_ref().map(|d| (d.active_provider_thread.clone(), d.native_session_id().map(str::to_owned)));
        let invalid = shell_pt.as_deref() != Some(owner_pt.as_str())
            || detail_says.is_some_and(|(pt, native)| pt.as_deref() != Some(owner_pt.as_str()) || native.as_deref() != Some(owner_session.as_str()));
        if invalid {
            self.shared.sessions.set(&agent, None);
            t.owner = None;
            t.discovery = Discovery::Unknown;
        }
    }

    // 2. Publishing a new or changed owner needs shell and detail agreement
    //    and this stream's own first `synchronized` (Sol round 3).
    let Some(detail) = t.detail.as_ref() else { return };
    let detail_pt = detail.active_provider_thread.clone();
    match (shell_pt, detail_pt) {
        (Some(s), Some(d)) if s == d => {
            if !t.synced || t.owner.is_some() { return; }
            match detail.native_session_id().map(str::to_owned) {
                Some(n) => {
                    self.shared.sessions.set(&agent, Some(&n));
                    t.owner = Some((d.clone(), n));
                    t.discovery = Discovery::Known { provider_thread: d };
                }
                None => t.discovery = Discovery::NotLoaded { provider_thread: Some(d), at: Instant::now() },
            }
        }
        // Disagreement, or a null on either side: nothing to publish.
        (_, d) => if t.owner.is_none() {
            t.discovery = Discovery::NotLoaded { provider_thread: d, at: Instant::now() };
        },
    }
}
```

`ThreadState` gains `owner: Option<(String, String)>`: the provider thread
and native session id of the owner this thread published. It survives
stalls, sync timeouts, stream releases and reconnects; only step 1 and
`gone` remove it. The detail is kept across a reconnect (the resumed
stream continues from the cursor), so a resumed event that changes the
native id, or sets it to null, invalidates the owner at once, before that
stream synchronizes.

`gone(thread_id)`: interrupt its stream, remove it from `threads`,
`shared.threads` and the session map, then
`core.observe(Observation::AgentGone { agent_id })`. The registry resolves
an open request `lost`.

`connection_lost()`: clear stream ids (they belong to the dead
connection), keep every cursor, upsert every thread's last observation
with `state: Unknown`, and set the source `Degraded` with "connection to
T3 lost". Open requests stay open; answers to them get
`source_unavailable` until the reconnect.

- [ ] **Step 6: Implement thread streams and session learning**

Stream classes (one definition, used by the plan, the spec and the
tests):

- **Request streams**, mandatory and not counted against any cap: every
  thread whose shell entry has a pending request, or that still has a
  surfaced request (`open`, Task 6). The second case matters after a T3
  restart: the shell then shows no request, and only the thread stream
  reports it `cancelled`. Their number is bounded by the number of
  outstanding requests.
- **Working streams**: threads that map to `working`, most recently
  updated first, at most `max_live` (32).
- **Discovery stream**: at most one at a time (D4, Sol round 1,
  finding 4). A thread is **eligible** when its `Discovery` is `Unknown`,
  or `NotLoaded` for longer than `relearn_after`, and it is not stalled
  (`stalled_until` below). The same rule applies to both groups (Sol
  round 2, finding 2):
  1. **overflow**: working threads that did not get a working stream;
  2. **recent**: Claude or Codex threads updated within `learn_window`
     (`ZERO` disables this group only).

  Overflow goes first, but after `OVERFLOW_BURST` (3) consecutive overflow
  picks the next pick comes from the recent group when it has an eligible
  thread. Within a group, the thread checked longest ago goes first. So a
  recent thread waits at most `OVERFLOW_BURST + 1` discovery rounds, and a
  null overflow thread is retried at most once per `relearn_after`.

  A discovery stream is interrupted right after its `synchronized`,
  unless the thread became a request or working stream. At that point
  `Discovery` becomes `Known { provider_thread }` if the published-owner
  rule below found a native id, otherwise
  `NotLoaded { provider_thread, at: now }`.
- **Initial synchronization deadline** (Sol round 2, finding 3). Every
  thread stream, of any class, must deliver its first `synchronized`
  within `sync_timeout` (15 s) of being opened. On expiry the reconciler
  interrupts it, evicts its detail and cursor, sets the thread's
  `stalled_until = now + relearn_after`, and **resets its `Discovery` to
  `Unknown`** so it is eligible again after the stall (Sol round 3). It
  does **not** clear an owner that an earlier synchronized stream
  validated (Sol round 4): only identity evidence does (`publish_owner`
  step 1). Then it moves on (the discovery slot
  is free for the next candidate). A stalled thread is skipped by every
  class until `stalled_until` passes; a request stream is then reopened
  (its open request stays as it is meanwhile, and answers still work
  because they do not need the stream). The shell stream has the same
  deadline; missing it closes the connection, which reconnects and
  resumes.

`on_tick` (and after every shell chunk) runs the policy pass:

- Open request streams first, then working streams, then the discovery
  stream, at most `OPEN_PER_PASS` new streams per pass.
- A request or working stream whose thread no longer qualifies is
  interrupted once `unneeded_since` is older than `release_after`.
- **Releasing a stream evicts its detail and cursor** (`detail = None`,
  `cursor = None`). A later subscription asks without `afterSequence` and
  gets a fresh snapshot. Only threads with an open stream hold detail.
- Subscribe payload: `{"threadId", "requestCompletionMarker": true}` plus
  `afterSequence` when the thread has a cursor.

Thread chunk values:

- `Snapshot`: `ThreadDetail::from_projection`, add the skipped count to
  `decode_errors`, set the thread cursor to `snapshot_sequence`.
- `Event`: skip at or below the cursor; set the cursor; `detail.apply`;
  a decode error counts and is logged like a shell decode error.
- `Synchronized`: clear the stream's sync deadline, set `synced`, run
  `publish_owner`; for a discovery stream, record `Discovery` as above.
  Opening a stream resets `synced` to false.
- After each value, run `publish_owner(thread)` (below);
  - run the request reconciliation (Task 6; a no-op in this task);
  - `detail.prune(&keep)`, where `keep` holds the shell's pending request
    id and the surfaced request id (Task 2).

```rust
            core.request_id_for(&t.agent_id, &CorrelationKey(t.t3_request_id.clone())).as_deref() == Some(request.id.as_str())
        })
```

```rust
    let shell_pending = t.shell.as_ref().and_then(|s| s.pending_runtime_request.as_ref()).map(|p| p.id.clone());
    // Forget hidden ids the shell no longer shows.
    t.hidden.retain(|h| shell_pending.as_deref() == Some(h.as_str()));
    let Some(detail) = t.detail.as_ref() else { return };

    // 1. End the surfaced request once the thread detail says it is not pending.
    if let Some(open) = t.open.clone() {
        if let Some(status) = detail.request_status(&open).filter(|s| *s != "pending") {
            let by = if status == "resolved" { ResolvedBy::Terminal } else { ResolvedBy::Lost };
            t.open = None;
            self.shared.targets.remove(&open);
            if let Some(rid) = self.core.request_id_for(&agent_id, &CorrelationKey(open)) {
                self.core.observe(Observation::RequestEndedIfOpen { request_id: rid.clone(), by });
                if self.core.request(&rid).is_some_and(|r| r.status == RequestStatus::Answering) {
                    self.pending_ends.push((rid, by));
                }
            }
        }
    }

    // 2. Surface the request the shell points at, once the detail has it.
    if let Some(p) = shell_pending.filter(|p| !t.hidden.contains(p)) {
        if let Some(view) = detail.pending_view(&p) {
            let (obs, target) = map::request_obs(&agent_id, thread_id, &view);
            // A superseded request's target goes now (Sol round 1, finding 5).
            self.shared.targets.retain_thread(thread_id, Some(&p));
            self.shared.targets.insert(target);       // before the observation: no claim can miss it
            self.core.observe(Observation::RequestSeen(obs));
            t.open = Some(p);
        }
    }
}
```

The borrow checker will want `t` re-borrowed around the `self.core` and
`self.shared` calls; split the state or copy the needed values first. Keep
the order of operations above.

A `RequestSeen` for a new key while another request is pending makes the
registry supersede the old one. The old target is removed when the
detail ends it, or when the thread is `gone`.

`on_tick` drains `pending_ends`:

```rust

    None => false,
    Some(r) if r.status == RequestStatus::Open => {

        false
    }
    Some(_) => true,
});
```

`drain_mailbox` (on every notification and every tick):

- each answered `(thread_id, t3_request_id)`: add the id to that thread's
  `hidden`, clear `open` if it matches, remove the target, and re-upsert
  the thread (D9);
- a degraded message: set the source `Degraded` with it until the next
  reconnect.

`gone(thread_id)` also removes the thread's targets.

```rust
pub struct T3Adapter {
    cfg: T3Config,
    shared: Arc<Shared>,
    sync: Mutex<Option<SyncHandle>>,
    core: Mutex<Weak<Core>>,
}

impl T3Adapter {
    fn core(&self) -> Option<Arc<Core>> { self.core.lock().expect("core slot").upgrade() }
    /// The mailbox never drops an entry (Sol round 1, finding 7).
    fn degrade(&self, msg: Option<&'static str>) { if let Some(m) = msg { self.shared.mailbox.degraded(m); } }
}

#[async_trait]
impl Adapter for T3Adapter {
    fn name(&self) -> &'static str { "t3" }
    fn answer_paths(&self) -> &[AnswerPath] { &[AnswerPath::T3] }
    fn sources(&self) -> &[Source] { &[Source::T3] }

    async fn deliver(&self, request: &Request, answer: &Answer) -> Result<(), DeliverError> {
        let deadline = Instant::now() + self.cfg.dispatch_budget;
        let Some(core) = self.core() else { return Err(DeliverError::NotDelivered(ErrorCode::SourceUnavailable)) };
        let Some(target) = self.shared.targets.find(&core, request) else {
            return Err(DeliverError::NotDelivered(ErrorCode::SourceUnavailable));
        };
        let command_id = uuid::Uuid::new_v4().to_string();
        let payload = match map::respond_payload(&command_id, &target, request, answer) {
            Ok(p) => p,
            Err(why) => { tracing::warn!(request_id = %request.id, why, "T3 answer not sent"); return Err(DeliverError::NotDelivered(ErrorCode::BadRequest)) }
        };
        let Some(conn) = self.shared.current_conn() else { return Err(DeliverError::NotDelivered(ErrorCode::SourceUnavailable)) };
        let res = conn.call(wire::DISPATCH, &payload, deadline).await;
        match outcome::classify(&res, Some(&target.t3_request_id)) {
            Outcome::Delivered => {
                core.observe(Observation::RequestEndedById { request_id: request.id.clone(), by: ResolvedBy::Inbox });
                self.shared.mailbox.answered(&target.thread_id, &target.t3_request_id);
                Ok(())
            }
            Outcome::NotDelivered { code, end, degrade } => {
                if let Some(by) = end {
                    core.observe(Observation::RequestEndedById { request_id: request.id.clone(), by });
                }
                self.degrade(degrade);
                Err(DeliverError::NotDelivered(code))
            }
            Outcome::Uncertain(why) => Err(DeliverError::Uncertain(why.to_string())), // fixed text (Task 4)
        }
    }

    async fn send(&self, agent: &Agent, text: &str) -> Result<(), DeliverError> {
        let deadline = Instant::now() + self.cfg.dispatch_budget;
        if crate::text::check_prompt_text(text).is_err() { return Err(DeliverError::NotDelivered(ErrorCode::BadRequest)); }
        let thread_id = self.shared.threads.read().expect("threads").get(&agent.id).cloned();
        let Some(thread_id) = thread_id else { return Err(DeliverError::NotDelivered(ErrorCode::AgentGone)) };
        let Some(conn) = self.shared.current_conn() else { return Err(DeliverError::NotDelivered(ErrorCode::SourceUnavailable)) };
        let payload = map::dispatch_payload(&uuid::Uuid::new_v4().to_string(), &uuid::Uuid::new_v4().to_string(), &thread_id, text);
        match outcome::classify(&conn.call(wire::DISPATCH, &payload, deadline).await, None) {
            Outcome::Delivered => Ok(()),
            Outcome::NotDelivered { code, degrade, .. } => { self.degrade(degrade); Err(DeliverError::NotDelivered(code)) }
            Outcome::Uncertain(why) => Err(DeliverError::Uncertain(why.to_string())), // fixed text (Task 4)
        }
    }
}
```

The `RequestEndedById` for `Terminal` or `Lost` is observed **before**
returning `NotDelivered`. The core's later `release` then finds no
request and does nothing, so the request never flips back to `open`.

The 8 s budget covers the queue, the write and the reply, so both methods
finish within the 10 s contract without another timeout.
