# agent-caller v1 roadmap

Spec: `docs/superpowers/specs/2026-10-07-agent-inbox-design.md`

The spec covers five subsystems. Each gets its own plan, and each plan
produces software that works and can be tested on its own.

| Plan | Delivers | Depends on | Spec gates (§11) |
|---|---|---|---|
| **P0 Verification checks** | Recorded fixtures and spec updates for §11 items 2–9 | — | n/a (it produces the gates) |
| **P1 Protocol and daemon core** (`2026-10-07-p1-protocol-core.md`) | `acd-protocol`, `acd-core` (registry, lifecycle, event log, idempotency, acd/1 server), and the `acd` binary with `init`, `run`, `status` and `token rotate`. No real adapters yet. | — | none |
| **P2 herdr adapter** (`2026-10-08-p2-herdr-adapter.md`) | Discovery, sync, state mapping, the read-only fallback, follow-ups through `agent.prompt`, the fingerprinted `keys` delivery engine | P1 | 6 (resolved 2026-10-08) |
| **P3 Hooks: Claude and Codex** | The `acd hook` shim, the HTTP hook endpoint, the Claude and Codex adapters (held hook, key path through P2, binding and migration), and `acd hooks install`/`uninstall` | P1, P2 | 2, 4, 5, 7 |
| **P4 T3 adapter** | WebSocket RPC client, state and request mapping, answers and follow-ups | P1 | 3 |
| **P5 Mac app** | Tauri menu bar app, floating panel, keyboard, undo, notifications, machine settings | P1 (protocol only; can be built against a fake daemon) | none |

**Order:** P1 first. P0 runs in parallel with P1, since it is read-only and
only runs experiments. P2, P4 and P5 can then run in parallel. P3 starts
after P2.

**Live end-to-end** (`just e2e`, spec §13) and the v1 acceptance criteria
(spec §14) run after P3, P4 and P5 have merged.
