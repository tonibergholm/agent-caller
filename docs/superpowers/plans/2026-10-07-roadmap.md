# agent-caller implementation status

Reviewed against `main` on 2026-11-04 (head `28e4664`, the merge of #98; 0.9.0
is the latest release, #65).

## Where things stand

- P0 to P5 (protocol, core, herdr, hooks, T3, Mac app) and P6 to P8 (live
  end-to-end fixes, panel redesign, signing, hook-only visibility) are merged.
- 0.8.0 (#44) is released. The 0.8.1 fixes merged in #50; there is no `v0.8.1`
  tag. 0.9.0 (#65) added the external
  producer source (#56) and voice steps 3 and 4.
- Voice steps 1 to 4 are merged on macOS (#24, #27, #54 to #71). The Linux and
  Windows backend ([research](../../research/2026-10-12-voice-backend-b.md))
  and the optional cloud model are not built.
- The Omarchy inbox (`acd-inbox` and the shell plugin) is merged (#28, #29).
  The 2026-10-12 live check has a limited scope: install, one approval with
  countdown and Esc, a notification, and a shell restart. It excludes pairing
  a remote machine with keyring lock and unlock recovery, and the
  typing-while-another-agent-updates focus cases
  ([record](../../research/2026-10-12-omarchy-plugin-api.md)).
- The iOS shell is merged and foreground only (#31, #40, #41, #45 to #47).

This is pre-release software built from source. Merged implementation does
not imply every acceptance check passed: see the
[live end-to-end record](../../research/2026-10-11-e2e-run.md) and the
[known gaps](2026-10-07-p1-followups.md).

The [design spec](../specs/2026-10-07-agent-inbox-design.md) records the
design and review decisions. Per-phase plans in this directory are
historical implementation briefs. The original dependency roadmap is

## Road to 1.0

Decided 2026-10-13, after 0.8.0 (macOS, Omarchy, iOS from source). 1.0 means
a version the maintainer uses every day on all three clients, with the
items below included. Each step gets its own spec and plan.

1. **0.8.1. Merged (#50), no `v0.8.1` tag.** Small fixes found in the first real use of 0.8.0: a hint when
   Input Monitoring reads Denied but the system list shows the app on (a
   stale grant from another build), a plain offline banner on iOS instead of
   `os error 61`, and clearing the pairing line from the clipboard after
   import. The [known gaps](2026-10-07-p1-followups.md) are sorted
   into "blocks 1.0" and "later" (#51).
2. **Voice commands.** Voice steps 3 and 4: an intent model for free-form
   speech and spoken replies, on macOS. Merged 2026-10-13 (#54 to #71); the 16-item live check on
   the signed app has not been run. A Linux and Windows speech backend
   stays outside 1.0 unless it is added here.
3. **Relay and push.** A relay that carries a wake-up, never request
   content, and push delivery. Android (FCM) is verified first. iOS (APNs)
   needs the paid Apple Developer membership, so its live check moves to
   step 5. This is a trust-model change and needs an independent review of
   the spec before code. Status 2026-11-04: the design spec is merged with its
   independent review recorded ("accept with changes": six blocking points and
   two owner decisions before any code). An implementation-ready spec and the
   `acd-relay` crate are in PR #97 (draft, not merged). No relay code is on
   main.
4. **Windows and Android clients.** Android reuses the relay from step 3.
   Whether Windows also needs a Windows `acd` daemon is decided in its spec.
   Status 2026-11-04: the feasibility note is merged
   ([research](../../research/2026-11-03-windows-android-feasibility.md)); the
   client crates compile for Windows and Android with every non-Unix path
   failing closed (#79), guarded in CI (#93); Windows groundwork is merged
   (#103, [docs/windows.md](../../windows.md)). Type-checked only; nothing was
   linked or run. The Android shell is PR #104, not merged.
5. **Signed releases. Not started.** After the membership renewal (planned
   2026-10-23; the owner confirms): a
   notarized Mac app and `acd`, a TestFlight iOS build, and the iOS push
   live check.
6. **1.0. Not started.** Acceptance checks run on every platform, known gaps cleared or
   documented as accepted, and install docs written for a first-time user.

If dates slip, the cut line is Windows and Android: 1.0 ships without them.
